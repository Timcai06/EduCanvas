# 一、项目背景

> 状态：初稿 v1 · 08-24。【待补】文献/政策原文引用编号统一在终稿轮补齐。

## （一）社会背景

教育数字化转型已成为国家战略。随着人工智能技术加速演进，人工智能通识教育正从高等教育快速下沉到基础教育阶段，成为中小学素质教育的重要组成部分。然而当前普及面临三个结构性矛盾：

1. **优质师资供给不足**：兼具 AI 专业背景与教学能力的教师稀缺，且分布严重不均，非一线城市尤其突出；
2. **个性化教学资源匮乏**：统一课标难以匹配不同学段、不同认知水平学生的差异，分层教学依赖教师个人投入；
3. **学生自主学习引导缺失**：现有工具要么是"题库刷题"缺乏讲解引导，要么是通用聊天助手缺乏教学法的约束，学生提问后得到的答案无法保证适龄、准确、循序渐进。

大语言模型技术的成熟为缓解上述矛盾提供了新可能——但直接把通用对话模型暴露给未成年人，存在内容不可控、评价不可信、合规不达标三大风险。本项目（EduCanvas）的核心立意正是：**用确定性的工程边界把大模型约束成一名可信的 AI 教师**。

## （二）项目目标

对照赛题要求，确立四条可验证的目标：

1. **学段自适应**：系统根据学生选择的年级段（小学低年级/小学高年级/初中/高中）自动匹配知识深度、交互风格与难度梯度；年龄与年级事实来自可信声明而非模型推断；
2. **多模态交互**：提供不少于三种稳定落地的多模态形式——对话问答、结构化文档阅读、游戏化练习（测验/分类游戏）、流程图编排等，并支持教学资料的结构化解析输入；
3. **个性化学习路径闭环**：记录学习历史，练习结果经确定性判分驱动掌握度更新，动态调整后续推荐，形成自适应闭环；
4. **7×24 可信可用**：可运行的完整系统原型，具备 API 对接与页面嵌入的集成部署方案；判分、掌握度等教育事实由确定性代码维护，可审计、可回溯。

## （三）团队调研

### 1、同类产品调研

| 类型 | 代表 | 与本项目差异 |
|---|---|---|
| 通用 AI 助手加教育皮肤 | 各家大模型 App 的"学习助手" | 无确定性判分与掌握度体系，答案适龄性靠 Prompt 约束，幻觉直接进入学习记录 |
| 硬件学习机 | 主流学习机品牌 | 效果好但硬件绑定、价格高，内容更新慢，无生成式互动产物 |
| 题库刷题产品 | 拍搜/题库类 App | 有题无讲解，被动作答为主，缺少多模态生成与主动引导 |

### 2、关键技术调研

立项前完成了两轮源码级技术调研（详见附录调研记录）：

- **输入侧引擎选型**：对 firecrawl/anydoc、pandoc、markitdown、docling、marker、MinerU 六条路线做了能力覆盖表级对比（公式、表格、中文 OCR、服务端可跑性、许可），最终收敛为 MinerU 单引擎——office 后端零模型秒级解析 docx/pptx/xlsx，pipeline/vlm 后端针对性解决扫描件与中文教材的公式/表格保真；
- **参考产品范式研究**：对 NotebookLM 类产品的来源引用、音频共创模式做了能力映射分析，提炼出"来源可信、表示派生、引用可溯"的设计原则。

调研结论均以正式决策记录（ADR）形式沉淀，保证每个重大技术选择可追溯依据与后果。
