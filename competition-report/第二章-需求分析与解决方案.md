## （一）用户角色与需求分析

### 1、应用对象：K12 学生（小学低年级 / 小学高年级 / 初中 / 高中）

学生是系统的 primary 用户，但不同学段的认知水平、识字量、抽象思维能力和自主性差异巨大，不能用同一个交互模式服务全部学段：

| 学段 | 典型特征 | 核心诉求 |
|---|---|---|
| 小学低年级 | 识字量有限、注意力短、具象思维 | 语音交互、绘本故事、游戏化激励、鼓励式反馈 |
| 小学高年级 | 好奇心强、开始接触图形化编程 | 图示化讲解、简单动手实践、闯关式练习 |
| 初中 | 抽象思维发展、有考试压力 | 概念体系梳理、错因诊断、适度深度的展开 |
| 高中 | 自主学习能力强、面向升学与应用 | 编程实践、算法原理、项目式学习 |

【待补·依赖 A1】四学段显式选择入口与知识库分层映射的落地证据（当前产品已有学习偏好五维设置：解释顺序、引导风格、响应深度、模态偏好、反馈风格，见第三章第四节；学段选择器开发中）。

### 2、应用对象：教师

教师需要将 AI 通识课教学内容快速组织为可分发的学习资源，并了解学生学习情况：

- 备课资源准备：上传现有讲义（PDF/PPT/Word），系统结构化解析后转为可对话、可引用的学习资料；
- 学习情况查看：掌握度与练习正确率等教学事实由确定性代码维护，教师看到的是可信投影而非模型生成的说辞。

【待补】教师端功能目前以平台能力形态存在（资源工作台、学习档案投影），竞赛演示中如何呈现教师视角需要设计。

### 3、应用对象：家长 / 监护人

未成年人使用 AI 产品必须处理监护与合规问题。我们的设计（ADR-0022）：

- `general` 体验模式需要一次监护人确认选择；
- 音频留存属于监护人单独同意事项，不把云端音频留存写成默认产品事实；
- `restricted` 模式允许瞬时云端识别但不默认留存。

这一边界是我们区别于普通"套壳聊天产品"的重要合规设计。

## （二）项目解决方案

### 1、整体架构概述

EduCanvas 是"以教育能力为核心的通用个人 Agent 平台"：通用 Agent 是产品主体，教育通过受控能力接入，不为教学场景复制第二个 Agent。整体分层如下：

```text
入口层    Web（Next.js + BFF/SSE）｜ TUI ｜ 渠道适配（Telegram 实验性）｜ 能力节点
控制面    Gateway：身份、路由、Operation、审批、事件恢复、渠道投递
执行层    TurnApplicationService（唯一收敛点）→ AgentLoopEngine → Model Gateway / Tool Kernel
领域层    teaching-core：学习者画像、掌握度、学习投影（确定性代码，非模型自由发挥）
任务层    Durable Worker：文档转换等持久后台任务
事实源    PostgreSQL（身份、Notebook、消息、Operation、Artifact、学习事实、持久任务）
```

关键架构原则：

- **一个自然人一个长期 Agent**，Web、TUI、渠道只是不同入口（ADR-0002）；
- **教育判分、掌握度和课程状态由确定性代码维护**，不能由模型或浏览器直接写成事实——这是"AI 教师"可信度的根基；
- **Provider 响应是不可信输入**，产生领域事件前必须验证；
- PostgreSQL 是唯一业务事实源，历史 migration 与生成物不手改。

### 2、核心系统与功能概述

按五个子系统组织（详见第三章）：

1. **对话智能体引擎**：单一 Agent Loop，多入口收敛到同一 Turn 执行语义；
2. **多模态输入与资源系统**：MinerU 结构化解析管线，原件与派生表示分离；
3. **Canvas 多形态互动产物**：测验、分类游戏、流程图等互动产物的契约化生成与自动批改；
4. **教学状态机与个性化学习路径**：画像—练习—判分—掌握度更新—推荐的闭环；
5. **语音交互与桌面外延**：听写与实时语音双入口，桌宠作为第一方桌面延伸。

### 3、关键技术实现路径

| 技术域 | 选型与路径 | 依据 |
|---|---|---|
| 大模型接入 | Model Gateway 统一 Provider Adapter 边界，文本与视觉提供商分离（ADR-0017），模型能力独立 Provider 可继承（ADR-0021） | 避免单供应商锁定；每次模型调用有账本 |
| 文档理解 | MinerU 单引擎（office 后端秒级解析 docx/pptx/xlsx，pipeline/vlm 处理 PDF），异步三步协议 + 有界轮询 | 中文教材 OCR/公式/表格针对性最强，纯 CPU 可跑 |
| 结构化输出 | Canvas Artifact 以 zod schema 契约化（quiz/classification_game 等），服务端重校验后才落库判分 | 模型输出不可信，契约保证判分确定性 |
| 检索增强 | 混合语义检索与向量身份边界（ADR-0015）；Product Knowledge / Notebook RAG / Memory 三种作用域分离（KM 计划） | 教育内容对准确性要求高，检索必须带身份与失效语义 |
| 语音 | 听写走同源 HTTP 批量 ASR；实时语音经短时 ticket 进入 WebSocket，云端级联（ADR-0018/0025） | 低龄学生打字困难的替代入口 |
| 部署集成 | gateway.v1 版本化多入口协议，支持 API 对接与页面嵌入 | 对应赛题"系统部署与集成"要求 |

### 4、业务闭环与实施逻辑

对应赛题"个性化学习路径"要求的完整闭环：

```text
选择学段/课程 → 判断当前水平（画像+掌握度）
  → 对话讲解与主动引导（Agent + Canvas）
  → 互动产物学习（测验/分类游戏/动画…）
  → 自动评价与即时反馈（确定性判分）
  → 更新掌握度（teaching-core）
  → 推荐下一步内容（学习路径投影）
```

北极星场景：在缺少专业 AI 教师的情况下，学生仍能独立完成一节准确、有趣、可操作、有反馈的 AI 通识微课。示范主题："AI 如何识别猫和狗"——同一知识点分别用绘本、分类游戏、特征可视化和 Python 实验适配不同学段。
