## 创新一：以确定性领域状态机治理教育 Agent（受控教学架构）

### 1、国内外研究现状

【待补·文献综述】现有 K12 教育 Agent 产品（国外 Khanmigo、国内各学习机大模型模式）普遍采用"大模型 + Prompt 人设"路线：对话由模型自由发挥，练习判分依赖模型自评，学习记录直接采信模型输出。该路线的问题是**幻觉会污染学习事实**——错判一道题的掌握度，后续推荐全部失真；且无法通过教育主管部门对"内容科学性、评价可信度"的审查。

学术界方面，LLM-as-Judge 的偏差已被多项研究指出；教育测量领域则长期遵循 IRT/CDM 等心理测量模型强调评价的确定性与可复现性。【待补：具体引文】

### 2、核心技术突破

我们提出并落地了**"通用 Agent 主体 + 教学受控接入"的双层架构**：

```text
模型层（自由度）：AgentLoopEngine 负责对话、规划、工具调用
     │  模型只能"提议"
领域层（约束）：teaching-core 确定性代码独占教育事实
     │  掌握度/课程状态/判分只由领域事件驱动
事实层（持久）：PostgreSQL 单一事实源 + 领域事件唯一写入通道
```

三个关键设计：

1. **判分确定性**：quiz/classification_game 的批改由 `grading.ts` 纯函数完成，不经过模型自评；模型生成的题目本身也要先过 zod 契约校验才能成为可交互产物；
2. **声明来源闭集**：学习者年龄与年级事实只能来自 `self_declared / guardian_declared / school_asserted` 三种明确声明，模型观察被排除在来源闭集之外，从数据模型层面杜绝"模型给学生的年龄改来改去"；
3. **不建第二套 Loop**：教学能力通过 Profile/Skills/Tools 接入同一 Agent 运行时，避免"通用助手一个脑、教学助手另一个脑"的状态分裂——这是大量 Agent 产品在功能扩张后陷入的架构债。

### 3、效果验证

- 该架构由 593 个单元/集成测试文件与 19 个浏览器端到端测试守护，其中教学判分、掌握度更新均有独立故障注入用例；
- 15 份质量证据文档（`docs/06-quality/evidence/`）记录每个交付线的验收边界与未验证项，形成可审计的工程证据链；
- 代码规模约 27.6 万行 TypeScript，全部处于 workspace 边界测试与包策略治理之下。

## 创新二：不可信内容的全链路契约管线（多模态输入→结构化互动输出）

### 1、国内外研究现状

【待补·文献综述】文档智能解析方向，开源引擎（MinerU、Marker、Docling 等）在中文教材场景的公式/表格保真度差异显著（我们的选型调研已完成引擎级对比：office 后端零模型秒级解析 docx/pptx/xlsx，pipeline/vlm 后端处理扫描件）；多模态生成方向，模型直接生成 HTML/JS 给未成年用户存在注入与不当内容风险，主流产品普遍采取"沙箱或模板白名单"策略，但缺少与判分系统的契约化衔接。

### 2、核心技术突破

我们把"不可信"作为管线的第一性假设，构建了输入输出两端的内容契约管线：

**输入侧（文档 → 结构化派生表示）**：

- 上传经 MIME 归一化 + 魔术字节双重校验，原件以 `assetId+versionId` 不可变身份入私有存储；
- MinerU 三步异步协议（提交→有界轮询≤15分钟→下载 zip），结果解包执行路径穿越、解包炸弹、大小上界校验后落为带 manifest 的派生表示（md + content_list + images）；
- 解析失败降级为纯文本并显式标记 `degraded_plain_text`，UI 与上下文快照均可见降级状态，绝不冒充结构化结果。

**输出侧（模型 → 可交互教学产物）**：

- 每种 Canvas Artifact 以 zod schema 定义契约，模型产出先过协议校验、服务端二次校验后才渲染给学生；
- 学生提交同样不被信任：服务端重新运行协议校验后再进入确定性判分；
- Canvas 主页面禁止执行模型生成的任意 HTML/JS，探索型产物只在无 same-origin、默认禁网的隔离 Runtime 中运行。

**横切安全**：Provider 响应视为不可信输入强制验证；任务 URL 只允许回到配置 origin 且禁跟随重定向（SSRF 防护）；供应商错误体、密钥、原始 Prompt 不进日志与浏览器响应（secret containment）。

### 3、效果验证

- MinerU 管线具备完整的故障注入测试族：超时、重试、结果损坏、路径穿越、解包炸弹、权限复验、secret containment 均有 CI 用例（真实 GPU 服务仅做受控 canary，不进普通 PR CI）；
- 复杂表格走 MinerU 原生 HTML 受控渲染路径，colspan 等复杂表保真（ADR-0030），聊天与笔记渲染边界分离。

## 创新三：面向未成年人的分级信任与合规边界

### 1、国内外研究现状

【待补·文献综述】《未成年人网络保护条例》《生成式人工智能服务管理暂行办法》对未成年人模式的知情同意、内容安全提出要求；主流 AI 学习产品普遍采用"一刀切"内容过滤，缺少数据留存粒度的分级同意机制。

### 2、核心技术突破

1. **双体验模式门禁**：`general` 模式需一次监护人确认选择；`restricted` 允许瞬时云端识别但不默认留存音频；
2. **音频留存的监护人单独同意**：云端语音识别的音频是否留存是独立于账号注册的单独同意事项，有专门的 consent 记录表与校验流程（ADR-0022），不做"打包同意"；
3. **权限逐次重授权**：学生上传的原件与派生图片存于私有存储，浏览器一律通过逐次鉴权的资源路由访问；服务端每次按 effective subject × Notebook × ready version 重算权限，provenance 本身不授权；
4. **最小化个人信息**：画像只保存年龄段不存出生日期，不做人脸/生物特征年龄推断。

### 3、效果验证

上述边界均为已接受 ADR 并有对应实现与测试；音频同意流程有独立 schema 与审计字段。相比竞品的"隐私政策一句话"，本方案把合规要求转译成了可测试的工程约束。
