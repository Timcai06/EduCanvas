> 状态：初稿 v1 · 08-24。本章是"智能体设计合理性 25% + 多模态交互质量 25% + 教育适配性 20%"的主证据章节。
> 素材来源：`docs/02-architecture/01-系统架构现状.md`、ADR-0001~0032、teaching-core / canvas-protocol / asset-processing 源码。
> 【待补】= 未完成或依赖决策；写作时保持"只写已落地事实"原则。

## （一）对话智能体引擎

### 1、设计目标

把大模型变成"7×24 在线 AI 教师"的前提是：模型输出可信、调用可控、入口统一。我们的答案是**唯一 Agent Loop + 多入口收敛**。

### 2、分层实现

```text
Web BFF/SSE ─┐
TUI ──────────┤→ Gateway 控制面 → TurnApplicationService（唯一收敛点）
渠道适配 ─────┤                        ↓
能力节点 ─────┘                  AgentLoopEngine（唯一循环）
                                      ↓
                          Model Gateway（Provider 治理）+ Tool Kernel（工具/MCP）
```

- **Turn 收敛**：Web 普通对话、教学 Turn、TUI、Live 语音的 ASR final 提交，全部走同一个 `TurnApplicationService`；Assistant 增量、工具状态、来源和 Artifact 写同一消息账本。不存在"第二套对话执行路径"。
- **模型治理**：Model Gateway 是唯一的 Provider Adapter 边界。文本与视觉提供商分离路由（ADR-0017）；模型能力作为独立 Provider 注册并可被继承（ADR-0021）；每次模型调用落 `model-run-ledger` 账本，可审计、可核算成本。
- **上下文组装**：Context Engine 按作用域组装 Notebook 上下文；Product Knowledge、Notebook RAG、Personal Memory 三种检索来源拥有不同的来源、作用域和失效语义，禁止互相覆盖权威事实（KM 计划边界）。

### 3、年级自适应机制（评"教育适配性"的关键）

自适应的事实基础是**学习者画像的可信声明体系**（teaching-core `learner-profile` + `learner_profiles` 表）：

**① 年级段与年龄带的数据库约束落地**：

- `grade_band` 年级段：`primary_school` / `middle_school` / `high_school` 三档，数据库层 CHECK 约束保证合法值；
- `age_band` 年龄带：`under_13` / `13_to_15` / `16_to_17` / `adult` / `unknown` 五档——只存年龄段，**不收集出生日期、不做生物特征推断**；
- `declaration_source` 声明来源闭集：`self_declared` / `guardian_declared` / `school_asserted`——年龄与年级事实只能来自明确声明，**模型观察不能进入这个来源闭集**。

**② 学习者画像驱动的五维交互偏好**（`apps/web/features/study/study-setup.tsx`）：

| 维度 | 取值 | 作用 |
|---|---|---|
| 解释顺序 | 先看例子 / 先讲概念 | 控制讲解的知识组织方式 |
| 引导风格 | 分步引导 / 先独立尝试 | 控制 Socratic 式追问 vs 直接给答案 |
| 响应深度 | 简洁要点 / 适中展开 / 详细讲解 | 控制知识深度与篇幅 |
| 模态偏好 | 图文练习结合 / 多用图示 / 以文字为主 / 以练习为主 | 控制多模态产物配比 |
| 反馈风格 | 鼓励式 / 鼓励纠正并重 / 直接指出问题 | 匹配学段心理特征 |

偏好进入 Profile 后由 teaching-core 的 learner-profile 统一维护，作为 Turn 组装 Context 的输入之一。

【待补·依赖 A1】赛题要求的小学低年级/小学高年级/初中/高中四学段中，当前年级段为小学/初中/高中三档；需将小学拆分为低/高两档并建立"学段→知识库分层→难度梯度→语言风格"映射表，选择入口开发进行中。（问题台账 Q1）

### 4、主动引导

智能体不只被动应答：基于学习会话状态与掌握度投影，Agent 可主动发起章节内容引导。实现上依托同一 Agent Loop 的工具化规划能力，不引入第二套调度器。【待补】主动引导策略的具体触发规则文档化（读 agent-runtime 提炼）。

## （二）多模态输入与资源系统

### 1、功能定位

教师/学生上传的教学资料（PDF、Word、PPT、Excel）不是被当作一坨纯文本塞给模型，而是经过结构化解析管线转为**带图片、公式、表格保真的派生表示**，供对话引用与结构化阅读。

### 2、处理管线（ADR-0026）

```text
上传 → MIME 归一化 + 魔术字校验 → 原件入私有存储（不可变身份 assetId+versionId）
    → Durable Worker 提交 MinerU（三步协议：POST /tasks → 有界轮询 ≤15min → 下载 zip）
    → 解包校验（路径穿越/解包炸弹/大小上界）→ 派生表示落库（md + content_list + images + manifest）
    → Source 结构化阅读视图 / 对话 context materialization
```

关键工程决策：

- **office 文档秒级解析**：docx/pptx/xlsx 走 office 后端零模型解析，PDF 走 hybrid 引擎（中文 OCR/公式/表格针对性最强）；
- **降级明确**：MinerU 未配置或失败时回退纯文本抽取，结果标记 `degraded_plain_text`，绝不与完整结构化结果混同展示；
- **复杂表格保真**：MinerU 原生 HTML 表格受控渲染（ADR-0030），聊天/笔记侧不直接放行任意 HTML；
- **安全边界**：有界上传、轮询超时上限、结果 zip 大小上界、SSRF 防护（禁跟随重定向、任务 URL 只允许回到配置 origin）、secret containment（供应商错误体不进日志）。CI 使用 fake MinerU 服务验证超时、重试、结果损坏、路径穿越等故障注入场景。

### 3、资源工作台

Source（原件+派生表示）、Artifact（互动产物）、Conversation 共享 Notebook Membership；浏览器访问一律经逐次重授权的资源路由，不暴露私有存储位置。Artifact 以 immutable version 保存 provenance，服务端每次按 effective subject 重算权限。

## （三）Canvas 多形态互动产物（多模态输出主战场）

### 1、契约化的产物体系（ADR-0027）

Canvas Artifact 是模型生成与学生交互的核心载体。每个产物类型以 zod schema 定义契约（`packages/canvas-protocol`），**模型产出先过协议校验、服务端重新校验后才成为可交互事实**：

| 产物类型 | 教学用途 | 状态 |
|---|---|---|
| `quiz` 测验 | 讲解后自动生成趣味小测，自动批改即时反馈 | ✅ 已落地（含判分协议 grading.ts） |
| `classification_game` 分类游戏 | 概念分类训练（如"AI 如何识别猫狗"的特征拖拽归类） | ✅ 已落地 |
| `pipeline_flow` 流程图 | 流程/管道类知识的可视化编排 | ✅ 已落地 |
| `animation` 动画讲解 | 抽象概念可视化 | ⚠️ 动画壳与上下文类型已落地，内容生成管线深度【待核实】 |
| 绘本 | 低龄学段图文故事 | ❌ 见 C1 决策（暂缓） |
| 在线编程环境 | 编程实践 | ⚠️ Docker 执行底座已有（experiment-runtime），学生可见编辑器 UI【见 C1 决策】 |

赛题要求六种形式至少三种，我们已稳定落地三种互动产物 + 结构化文档阅读，其余按集成路线呈现。

### 2、自动批改闭环（对应赛题"游戏化练习…自动批改与反馈"）

以 quiz 为例的完整数据流：

```text
模型生成 quiz artifact（zod 校验通过才可渲染）
→ 学生作答（quiz_answer_submitted 事件）
→ 服务端重新运行协议校验（不信任客户端提交）
→ grading.ts 确定性判分 → CanvasFeedbackDTO（attempted/correct/itemResults/message）
→ 进度更新（progress）→ 掌握度更新（teaching-core）→ 学习路径调整
```

判分是确定性代码而非模型自评——这是"教育判分不能由模型写成事实"原则的直接体现。答对后的庆祝动效（celebrate）提供低龄友好的即时激励。

## （四）教学状态机与个性化学习路径

### 1、可信教学事实的唯一归属（ADR-0007）

学习者的掌握度、课程结构化状态、学习计划全部集中在 `packages/teaching-core`：

- `learner-profile`：画像与偏好；
- `mastery`：知识点掌握度，仅由确定性判分事件驱动更新；
- `learning-projection`：面向侧边栏/报告的可信投影。

领域事件（domain-events）是唯一的事实写入通道；模型只能提议，不能直接改写掌握度。

### 2、个性化路径闭环

```text
学习历史记录（会话+产物提交事件）
→ 答题表现（grading 结果）
→ mastery 更新
→ learning-projection 输出下一步推荐
```

该闭环直接对应赛题答题要求（3）"记录学生学习历史，根据答题表现和兴趣偏好动态调整后续推荐内容"。学习档案（P 计划）提供跨会话的长期视图。

【待补】推荐策略的具体规则文档化（mastery 阈值→推荐触发的映射，读码提炼后补写一页）。

## （五）语音交互与桌面外延

### 1、语音双入口（ADR-0018/0025）

- **听写**：同源 HTTP 批量 ASR，适合长文本输入；
- **实时语音（Live）**：ASR/TTS 经短时单次 ticket 进入 Gateway WebSocket，云端级联架构；ASR final 只提交一次现有 Turn，与文字对话共用消息账本。

语音是小低学段的替代输入入口，也是无障碍价值的体现。已有本地 fake-provider 自动化证据；真实 Provider 验证列入赛前收尾项。

### 2、桌宠桌面外延（ADR-0028）

桌宠是统一 EduCanvas 系统的第一方桌面延伸，非独立应用——降低低龄学生的使用门槛，强化"AI 学习伙伴"的产品心智。
