# ADR-0018：实时语音输入选型与流式识别边界

- 状态：`accepted`
- 日期：2026-07-28
- 负责人：@Timcai06

## 背景

多模态 K12 教学助手需要语音输入：学生用说话代替打字提问，课堂场景还需要持续听写上屏。目标形态是**实时边说边转**——说话过程中就有增量文字出现，而不是录完再等一次转录。

现状：`AudioTranscriptionModelGateway.transcribeAudio()` 已经存在，但它是**一次性接口**——接受已鉴权的完整音频字节，返回完整文本。`asset-context.ts` 里 `transcriptionText` 与 `extractedText` 等价参与文本预算。这条链路服务的是"上传一段录音，异步转成文本进 Prompt"，与实时流式是两种不同的东西。

约束来自部署环境：开发与演示机是 **Apple Silicon（M5 Pro）**，没有 CUDA。这直接排除了一批只提供 CUDA serving 的方案。

## 候选方案

**A. MOSS-Transcribe-Diarize（最初的候选）**

OpenMOSS 的 0.9B 端到端音频理解模型，Apache 2.0，中文 ASR 精度 SOTA（AISHELL-4 CER 14.19，优于豆包 18.18 与 Gemini 3 Pro 21.40），并原生输出说话人分离与时间戳。

**排除。** 官方技术报告在"局限"一节明确写明 _absence of streaming/online inference_——推理是一次性吃下整段音频（最长 90 分钟），流式被列为未来方向而非现有能力。这不是部署难度问题，是模型能力问题：它靠 128k 上下文一次装下全部音频来保持说话人标签一致，该设计与流式互斥。

叠加平台约束：官方 serving 走 vLLM / SGLang，需要 CUDA 12/13；社区的 `moss-transcribe.cpp`（ggml 移植）能在 Metal 上跑，但复刻的是同一张非流式推理图。用 VAD 切段做伪流式可以逼近，但延迟仍在 1–2 秒量级，且要在 Mac 上自行包装 C++ 服务。

**B. 云 ASR 流式接口**

零本地部署，但引入按时长计费的持续外部依赖，且课堂音频持续外传涉及学生语音的合规问题。K12 场景下这是实质性顾虑，不只是成本问题。

**C. sherpa-onnx（k2-fsa）**

ONNX Runtime 上的流式语音框架，提供预训练的流式 zipformer / paraformer 模型。

## 决定

采用 **C：sherpa-onnx**，模型选 `sherpa-onnx-x-asr-*ms-streaming-zipformer-transducer-zh-en-punct-int8-2026-06-05` 系列。

- **短句提问**用 `480ms` 版本：分块延迟低，响应快；
- **课堂字幕**用 `1920ms` 版本：延迟高但准确率更好；
- 两者模型格式与调用方式一致，切换只是换模型目录。

## 原因

**它在 Node 部署栈内运行，不引入 Python、CUDA 或自建推理服务。** 这仍是相对方案 A 的决定性差异。后续产品适配器采用 `sherpa-onnx` 的 Node-hosted WASM SIMD 路径；它与 `sherpa-onnx-node` 一样由 npm 安装，部署栈仍是 Node + PostgreSQL，`make setup && make all` 的入口不变。

**它本来就是为流式设计的。** 提供在线识别器、增量结果、端点检测（自动判断学生说完了）与 silero-VAD，这些正是实时输入需要而 MOSS 缺失的能力。

**模型自带标点。** `-punct-` 变体直接输出带标点的文本，转出来就是可读句子，可以直接进教学 Turn，不需要再接标点恢复模型。

**中英混合覆盖课程语料。** AI 通识课必然混英文术语，选定模型是 zh-en 双语训练。

## 实测（2026-07-28，Apple M5 Pro / arm64 / Node v24.18.0）

用 `say -v Tingting` 合成中文语音，16 kHz 单声道 WAV，按 100 ms 分片喂入模拟实时输入。

**基本可用性成立：**

| 指标     | 结果                                             |
| -------- | ------------------------------------------------ |
| 安装     | `npm install sherpa-onnx` 6 秒完成               |
| 模型体积 | 下载 128 MB，解压 175 MB（int8）                 |
| 模型加载 | 1.67 s（WASM）/ 0.54 s（原生 addon），一次性成本 |
| RTF      | **0.13–0.20**，即 5–7 倍实时速度                 |
| 增量输出 | 3.78 s 音频产生 6 次增量结果，首个片段为「同学」 |
| 标点     | 自动生成，无需后处理                             |

**识别质量：**

| 输入                                    | 输出                                    | 结果                     |
| --------------------------------------- | --------------------------------------- | ------------------------ |
| 同学你好，请问贝叶斯定理是什么意思      | 同学你好， 请问贝叶斯定理是什么意思     | ✅ 完全正确              |
| 什么是机器学习中的过拟合现象            | 什么是机器学习中的过拟合现象            | ✅ 完全正确              |
| 请解释一下 Transformer 模型的注意力机制 | 请解释一下 transformer 模型的注意力机制 | ✅ 正确（英文小写）      |
| 老师，Bagging 和 Boosting 有什么区别    | 老师， backing 和 boosting 有什么区别   | ❌ **Bagging → backing** |

最后一行是本次实测最有价值的发现：**专业术语会被识别成发音相近的常用词**。K12 AI 通识课的核心词汇（Bagging、Boosting、Embedding、Gradient Descent 等）正是这类低频专有名词，不处理会持续出错。sherpa-onnx 支持热词（`hotwordsFile` + `hotwordsScore` + `modelingUnit: 'cjkchar+bpe'` + `bpeVocab`），实现时必须配置课程术语热词表，并随课程内容维护。

**流式模型需要尾部静音才能 flush 最后一段。** 直接 `inputFinished()` 会丢失结尾（实测丢了「是什么意思」）；补 1.5 s 静音后完整。这是实现时的必要细节，不是模型缺陷。

## 路线实证与未验证项

2026-07-29 在 Apple Silicon arm64、相同 16 kHz 官方 WAV（`0.wav` 至 `3.wav`）、100 ms
PCM 分块与 1.5 s 尾静音上，用 `tooling/voice-lab/run-compare.mjs` 得到以下矩阵：

| Node                  | `sherpa-onnx-node` 原生 addon | `sherpa-onnx` WASM SIMD | 原生 RTF      | WASM RTF      |
| --------------------- | ----------------------------- | ----------------------- | ------------- | ------------- |
| 20.20.2（仅兼容实验） | 0/4 非空                      | 4/4 非空                | 0.0300–0.0357 | 0.1166–0.1323 |
| 22.23.1               | 0/4 非空                      | 4/4 非空                | 0.0316–0.0366 | 0.1180–0.1317 |
| 24.18.0               | 0/4 非空                      | 4/4 非空                | 0.0301–0.0352 | 0.1160–0.1295 |

因此，**否决原生 addon 作为本项目后续产品路线**：它虽更快，却在仓库支持的 Node 22/24
以及兼容性 Node 20 中都返回空文本。选择 **WASM SIMD** 作为后续产品适配器路线；Node
22/24 的 4/4 非空与约 0.12 RTF 证明了此 fixture 范围内的实时性，但不等于产品能力已启用。

以下事项仍未验证，避免把路线选择误读为可发布：

- **热词效果未验证**：runner 已以 `modelingUnit: 'cjkchar+bpe'`、`bpeVocab`、`modified_beam_search` 和 UTF-8 词表构造 WASM 路径；坏热词路径会显式失败。但官方 WAV 不含 `Bagging/Boosting`，本机合成尝试得到零样本 WAV，尚无有效的目标词 before/after 证据。不能用字符串替换伪造通过。
- **未测真实麦克风输入**：全部测试基于合成语音的 WAV 文件。真实场景的环境噪声、口音、远场拾音都会影响准确率。
- **未测长时间连续流**：课堂字幕场景需要数十分钟持续识别，内存增长与长连接稳定性未验证。
- **未测并发**：多个学生同时语音输入时的资源占用未知。

## 后果

**需要新增流式 Port。** 现有 `AudioTranscriptionModelGateway.transcribeAudio()` 是一次性语义，无法表达"持续输入音频分片、持续输出增量结果"。新 Port 与它并列而非替代：前者服务已上传录音的异步转录，后者服务实时输入。两者产出的文本进入 Prompt 的方式一致。

**需要新增双向传输通道。** 浏览器麦克风 → 服务端的音频分片需要 WebSocket 或等价机制；现有 SSE 是单向的。这是本次改动中工程量最大的部分，且触及 Gateway 的连接管理与身份边界。

**模型文件不进仓库。** `CLAUDE.md` 明令禁止提交模型权重。采用与 ffmpeg 相同的处理方式：不打包、按需获取、路径由环境变量声明，未配置时语音输入能力不注册——能力不进入工具策略，模型不会声称自己能听。需提供带校验和的下载脚本。

**实时语音是不可信输入。** 转录文本与 Asset 正文同级，属于不可信内容，不能覆盖 system policy，不能直接触发工具调用。这一点沿用 `asset-context.ts` 既有约束，不因输入方式改变而放松。

## 原始音频的留存边界

项目负责人已决定：**原始音频短期留存后自动删除**，而非转完即焚。保留的目的是排查识别错误，以及在模型升级后用更好的模型重跑历史音频。

这个选择把语音输入从"纯计算"变成了"持有未成年人敏感个人信息"，因此以下要求不是可选优化，而是启用该能力的前提：

**语音是生物特征信息，学生是未成年人。** 依《个人信息保护法》第二十八条、第三十一条，不满十四周岁未成年人的个人信息属于敏感个人信息，处理须取得监护人的**单独同意**，并制定专门的处理规则。因此：

- 语音输入能力默认关闭，只有在监护人同意记录存在时才对该学生注册；
- 同意是针对"音频留存"这一具体目的的单独同意，不能与总体服务条款打包；
- 撤回同意必须立即生效，并触发该学生已存音频的删除。

**留存期限固定且短。** 默认 **7 天**，由配置声明上界，不允许无限期保留。到期删除是硬删除，不是软删除标记——软删除对敏感个人信息不构成"已删除"。

**删除必须可靠。** 复用既有 Asset 的 Outbox 删除机制（ADR-0010、ADR-0016 已建立的模式）：删除意图先落库，再由 Worker 驱动对象存储的实际清理，崩溃恢复后继续。到期未删成功的音频必须可被发现，不能静默残留。

**访问面最小。** 音频只能由该学生本人与其监护人访问；教师、管理员默认无权访问。`storageKey` 不离开服务端，与既有 Asset 约束一致。审计需记录每一次音频读取。

**转录文本与音频分离。** 文本的生命周期跟随对话历史，不随音频的 7 天期限删除——两者的处理目的与法律基础不同，不能混为一谈。

**实时语音是不可信输入。** 转录文本与 Asset 正文同级，属于不可信内容，不能覆盖 system policy，不能直接触发工具调用。这一点沿用 `asset-context.ts` 既有约束，不因输入方式改变而放松。

**课堂字幕不做说话人区分。** 项目负责人已确认不需要该能力，因此流式链路不引入说话人分离，MOSS-Transcribe-Diarize 也不作为补充方案保留——说话人分离是它在本项目中唯一的不可替代之处，该需求取消后它没有引入价值。

## 开放问题

- 监护人同意的采集与撤回流程尚未设计，它跨越身份、Web 界面与数据生命周期，可能需要独立 ADR。
- 7 天是否为合适的留存期限，需在真实使用中验证——若排查识别错误从未用到历史音频，应缩短或退回"转完即焚"。
- 热词表的维护归属：随课程内容更新，还是作为独立的术语库。

## 验证方式

- 实现阶段采用已选定的 WASM SIMD 路径；必须先完成热词效果验证，否则不进入接线。
- 流式 Port 的纯逻辑（分片累积、端点判定、增量结果合并）需附单元测试，遵循 `CLAUDE.md` 对核心纯逻辑的要求。
- 音频留存的到期删除需集成测试覆盖：到期删除、撤回同意即时删除、崩溃恢复后继续删除、删除失败可被发现。留存期是合规承诺，不是尽力而为的清理。
- 需要一次使用真实麦克风、真实课堂噪声环境的 live smoke，Fixture 不能替代——本次视觉 Provider 接入的教训（ADR-0017）已经证明这一点。
