# ADR-0029：统一日志协议与本地运行时

- 状态：`draft`（随本 PR 实现，待 Code Owner 评审后 accepted）
- 日期：2026-08-14
- 决策范围：本地开发体验、日志基础设施、进程生命周期；不改变业务事实与 telemetry 语义
- 上位决策：[ADR-0005](./0005-模块化单体产物与持久任务.md)

## 背景

本地启动链（Makefile / PowerShell / CMD / Node orchestrator）各自维护一套
readiness、migration 与错误处理逻辑，输出混在同一个终端且无分层；日志无限
append 到单一文件，跨会话混杂；Worker 无独立 readiness；Gateway 已有安全
结构化日志但没有统一信封；PowerShell 与 Makefile 的启动能力分叉。

## 决策

### 1. 单一启动事实源

完整启动流程（Environment → Docker → Database → Migration → Gateway →
Web → Worker → Runtime ready）收敛到 `tooling/local/local-orchestrator.mjs` 及配套
模块。Makefile、PowerShell、CMD 只做薄入口，不再复制启动业务逻辑。三平台的
启动状态语义一致。

### 2. 统一日志协议 `educanvas.log.v1`

- 信封：`schema / ts(ISO 8601 UTC) / level / service / event / message / runId /
pid / stream`，可选关联字段 `requestId / operationId / traceId / jobId /
workerId / conversationId / durationMs / outcome / error`；
- `event` 是稳定机器接口（低基数），`message` 是人类可读内容，两者分离；
  禁止模糊事件名（`started`、`done`、`request`、`error`）；
- 级别语义固定：DEBUG（高频排查）/ INFO（正常状态变化）/ WARN（偏离但可继续）/
  ERROR（单次失败）/ FATAL（进程无法继续）；
- 协议常量单一事实源：`packages/logging/protocol.json`，TS 与 tooling（.mjs）
  共同 import，不在两处复制 schema/级别/事件名。

### 3. 独立 `@educanvas/logging` 包

与 `@educanvas/telemetry` 职责分离：logging 负责事件日志、JSONL sink、pretty
rendering、安全错误序列化与脱敏；telemetry 负责 OpenTelemetry traces/metrics/
exporter/sampling，不承担终端渲染与文件轮转。业务事实仍只以数据库 operation
store 为准，logging 不替代事实源。logging 公共接口不暴露 OTel SDK 类型，
traceId 以脱敏字符串进入日志。

tooling（纯 Node .mjs 运行时）无法直接 import TS 包源码，遵循仓库既有先例
（`tooling/local/workspace-env.mjs` 与 `apps/worker/src/workspace-env.ts` 双实现），
在 `tooling/local/local-pretty.mjs` 提供同一样式契约的运行时渲染实现；协议常量
仍通过 `protocol.json` 共享，不复制 schema/级别/事件名。

### 4. 独立运行会话

每次启动创建 `tmp/logs/local/local-<ts>-<rand>/`，含 `run.json`
（schema/runId/state/orchestratorPid/URLs/services pid）与
`combined.jsonl` + 按服务 `{service}.jsonl`；`latest.json` 定位当前运行。
日志文件中绝不出现 ANSI；JSONL 每行可独立 `JSON.parse`。保留策略：默认保留
最近 10 次运行，永不删除当前运行，清理失败只记 warning 不阻断启动。

### 5. 服务 readiness

- Gateway：`/healthz` 探测（body 校验 service/protocol）+ `service.ready` 事件；
- Web：HTTP 探测；
- Worker：只认结构化 `worker.ready` 事件（含 taskCount/concurrency/
  pollIntervalMs），不匹配文本；ready 前退出或 fatal 即整体启动失败；
- 三个服务全部就绪才宣布 `runtime.ready`；`make all` 默认只输出阶段摘要
  （≤20 行），详细日志入 run directory；`make all-verbose` 实时 pretty 渲染。

### 6. 进程输出管道

每服务独立 spawn（不再依赖 Turbo 合并日志），stdout/stderr → line splitter →
协议解析/legacy 包装（`process.output`）→ redaction → JSONL sinks →
pretty renderer → readiness 检测。服务来源由 spawn 绑定确定，不依赖框架
彩色文本；协议行内 service 字段以进程绑定为准（防伪造）。超长行截断、
pending 缓冲有上限、非 JSON 行不崩溃。

### 7. 子进程终止

POSIX 下每个服务 `detached` 成独立进程组，orchestrator 统一收信号后按
`kill(-pgid)` 终止整棵树（pnpm → tsx/next 不因信号不转发而残留孤儿）；
Windows 用 `taskkill /T`。Ctrl-C/SIGTERM/SIGHUP 均走同一优雅停止路径，
超时后 SIGKILL。stop 命令只清理 run.json 记录的 PID/端口验证过的本项目进程。

### 8. 安全日志纪律

- 只采集低基数白名单字段；Graphile Logger 白名单为 workerId/taskIdentifier/
  jobId/attempt/maxAttempts/durationMs，payload 与正文绝不落盘；
- 递归脱敏敏感键（password/token/api key/authorization/cookie/session/
  credential/private key/DATABASE_URL/prompt 等）；URL 内嵌凭据与
  `Bearer <token>` 形态整段替换；
- 错误载荷只含 name/code/message/retryable/causeCode；堆栈、连接串、正文
  一律不落日志；error.message 内嵌凭据在序列化前统一清洗；
- 同一错误只在责任边界记录一次：底层依赖返回带 code 的安全错误、重试层
  warn、应用边界 error、进程边界 fatal。

### 9. Migration fingerprint

migration 采用 fingerprint skip：`sha256(迁移源文件 + database
system_identifier)`。system_identifier 是数据库集群身份，数据卷清空后变化，
避免数据库重建后错误跳过；数据卷保留时容器重建不误重跑。身份读取失败时
降级为每次幂等执行（正确性优先于跳过优化）。状态文件沿用旧
`.educanvas-migrate-state.json`，与旧 Windows 逻辑兼容。

### 10. Turbo 定位

Turbo 仍是任务编排工具：`pnpm dev:core`（`make dev-ui`）保留用于 Turbo TUI
观察原始 task 日志；默认 `make all` 由 orchestrator 控制展示。不修改 Turbo
全局输出行为，避免影响 CI 与非交互环境。

## 故障点与预期

| 故障点                   | 处理                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| Worker ready 前退出      | 整体启动失败，输出失败摘要（首条 fatal/error + 退出码 + 日志路径）    |
| Web readiness 超时       | 整体启动失败，清理已启动服务                                          |
| 端口被无关进程占用       | 检测半个 core → 只清理命令行含仓库特征的本项目进程 → 仍占用则明确报错 |
| runtime ready 后服务退出 | 更新 run.json 服务状态；`make status` 如实显示 down                   |
| 日志清理失败             | 只记 warning，不阻断启动                                              |

## 回退

- `make all` 回退到 `make dev-ui`（Turbo TUI）可观察原始日志；
- 删除 fingerprint 状态文件即回到每次幂等迁移；
- 新增包与 tooling 模块均为增量，不修改既有业务代码路径。

## 验证要求

- 纯单测覆盖：协议序列化、脱敏、安全错误、JSONL 可解析、pretty 渲染
  （TTY/NO_COLOR/中文宽度）、run session、进程管道、失败摘要、log viewer
  过滤、Graphile 白名单、Gateway 信封级别映射；
- orchestrator 黑盒（fake 工具链）覆盖：全就绪、各服务就绪前退出、
  readiness 超时、Ctrl-C 清理、半个 core 清理、不误杀仓库外进程；
- 真实环境验证：`make all` 输出 ≤20 行、第二次启动 migration skipped、
  Ctrl-C 后端口全部释放、`make logs SERVICE=worker` 可用。
