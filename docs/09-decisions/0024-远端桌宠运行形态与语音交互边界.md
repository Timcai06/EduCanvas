# ADR-0024：远端桌宠运行形态与语音交互边界

- 状态：`accepted`
- 日期：2026-08-10
- 负责人：项目负责人
- 替代：PR #330 原提案“Web Three.js 桌宠渲染选型”

## 背景

EduCanvas 面向 K12，竞赛版本需要让低龄用户尤其是小学生，不依赖复杂页面和键盘输入，也能方便地调用同一个 Personal Agent。现有 `apps/desktop` 已提供 Electron 托盘小窗，但它仍是连接 localhost `/api/v1/assistant/turn` 的普通文本助手：标准有框窗口、无远端登录、无麦克风和语音播放，也不是桌宠。

原 PR #330 把桌宠定义为 Web 页面中的 Three.js 右下角助手，只升级现有 Web 面板表现层。该方案不能满足已经确认的新产品目标：桌宠必须独立于浏览器常驻桌面，macOS 优先且兼容 Windows，以点击语音作为主要入口；复杂结果再交给 Web/Canvas 展示。因此需要用本 ADR 替代原提案，并冻结桌宠作为第一方远程客户端的长期边界。

本决策服务竞赛原型，不在当前阶段建设完整儿童账户、监护人后台或商业上线合规体系；但仍保留明确录音状态、系统麦克风授权和 Provider Secret 不下发客户端等最低边界。

## 候选方案

### A. Web Three.js 右下角助手

- 优点：复用 Web 的 Three.js、GSAP 和现有 Assistant Panel，请求链路短。
- 缺点：浏览器关闭后不存在，不是操作系统桌宠；WebGL 对可爱像素角色属于过度实现；仍依赖 Web 页面操作，不能成为低龄用户的独立语音入口。

### B. Electron + React + 2D 像素 Sprite（选择）

- 优点：复用现有 Electron 容器与 React 技术栈；一套 Renderer 覆盖 macOS 和 Windows；透明 PNG sprite sheet 与像素风天然匹配，不需要 WebGL 或专有运行时；可独立处理窗口、麦克风、系统浏览器登录和 Web handoff。
- 缺点：需要补齐远端认证、语音 Client、跨平台窗口和双平台打包；macOS 权限与 deep link 必须在打包应用中验证。

### C. Tauri + Web Renderer

- 优点：安装包和常驻内存可能更小。
- 缺点：需要引入 Rust 和不同系统 WebView 行为，放弃现有 Electron 基线；竞赛阶段迁移收益不足。

### D. SwiftUI + WinUI 双原生客户端

- 优点：操作系统集成最深。
- 缺点：产生两套客户端与两套测试/打包链，和竞赛交付节奏不符。

### E. Live2D、Rive、Spine 或 3D

- 优点：可提供更复杂的骨骼、形变或三维表现。
- 缺点：角色制作和运行时成本更高，部分方案还有许可或供应链负担；当前选择的可爱 2D 像素风只需要有限状态 sprite 动画。

## 决定

采用 **B：Electron + React + 2D 像素 Sprite**。桌宠是 `gateway.v1` 的第一方远程 Client，也是同一个 Personal Agent 的本地视觉和语音投影；它不创建第二 Agent、不复制 Canvas，也不成为新的业务事实权威。

### 1. 产品与平台

- macOS 是首要开发、演示和验收平台；Windows 必须支持相同主流程。
- 桌宠独立于浏览器常驻，继续复用 `apps/desktop` 的 Electron main / preload / renderer 信任分层。
- 竞赛版核心价值是“点击后即可通过语音使用 EduCanvas”，不是用复杂虚拟人替代教育能力。

### 2. 窗口与桌面行为

- 使用透明、无框、适度置顶的 Electron 窗口；不默认覆盖系统全屏空间。
- 默认停留在屏幕安全区域或上次拖拽位置，用户可以拖动。
- 只在 `idle` 且没有气泡时偶尔做小范围移动；`listening`、`transcribing`、`thinking`、`speaking` 和错误状态保持位置稳定。
- 显示器、分辨率或缩放变化后，将窗口钳制回当前 work area，不能永久丢到屏幕外。
- 角色与气泡区域接收点击，其他透明区域可以受控穿透；不得因此暴露任意窗口或系统控制能力。

Electron 当前提供透明窗口、always-on-top、位置和鼠标穿透能力；具体平台差异由 main process 封装，不能泄漏到 Agent/Voice 领域契约。

### 3. 角色渲染

- 首版角色为可爱 2D 像素风，使用透明 PNG sprite sheet，不引入 Three.js、Live2D、Rive、Spine 或新的 3D/骨骼 Runtime。
- 必需状态为 `idle`、`listen`、`think`、`speak`、`success`、`error`；`walk`、`sleep`、`wave` 是可选表现。
- 角色资产通过 manifest 声明帧尺寸、FPS、循环、锚点和状态映射；业务状态机不依赖某个具体角色包。
- 像素资源只按整数倍率和 nearest-neighbor 方式缩放，保持 macOS Retina 与 Windows 缩放下的锐利边缘。
- 系统启用 reduced motion 时停止偶尔移动，只保留表达交互状态所需的最小动画。
- 素材必须有清晰来源与许可证，允许参赛展示、录屏和构建制品分发；角色包不得携带脚本或动态代码。

### 4. 点击语音交互

主流程固定为：

```text
点击桌宠
  -> listening（明确显示正在录音）
  -> VAD 自动判断说完
  -> transcribing（云端整段 ASR）
  -> thinking（进入唯一 Agent Runtime）
  -> speaking（云端 TTS + 气泡字幕）
  -> idle
```

- 首版不做持续监听或唤醒词；`listening` 时再次点击可取消录音。
- 回答同时提供语音和简短气泡字幕；TTS 失败时保留字幕作为最低降级路径。
- 气泡用于短文本和恢复操作，不扩展成第二个完整聊天客户端。
- 麦克风拒绝、网络失败、ASR 空文本、Agent 失败和 TTS 失败必须投影为稳定状态和可重试入口，不能无反馈停住。
- 首版允许整段非流式 ASR 与非流式 MP3 TTS，不宣称全双工、流式语音或自然打断能力。

### 5. 云端 ASR/TTS

- ASR 与 TTS 均采用云端能力，实时主链不依赖远程 2080 Ti；该机器留给 RAG、embedding、reranker、离线评测和可重建派生任务。
- 复用 `packages/agent-core` 的 provider-neutral Voice Port 与 `packages/model-gateway` 的 OpenAI-compatible speech/transcription Adapter。
- ASR 与 TTS 可以分别配置 Provider、Base URL、模型、Voice 和 Secret；本 ADR 不绑定具体厂商。
- 具体 Provider 必须通过中文低龄语音 live smoke、延迟、可取消性、费用和稳定性验证后才能成为部署默认值。
- Electron 不持有 Provider Key、模型 ID或原始响应；Provider Secret、原始 Body 和错误归一化止于 Model Gateway。

### 6. Gateway、身份与唯一 Runtime

- 桌宠通过 `gateway.v1` 的第一方 Client 会话提交 Turn、消费 Operation Event、取消和恢复；不得把现有 localhost `local:owner` 回退当作远端身份。
- 首次启动使用系统浏览器完成 EduCanvas 登录/授权，再通过打包应用注册的 deep link 回到桌宠。
- 回跳只携带一次性短期 code/state；长期 Token 不进入 URL，客户端会话必须可撤销并由操作系统保护的存储能力保存。
- macOS 处理 `open-url`，Windows 处理单实例命令行回调；两者共享同一授权契约。
- `packages/agent-runtime` 继续拥有唯一 Agent loop；桌宠动画只投影 canonical Operation/Turn 状态，不新增宠物消息、工具或动画账本。

### 7. Web/Canvas 交接

- 简单回答留在桌宠的语音与气泡中。
- 课程、图片、Artifact 或 Canvas 等复杂结果完成后，桌宠提示用户并自动打开对应 EduCanvas Web 页面。
- Web handoff 使用受控 HTTPS/deep link 和已有 CanvasResource/Artifact 身份，不把 Conversation ID 或任意 URL 当作授权。
- 打开页面失败时提供“再次打开”，不得重新执行已经完成的 Agent Operation。

### 8. 持久化

- 首版只在本机保存窗口位置、静音、动画强度等 UI 偏好，不新增 Schema 或 Migration。
- 瞬时动画、移动和情绪状态不得写入长期 Ledger。
- 若未来需要跨设备同步角色偏好，必须先按 Feature Data Contract 声明 Authority、Retention、Deletion 和隐私边界，再决定是否进入通用 Preference。

## 非目标

- 不建设第二 Agent Runtime、第二 RAG、第二 Canvas 或平行消息账本。
- 不实现持续监听、唤醒词、后台静默录音、声纹识别或实时全双工语音。
- 不默认获取屏幕、Shell、任意文件系统或设备控制权限。
- 不在桌宠中渲染完整课程、Canvas、Artifact 或聊天历史。
- 不建设完整儿童年龄验证、监护人后台或生产商业合规体系。
- 不把 2080 Ti 变成实时语音单点依赖。
- 不在本 ADR 选择具体像素角色素材或云端语音厂商。

## 原因

- 直接服务竞赛目标：低龄用户点击后即可语音使用同一个教育 Agent。
- 复用现有 Electron 和 Model Gateway，而不是扩展旧 Web 面板或引入第二套 Runtime。
- 像素 sprite 对目标风格最直接，依赖、许可、包体和跨平台风险均低于 WebGL、骨骼或 3D 路线。
- 云端整段 ASR/TTS 与点击 + VAD 流程匹配，可用较小实现成本获得稳定演示，同时保留 Provider 可替换性。
- Web/Canvas handoff 让桌宠保持轻量，并继续使用平台已有的复杂内容展示与信任边界。

## 后果

- **收益**：形成独立于浏览器的低门槛语音入口；macOS/Windows 共用核心客户端；角色和 Provider 都可以替换。
- **代价**：需要新增桌宠远端认证、语音 Client、窗口平台适配和 macOS/Windows 打包证据。
- **风险**：现场网络和低龄中文语音质量可能影响演示；必须提前完成真实 Provider smoke，并保留字幕和明确重试降级。
- **兼容影响**：现有桌面助手可作为容器基线，但 localhost proxy、标准 380×600 窗口和文本表单不是远端桌宠的长期架构。
- **文档影响**：旧 desktop assistant spec 只描述 local-shell baseline；后续 PET 计划不得把它解释为远端产品契约。

## 验证方式

- macOS 打包应用完成：首次登录回跳、麦克风授权、一次中文语音问答、语音 + 字幕回答和 Web/Canvas handoff。
- Windows 构建完成相同主流程；平台差异不改变 Gateway/Voice/Agent 契约。
- 点击开始、VAD 自动结束、再次点击取消；失败均有可恢复状态。
- TTS 失败时字幕仍然可用；复杂结果只执行一次并可重复打开。
- 桌宠可拖拽、不会在交互期间乱跑，多屏变化后仍处于可见区域。
- Provider Secret、原始响应和内部错误不进入 Renderer、preload 事件或浏览器响应。
- 代码审计证明没有第二 Agent loop、宠物 Ledger、Schema/Migration 或 `apps/desktop -> apps/web` 反向依赖。
- macOS deep link 必须使用打包应用验证；Electron 官方说明命令行开发态不能替代该证据。
