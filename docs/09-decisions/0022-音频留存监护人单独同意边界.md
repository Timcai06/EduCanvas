# ADR-0022：未成年人音频留存的监护人单独同意边界

- 状态：`accepted`（项目负责人 @Timcai06 于 2026-08-05 明确接受）
- 日期：2026-08-05
- 负责人：@Timcai06
- 来源：[ADR-0018 实时语音输入选型与流式识别边界](0018-实时语音输入选型与流式识别边界.md)（第 128-147 行"原始音频的留存边界"）

## 背景

实时语音输入将产生学生的原始音频。ADR-0018 已 accepted 并决定：原始音频短期留存后自动删除（默认 7 天、配置声明上界），留存目的是排查识别错误与模型升级后重跑历史音频；学生语音属敏感个人信息，处理须取得监护人**单独同意**，默认关闭、撤回立即生效并触发删除（0018:128-147）。ADR-0018 同时声明"监护人同意的采集与撤回流程尚未设计，可能需要独立 ADR"（0018:154）。

本 ADR 只定义同意的**边界与契约**：谁可以同意、同意什么、如何生效与撤回、删除如何可靠执行、如何访问与审计，以及现有 `delegated_grants` 与 `object_deletion_outbox` 哪些可以复用、哪些绝对不能冒充同意。**不设计表结构、Repository、API 或 UI**——这些留给 V11/V14/V15/V16，并全部依赖本 ADR accepted。

## 候选方案

**A. 直接复用 `delegated_grants` 表达音频留存同意**

给 `kind='education.guardian'` 的委托新增一个 audio 相关 scope，把"存在该委托"当作同意事实。

**B. 新增用途明确的 voice-processing / audio-retention / cloud-transcription 单独同意事实（推荐）**

独立于 `delegated_grants` 的同意记录，绑定主体、授权人、目的、版本、时间、证明与状态。`delegated_grants` 最多只能作为既有关系声明的形状参考；当前实现没有可验证监护关系，不得把 grant 的存在当作证明。

**C. 只做即时处理，服务端不留存原始音频**

音频只进入受控 WASM 识别进程的内存，分段完成后立即释放，不留存任何服务端对象，也不发送给云端 Provider。

## 决定

采用 **B：新增用途明确的三类单独同意事实**。以下各节是同意契约本身，V11 起按此落库。

### 1. 数据主体与授权关系

- **数据主体**：发出语音的学生本人。产品按更严格的内部政策把所有原始语音视为敏感个人信息；这不是宣称任何普通录音在法律上都必然构成生物识别信息。不满十四周岁未成年人的个人信息依法属于敏感个人信息。
- **谁能给予同意**：
  - 不满十四周岁学生：只能由监护人以本人身份同意（《个人信息保护法》第三十一条）；
  - 成年用户（`age_band='adult'`）：自行同意；
  - 其他未成年人：当前 `age_band='13_to_15'` 跨越十四周岁法定边界，系统无法据此可靠判断本人是否可授权。V11 不新增完整出生日期；在专门的年龄/授权能力证明事实落地前，所有非 `adult` 年龄段都要求监护人同意（fail closed）。
- **监护关系证明**：当前代码**不存在**可证明监护关系的表或字段（`learner_profiles.declarationSource='guardian_declared'` 只是画像自报，schema/study.ts:55）。本 ADR 要求：同意记录必须同时绑定 `grantor`（监护人）与 `subject`（学生），且 grantor 的监护人身份必须有独立、可审计的声明或核验记录。开发/演示环境可使用明确标注为 `self_attested` 的关系声明；生产环境在接入可信核验方式前默认拒绝，不收集或保存证件图片。**无法验证 → 拒绝**。
- **未登录用户**：无权同意，任何音频留存对其 fail closed。
- **教师、管理员**：无权代替监护人同意。`platform.operator` 委托只覆盖平台运维范围，与个人同意无关。
- **跨 Notebook**：同意按**学生主体**维度生效，不绑定单一 Notebook（学生换 Notebook 学习不重复征求同意）；但音频对象的读取仍受 Notebook 归属与既有访问边界约束（`notebook-access.ts:37-90`），两者不互相替代。
- **隔离维度**：同意按 `subject`（主体）+ `purpose` 隔离；purpose 是下述三个封闭值之一。语音入口至少需要有效的 `voice-processing` 同意；留存和云端复核再分别检查自己的同意。缺记录、过期、撤回、无法验证一律 fail closed。

### 2. 单独同意的内容

- **三个独立目的**：
  - `voice-processing`：为实时转录在受控服务端内存中短暂处理 PCM，输入结束后立即释放，不写对象存储；这是任何语音入口的最低授权；
  - `audio-retention`：为识别错误诊断及模型升级后复核，最多保留原始音频七天；
  - `cloud-transcription`：把本次音频发送给配置的第三方转录 Provider 生成高质量终稿。
    三者不得合并为“改善服务”等宽泛目的，也不能互相隐含。用户可以只同意实时处理而拒绝留存或云端复核。
- **数据范围**：原始音频对象。**不包括**转录文本——文本的生命周期跟随对话/资产历史，不随音频留存期删除（0018:146；asset-transcription-repository.ts:150-152 转录文本写回 asset 后独立存在）。
- **留存期限**：默认最多 7 天，配置只能缩短、不能超过上界（沿用 0018:140）。期限从音频产生时起算。同意记录默认 12 个月到期，文案、目的、处理方式或数据范围变化时即使未到期也必须重新征求。
- **云端转录 Provider 外传**：**允许的前提是显式单独授权**。实时处理、本地留存与云端复核外传是三条不同路径（0018:41-53）；外传涉及第三方处理，不能由实时处理或留存同意隐含。三个声明各自可单独撤回；云端外传声明缺失或失效时，产品保留本地草稿并显示"未复核"（0018:52-53），不能静默外传。
- **证明记录**：同意记录必须含：同意版本（`consentVersion`）、展示文案版本（`noticeVersion`，与用户实际看到的文案一一对应）、授予时间、主体、授权人、状态与证明引用。文案/版本升级时须重新征求。
- **不可替代**：一般服务条款、登录状态、Notebook 成员身份、`declarationSource` 自报、`delegated_grants` 委托均**不构成**单独同意。
- **默认关闭**：缺少 `voice-processing` 同意时不采集音频、不注册语音入口。只有实时处理同意而没有另外两项同意时，可走本地 WASM 服务端内存路径，PCM 在分段完成后即时丢弃，不写对象存储、也不向云端发送。这一降级路径与当前 Node/WASM 架构一致，不虚构浏览器内识别能力。

### 3. 生效、撤回与删除

- **生效**：同意记录落库且状态为 active 时才生效；每条路径只检查与自己 purpose 匹配的 active 同意，不能用另一目的代替。
- **撤回**：任何同意撤回都立即阻止对应的新处理。撤回 `audio-retention` 时，在单个事务内完成两件事——(1) 同意状态立即置为 revoked；(2) 对该主体**已有**留存音频写入删除意图。两者缺一即撤回不成立。撤回 `cloud-transcription` 不删除本地留存；撤回 `voice-processing` 同时关闭新采集，并取消尚未进入终态的当前会话。
- **删除意图**：复用现有 `objectDeletionOutbox`（schema.ts:1226-1282），**不另建第二套删除调度器**。V11 把留存音频绑定到受控 `asset_version` 对象，V14 以已有 `objectKind='asset'` 与对应 sourceType 写入 outbox；若实现选择其他 objectKind，必须先显式扩展数据库约束与集成测试，不能假设现有 outbox 已支持 `audio`。
- **删除可靠性**：复用既有 claim/complete/fail 语义（object-deletion-outbox-repository.ts:50-144；delete-object-outbox.ts:91-152）：对象已不存在视为幂等成功；失败按指数退避重试、attempt≥10 进入终态 failed 可被发现；崩溃后租约过期可被重新领取。删除失败**不得**恢复用户可见音频——物理删除失败只影响资源回收，不影响"已删除"的业务事实。
- **转录文本不随 7 天音频期限删除**：文本、同意记录、音频对象是三个独立生命周期，互不级联（唯一例外：撤回时**已有音频**对象删除，但文本保留）。
- **到期删除**：7 天到期与撤回走同一删除路径（outbox），保证只有一套删除语义。

### 4. 访问与审计

- 原始留存音频只允许数据主体本人和已通过上述关系证明门禁的监护人读取。教师、管理员、Notebook owner/editor/viewer 身份本身均不授予读取权；跨主体、关系失效、同意失效或对象不存在统一 fail closed，不暴露对象是否存在。
- `storageKey` 永不进入浏览器与公共 DTO，沿用既有 Asset 约束（0018:144）。
- 每次音频**读取**、每次**撤回**、每次**删除意图写入**与每次**删除终态**（completed/failed）都产生稳定审计事实；审计事实可追溯主体、时间与操作类型。
- 日志不得包含音频字节、Prompt、Secret、Provider body 或对象存储键，只允许稳定 ID、objectKind 与错误码（沿用 V15 完成标准）。

**推荐 B**：A 无法承载单独同意的法定要素且语义错误；B 用独立事实表达同意，仅把 A 的字段形状作为关系声明建模参考；C 保留为“只有实时处理同意、没有留存或云端同意”时的 Node/WASM 内存降级形态。

**delegated_grants 可复用边界**：

- 可复用：`kind='education.guardian'` + `granteeUserId/subjectUserId`（schema.ts:249-254,277）只作为未来关系声明的字段形状参考；`grantedAt/expiresAt/revokedAt` 时间结构（schema.ts:262-266）与 `grantee_active` 索引（schema.ts:270-274）可借鉴为 active 查询模式。现有 grant 行本身不是经过验证的监护关系。
- 不可复用（**绝对不能**冒充音频留存同意）：① 委托语义本身（schema.ts:243 注释）；② `scopes` 封闭枚举与 1-16 约束（schema.ts:283-286；routing.ts:139-146 无 audio scope）；③ 无同意版本/展示文案版本/目的字段（schema.ts:244-288）；④ 当前无 repository 与授权消费方（routing.ts:148-179），复用不等于现成可用。

## 对下游任务的约束

- **V11（同意与音频留存 schema/migration）**：本 ADR accepted 后才解锁。只建立同意事实与留存记录约束；storageKey 仅服务端字段；转录文本不存此表；无有效同意不能创建留存记录；到期上界配置只能缩短。不得把本 ADR 的契约当作已实现 Schema 写入。
- **V14（留存 repository、访问审计与删除意图）**：本人/监护人读取、读取审计、撤回/到期扫描、同事务写删除 Outbox 意图；storageKey 不进公共 DTO；教师/管理员/跨主体默认拒绝。
- **V15（音频硬删除 Worker）**：复用既有 Outbox claim/complete/fail 模式，不建第二套调度器；对象不存在幂等成功；删除失败可查询并退避，崩溃重启继续；不恢复用户可见音频。
- **V16（浏览器采集与重采样）**：采集前校验有效同意；本任务不存音频；SSR 导入不得触碰 window/navigator。
- **V17（能力总闸门）**：缺有效同意时语音入口隐藏/禁用且原因可读；同意缺记录/过期/撤回/无法验证一律 fail closed。
- 本 ADR 已 accepted，因此只解锁直接后继 V11；V14、V15、V16 仍须等待各自正常前置任务，不能跨级开发。

## 项目负责人已接受的保守默认

1. **监护关系证明**：开发/演示允许明确标记的 `self_attested` 记录；生产环境在接入可信核验前拒绝，不存证件图片。
2. **年龄与授权能力**：由于现有 age band 无法精确区分十四周岁，所有非 `adult` 与 `unknown` 都要求监护人同意。
3. **授权粒度**：实时处理、本地留存、云端外传三项分别授权、分别撤回，不允许互相隐含。
4. **同意有效期**：默认 12 个月；文案、目的、处理方式或数据范围变化立即重新征求。
5. **音频留存期限**：维持最多 7 天，配置只能缩短；真实使用需要调整时另开 ADR，不在环境变量中放宽。

## 验证方式
