# ADR-0016：视频来源派生与部分成功边界

- 状态：`accepted`
- 日期：2026-07-27
- 负责人：项目负责人

## 背景

平台已经具备音频来源转录（ADR-0007 之后的音频纵切）与资产派生任务（预览、缩略图）。
教学素材里仍有一类无法处理的输入：课堂录像与讲解视频。

视频与既有输入的关键差别是**一个来源产生多条彼此独立的派生**：音轨转录与画面
关键帧。它们的失败原因完全不同——一段无声视频永远不会有转录，但画面完好；一段
编码异常的视频可能音轨正常而画面无法解码。把它们塞进单一 `status` 会让「处理失败」
同时掩盖「这段视频本来就没有声音」和「抽帧崩了」。

## 前置条件与假设

本 ADR 的执行前提是「音频转录与资产派生任务均已落地」，这一条已经满足。

**尚未由 Code Owner 确认的假设**：首批教育使用场景、格式、大小与时长预算。本 ADR
按下列预算实现，若产品结论不同，预算必须先改再实现：

| 维度   | 首批预算                                                  | 依据                                              |
| ------ | --------------------------------------------------------- | ------------------------------------------------- |
| 格式   | MP4（`isom`/`mp42`/`avc1` 等 brand）、QuickTime（`qt  `） | 课堂录制设备与手机的默认产出                      |
| 大小   | 50 MiB                                                    | 与 `asset_versions_size_check` 的库级字节上限同值 |
| 时长   | 20 分钟                                                   | 单个知识点讲解片段，不是整节课录像                |
| 分辨率 | 1920×1080 像素总数                                        | 抽帧与转码的解码内存上界                          |
| 关键帧 | 固定 4 帧，等间隔，JPEG，宽 640                           | 够做时间轴预览，不足以还原原片                    |

## 决策

### 格式与识别

1. 首批**不收 WebM**。WebM 与音频 WebM 共用同一个 EBML 魔术字，仅凭容器头无法区分
   「有视轨」和「纯音频」，而现有音频路径已经在用这个魔术字。在没有完整解析的前提下
   加入它，只会让两条路径互相误收。
2. MP4/MOV 与 M4A 共用 `ftyp` box，只有**主 brand** 能区分。此前音频探测把所有
   `ftyp` 都认领为 M4A，这会让一段 MP4 视频被送进音频转录路径；本次按 brand 收窄
   音频探测，并让复合探测器**先判视频、再判音频**。
3. 识别只依据容器 brand。文件名、浏览器 MIME 和客户端声明都不参与判断，Worker 侧
   还会用原始字节重新判定一次——上传时的结论不作为处理阶段的依据。

### 资源边界

4. 字节上限在上传层生效；**时长与分辨率无法从字节数判断**，必须等 Worker 用 ffprobe
   判定后才能拒绝。因此超时长视频会先落库为 `processing`，再以稳定失败码终结。
5. ffmpeg/ffprobe **只在 Worker 进程中**执行，用 `execFile` 传固定 argv 数组，
   不经过 shell：路径来自服务端临时目录，argv 形式让路径里的任何字符都不可能变成命令。
6. 显式资源边界：ffprobe 20 秒 / ffmpeg 120 秒硬超时（超时后 SIGKILL）、
   `-threads 1`（单任务不抢占整个 Worker 的 CPU，并发度由队列控制）、`-nostdin`
   （默认读 stdin 会在 Worker 里挂死）、ffprobe 输出 4 MiB 上界。
7. 临时目录每任务一个，**无论成败都在 `finally` 中回收**。转码中途被 SIGKILL 时不会
   有任何成功分支代码执行，清理挂在成功路径上必然残留。

### 不引入 ffmpeg 二进制依赖

8. 仓库**不打包** ffmpeg 二进制。它有平台差异与授权约束，把几十 MB 的平台相关产物
   放进依赖树，换来的只是少写一行部署文档。工具链路径由
   `EDUCANVAS_FFMPEG_PATH` / `EDUCANVAS_FFPROBE_PATH` 提供（默认 `ffmpeg`/`ffprobe`），
   缺失时以 `video_toolchain_unavailable` 诚实失败，不是崩溃。

### 复用而不复制转录

9. 视频音轨**复用 `AudioTranscriptionModelGateway`**，不新增第二套转录 Port。Worker
   只负责把视频变成一段符合白名单的单声道 16 kHz MP3，之后完全走既有转录路径。
   降采样与单声道不是画质取舍而是成本控制：转录模型对语音只需要这个规格。
10. 转录文本写入既有的 `asset_versions.transcription_text`，与音频来源同一列。
    提取出的音轨本身是**不持久化的中间产物**：它完全可从原视频重算，保留它只会让
    同一内容占两份存储。

### 关键帧是派生物

11. 关键帧存入 `asset_video_keyframes`，每帧带 `checksum`、`byteSize`、
    `timestampSeconds` 和 **`algorithmVersion`**。抽帧策略（帧数、时间点选择、编码
    参数）任何一项变化都必须提升版本，否则历史帧与新帧无法区分是不同算法还是不同内容。
12. `(assetVersionId, algorithmVersion, ordinal)` 唯一，使同一版本在不同算法下的帧
    可以共存，算法升级因此是可回滚过程而不是就地覆盖。
13. 对象键由**内容哈希派生**：同一版本重投产生完全相同的键与内容，重复写入是幂等
    覆盖而不是产生孤儿对象。
14. 与 `asset_representations` 的分工：representation 记录「这个版本有没有关键帧、
    处于什么状态」（一个版本一行），本表记录「具体是哪几帧」。

### 部分成功

15. 三个阶段的失败语义各不相同：
    - **探测**（格式、时长、分辨率）失败是**整体失败**——没有元数据就没有可用版本；
    - **音轨转录**失败只影响转录 representation；
    - **关键帧抽取**失败只影响关键帧 representation。
16. 只要探测成功，Asset Version 就进入 `ready`，任务记为 `succeeded`。两路派生各自在
    `asset_representations` 上留下自己的 `ready` / `failed` / `unavailable`。
17. **无音轨返回 `unavailable` 而不是 `failed`**：无声视频是合法输入，不是错误。UI
    因此能诚实区分「还没做」「做失败了」和「这段视频本来就没有声音」。
18. 重试语义：整体失败中，确定性失败（不支持的格式、损坏文件、工具链缺失）直接写终态
    不重试；瞬时失败交给 Graphile 退避，重试耗尽后仍写终态，不把账本留在 `running`。
    单路派生失败不触发整体重试——重试它需要用户显式重新处理（见开放问题）。

### 浏览器边界

19. CanvasResource 只暴露 `video` representation、状态与服务端授权后的动作。
    `objectKey`、临时路径、ffmpeg 命令行与原始异常都不进入任何浏览器响应。

### 生命周期

20. 关键帧与 representation 一样是派生对象，删除 Source 时一并进入对象删除 outbox
    （`source_type = 'asset_video_keyframe'`）。漏掉它们会在对象存储里留下无人引用的
    孤儿帧。

## 后果

- 课堂录像可以作为来源被转录并在时间轴上预览，不需要教师先自行转成音频；
- 部分成功成为一等状态，"这段视频没有声音" 与 "抽帧失败了" 不再互相掩盖；
- 未安装 ffmpeg 的部署行为完全可预期：视频上传会以 `video_toolchain_unavailable`
  终结，其余功能不受影响；
- 代价是 Worker 多了一个外部进程依赖，以及每个视频版本额外 4 张 JPEG 的存储。

## 开放问题

- **首批预算未经 Code Owner 确认**，见上文表格。这是本 ADR 唯一的硬前提缺口。
- 单路派生失败没有独立重试入口：目前只能整任务重投。需要 UI 上的「重新处理」动作
  和一个只跑失败那一路的任务变体。
- 关键帧尚无受控读取面：数据已经落库，但 Web 还没有对应的字节下发端点与 Renderer，
  Canvas 暂时只能显示视频状态而看不到帧。
- 没有视频内容安全审核。抽出的帧与转录文本都未经二次审核，面向未成年人的公开分享
  前必须重新评估。
- 未实现按用户/Notebook 的转码配额；当前只有单文件的大小与时长上限。
