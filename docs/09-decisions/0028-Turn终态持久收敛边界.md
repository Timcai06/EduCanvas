# ADR-0028：Turn 终态持久收敛边界

- 状态：`proposed`
- 日期：2026-08-12
- 决策范围：CA01 契约冻结；最终接受由集成负责人审查
- 上位决策：[ADR-0002](./0002-网关客户端渠道与能力节点.md)、[ADR-0003](./0003-统一运行时与笔记本上下文.md)

## 背景

Web General 的 Turn Application 先在消息事务中结算 assistant 正文和引用，Gateway 随后在另一事务追加 terminal event 并更新 `agent_operations`。进程在两次提交之间失败时，消息和 Operation 会永久分叉；反向的取消竞速也可能先写 Operation terminal，再留下未结算消息。

把 Agent Loop、工具副作用和所有 Gateway 事件塞进一个跨层大事务会扩大耦合，并且无法把 Provider 或外部工具调用纳入数据库原子性。仅做进程内 retry 又不能覆盖重启。

## 提议

1. Gateway 继续是 Operation terminal 的唯一 writer；Turn Application 不直接修改 `agent_operations`。
2. assistant 消息和引用结算时，在同一 PostgreSQL 事务冻结一个 operation 唯一的 `terminal commit intent`。它只保存 operation/message ID、公开终态、公开 Gateway failure code、retryable 与结算时间；不保存正文、Prompt、Provider body、工具参数、secret 或 stack。
3. assistant 消息、引用、Operation 和 terminal event 保留各自既有事实；Gateway Operation Store 提供持久、幂等、可重启的 reconciliation 入口，在 Operation 级事务锁内同时读取 intent、Operation 和最后一个 terminal event：
   - 两侧都未终结时返回 pending，不制造失败；
   - intent 已冻结而 Operation 仍 running 时，按 intent 追加唯一 terminal event；
   - terminal event 已提交而 assistant 仍 active 时，只允许在以下情形补齐消息终态：
     - `terminal` 为 `failed`/`cancelled` 且正文为空；
     - `completed` 必须已存在 durable lifecycle intent（`terminal intent`）；
       其余场景一律 fail closed（包含已有 partial content）。
   - 两侧终态一致时幂等返回；两侧冲突时 fail closed 并产生无正文、低基数诊断，禁止最后写入者覆盖。
4. terminal event 与 `agent_operations` 状态仍必须在同一数据库事务提交。重复 reconciliation 不得产生第二 terminal event、第二份引用或重新执行模型、工具、Artifact Job。
5. Gateway 对同一 idempotency key 的 replay 在返回历史事件前执行 reconciliation。当前请求的 terminal append 失败时也调用同一入口；若数据库仍不可用，请求诚实失败，后续 replay 或重启恢复继续收敛。没有 intent 且仍在执行的 Turn 不得仅凭年龄被猜成失败；如需恢复进程中段，必须另有 lease/owner 事实。
6. Tool effect ledger 的 `committed/outcome_unknown` 语义不变。terminal reconciliation 只补消息与控制面终态，不重新调用 Tool 或 Provider。

`packages/gateway-runtime/src/terminal-reconciliation.ts` 是 CA01 冻结的 provider-neutral 纯状态机。Drizzle 加载、写入、故障注入和启动/replay 接线属于 CA02/CX01。

## 故障点与预期

| 故障点                               | 持久事实                           | 恢复动作                                                                               |
| ------------------------------------ | ---------------------------------- | -------------------------------------------------------------------------------------- |
| 模型或工具终态前失败                 | 双侧仍 active 或已有安全失败结算   | 原 Turn 失败路径结算；不由 reconciliation 猜测结果                                     |
| assistant 结算后、terminal append 前 | terminal intent，Operation running | 补唯一 Gateway terminal                                                                |
| 取消 terminal 后、assistant 结算前   | Gateway terminal，assistant active | 允许补齐空正文；有 partial content 时 fail closed；completed 必须已有 lifecycle intent |
| terminal append 响应丢失             | 两侧已一致                         | 幂等返回已有 terminal                                                                  |
| 重启后重复相同请求                   | 原 operation + 持久事件            | 先收敛，再 replay；不进入 Agent Loop                                                   |
| 已有冲突终态                         | 两侧不一致                         | fail closed，保留证据，禁止覆盖                                                        |

## 回退

CA02 的 reconciliation 调用必须可从组合根关闭并回到既有 append 路径；回退不删除事件或消息。若观察到冲突，停止自动写入，但保留只读诊断。任何 schema 变更必须独立 Migration，不与功能切换混成一个不可回退提交。

## 验证要求

- 纯状态机覆盖 pending、双向补齐、幂等和冲突；
- PostgreSQL 故障注入覆盖消息后 append 前、append 响应丢失、重复、取消与重启；
- Gateway/Web replay 证明模型、工具和 Artifact 副作用不会第二次运行；
- 诊断与浏览器响应不包含 Prompt、Provider body、secret 或 stack。
