# ADR-0026：多模态输入原件与派生表示边界

- 状态：`accepted`
- 日期：2026-08-11
- 负责人：@hzlgou
- 扩展：[ADR-0010](./0010-资产解析异步化与解析器归位.md)、[ADR-0017](./0017-文本与视觉提供商分离与图片输入路由.md)

## 背景

EduCanvas 已允许用户上传 PDF、DOCX、Markdown、纯文本和图片，并通过现有 Asset、
Worker、私有对象存储和 Turn materialization 链路向 Agent 提供上下文。当前文档抽取以
`unpdf`、`mammoth.extractRawText` 和 UTF-8 解码为主，标题、表格、公式、图片与页面
关系会退化为纯文本；另一方面，Canvas 的 Source 预览与 Agent 使用的抽取文本容易被
误解为同一份内容。

输入侧需要同时满足两个不同目标：用户查看时忠实保留原文件及其身份，Agent 推理时获得
结构清晰、可预算、可审计的表示。不能为了统一 Agent 上下文而覆盖原件，也不能把所有格式
强行伪装成 HTML 或 Markdown 原件。

## 候选方案

### 方案一：转换后用 Markdown 替换原文件

- 优点：读取路径单一；
- 缺点：丢失原始排版、签名、页码和下载事实，无法忠实预览或重新转换；
- 结论：不采纳。

### 方案二：只保存原文件，运行时临时抽取

- 优点：存储模型简单；
- 缺点：每轮重复转换、延迟不可控，无法冻结 producer/version/quality，也难以复用图片与公式；
- 结论：不采纳。

### 方案三：不可变原件加版本化派生表示

- 优点：原件、预览、Agent 上下文和后续重处理相互独立；可记录转换质量与生产者版本；
- 代价：需要治理派生文件、图片 manifest、兼容读和降级状态；
- 结论：采纳。

## 决定

### 1. 原件是 Source 事实，派生表示不是替代品

- 每次上传产生不可变的 `assetId + versionId` 身份；原始 MIME、字节、校验和与私有存储
  身份继续作为 Source 的事实来源。
- PDF 在 Canvas 中继续由 PDF Source Renderer 按原格式预览；图片、音频和视频继续由其
  原生媒体 Renderer 呈现。浏览器不能获得对象存储 key。
- 浏览器无法忠实原生预览的 Office 文件必须保留原件下载入口，并可另开“结构化阅读”视图；
  不得把派生 Markdown 冒充原始 DOCX/PPTX/XLSX。
- 派生表示必须绑定原始 `assetId + versionId`。重新处理可产生新的派生版本，但不能悄悄
  改变已冻结 Turn 所使用的表示。

### 2. 文档统一为结构化 Markdown 表示

- PDF、DOCX、PPTX、XLSX 进入独立 MinerU 转换服务；Worker 使用有界上传、轮询、取消、
  超时和结果校验，不在 Node 进程内加载 Python 模型或创建第二套任务账本。
- TXT、Markdown 通过严格 UTF-8 解码和规范化直接产生 Markdown representation，不调用
  MinerU。
- MinerU 未配置或服务不可用时，允许回退到现有 `unpdf`/`mammoth` 纯文本抽取；该结果
  标记为 `degraded_plain_text`，不能与完整结构化结果等价。
- Markdown 是 Agent 上下文和结构化阅读的主表示，但始终按不可信用户材料处理；资料内的
  指令不获得系统或工具权限。

### 3. 保留派生图片与可验证 manifest

- MinerU 输出的文档图片、图表和公式截图必须保留在同一不可变派生表示下，不能只留下
  断裂的 `images/...` Markdown 引用。
- 每个派生图片记录受控相对路径、内容 hash、MIME、字节大小和顺序/位置元数据；禁止绝对
  路径、`..`、符号链接和未声明文件。
- Markdown 中的图片引用在服务端投影为已鉴权的 Canvas Source resource URL；响应时重新
  校验用户、Notebook、Asset 与 Version 权限，不暴露私有存储位置。
- 解包文件数、单文件大小、总字节、Markdown 长度和图片数量均有平台上界；超限明确失败，
  不静默遗漏用户选择的资料。

### 4. 不同媒体保留各自的原生语义

- 图片：原图是视觉上下文；OCR、caption 或布局文本只是可选派生表示，不能替代原图。
- 音频和视频：原媒体用于播放；派生 transcript 应保留时间戳和 producer 身份，不强行伪装
  成普通文档。
- 网页与链接：保留原 URL、抓取时间与来源身份，正文可派生为 Markdown 快照；外部内容仍
  按不可信材料处理。
- 不支持的媒体明确返回 `unavailable` 或保持 `processing/failed`，不能返回空文本伪装成功。

### 5. Agent materialization 使用统一、可追溯的上下文

- Turn 仍只提交 `asset_ref`；服务端重新校验 Notebook 权限、Asset、Version、ready 状态和
  类型后，再投影为 provider-neutral context parts。
- 文档进入有界 Markdown 文本段；图片在视觉模型可用时进入受数量和总字节预算限制的 native
  image parts；音视频使用相应的已授权派生表示。
- 每次 context snapshot 冻结实际 representation identity、quality、producer、
  producerVersion 与来源版本。后续重新处理不能改变历史 Turn 的上下文事实。
- 资料不会授予工具能力；工具清单仍由现有 Agent Runtime policy/kernel 决定。

### 6. 质量与失败对用户可见

派生表示至少区分：

- `structured`：MinerU 或直接 Markdown 解码产生的结构化表示；
- `degraded_plain_text`：结构化转换失败后由纯文本抽取成功；
- `failed`：结构化与降级路径均失败；
- `processing`：仍在转换，当前 Turn 不得静默带入。

来源列表、Canvas Source 阅读视图和 Live Voice 本轮上下文必须显示实际状态。日志记录阶段、
稳定错误码、jobId、外部 taskId 和 producer，但不得记录原始文件正文、供应商错误体、主机
路径或密钥。

## 所有权与交付边界

ADR-0026 及其实现由 `@hzlgou` 负责，范围包括：

- 上传格式与 MIME/魔术字验证；
- MinerU Adapter、Worker 调用、背压、超时、取消与降级；
- 原件和派生 Markdown/图片的不可变身份、质量与 provenance；
- Source 原格式预览、结构化阅读和鉴权资源路由；
- Agent context materialization 与输入侧回归测试。

Canvas 输出类型、Artifact Renderer、自由 Web App Runtime 和输出选择不属于本 ADR，由
[ADR-0027](./0027-Canvas多形态输出与交互运行时边界.md)约束。两条线只通过版本化的
context part / artifact proposal 契约汇合，均不得创建第二套 Agent Loop。

## 后果

- 原件可以忠实预览、下载和重新处理，Agent 同时获得结构化内容与必要的原生图片。
- MinerU 成为额外部署能力，需要内网鉴权边界、模型版本治理、并发背压和可观测性。
- 旧 `text/plain` representation 保持兼容读；迁移不能要求重传原文件。
- 派生图片增加私有存储和资源路由成本，但避免“多模态”退化为只有 OCR 的文本系统。
- 若需要新增或调整持久字段，必须使用正式 Drizzle Migration，不手改生成输出。

## 验证方式

1. 上传 PDF 后仍可按原 PDF 预览；同一版本另有结构化 Markdown 阅读表示。
2. 含标题、表格、公式和图片的真实 PDF/DOCX 样本完成转换，图片经鉴权资源路由显示。
3. TXT/MD 不调用 MinerU，严格解码失败明确终止。
4. 关闭 MinerU 后走纯文本降级，UI 与 context snapshot 均显示
   `degraded_plain_text`。
5. Agent 同时收到有界 Markdown 和必要的 native image parts，且无对象存储 key 泄露。
6. 旧资产、旧 `text/plain` representation 与已冻结 Turn 仍可读取。
7. CI 使用 fake MinerU 服务验证超时、重试、结果损坏、路径穿越、解包炸弹、权限复验和
   secret containment；真实 GPU 服务只做受控 canary，不进入普通 PR CI。
