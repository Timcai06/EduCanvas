# ADR-0032：工程包策略与公共错误治理

- 状态：`accepted`
- 日期：2026-08-22
- 负责人：@Timcai06
- 上位决策：[ADR-0002](./0002-网关客户端渠道与能力节点.md)、[ADR-0003](./0003-统一运行时与笔记本上下文.md)、[ADR-0023](./0023-Web-features静态边界.md)

## 背景

EduCanvas 已形成 26 个 pnpm workspace、单一 Agent Loop、Gateway/Web 双入口和风险分流 CI。
此前这些约束分散在 manifest、测试和人工知识中，新包、深层 import、Provider SDK 或临时债务
可以绕开评审意图。Web HTTP 错误还可能把服务端文案当成公共字段，扩大内部异常泄漏面。

## 候选方案

| 方案             | 做法                                                              | 结论                                   |
| ---------------- | ----------------------------------------------------------------- | -------------------------------------- |
| A 复用现有治理   | 在 `file:check`、tooling tests 和 CI impact 上增加机器可读 policy | **采纳**：约束靠近现有入口，失败反馈快 |
| B 引入新治理平台 | 增加独立服务、框架或远程策略引擎                                  | 拒绝：对模块化单体增加无必要运行依赖   |
| C 只靠文档评审   | 记录建议但不阻止违规                                              | 拒绝：无法证明新包、入口和例外没有漂移 |

## 决定

1. `tooling/architecture/package-policy.json` 是 workspace 分类、逻辑 Owner、允许依赖种类和公开
   entrypoint 的架构事实源；自动发现的 workspace 必须完整登记。
2. core/runtime/adapter/app 按依赖矩阵检查。Provider SDK 只允许在 `model-gateway`；跨包
   `/src/*`、未声明子入口和相对穿越禁止。
3. allowlist 只能记录精确 consumer 与 target/specifier，且必须包含 `reason`、`issue`、`expiry`。
   尚无外部 Issue 时使用唯一 `internal:ARCH-DEBT-####`，过期、未使用或扩大范围均失败。
4. Web 与 Gateway 的 HTTP/升级失败只公开 `{ error: { code, requestId } }`；重试时间只通过
   `Retry-After`。浏览器依据稳定 code/status 映射本地文案。
5. `gateway.v1` 的 `operation.failed` 是严格协议事件，不是 HTTP envelope。它保留
   `code/retryable`，并拒绝任意 message、stack、Provider body 或 prompt 字段。
6. 大文件债务继续由 `file:check` 管理，但每项必须有 Owner、原因、目标、追踪号、期限和
   acceptedLines；新 400 行文件和既有债务增长直接失败。
7. CI 继续风险分流并保留 required check 名称，同时公开 Changed/Required/Skipped 解释；
   未知路径或分类异常全矩阵 fail-open。

## 后果

- 新 workspace、依赖或入口需要先作出可评审的架构决定；bootstrap 例外会自动到期。
- 公共错误不再携带服务端可变文案，UX 文案改由客户端稳定映射维护。
- 治理规则本身进入同一 `file:check` 和 tooling test 入口，不新增部署组件。
- 收紧 exports 或清理 allowlist 可能暴露历史耦合；应以小提交修复，不放宽全局规则。

## 回退

八个治理提交均可独立回退。若单条策略误判，优先修正 policy 元数据或精确、短期 allowlist；
不得通过关闭 `file:check`、暴露内部错误或创建第二个 Agent Loop 回退。

## 验证要求

1. `pnpm file:check` 验证登记、依赖、入口、公共输出和文件债务；
2. `pnpm lint && pnpm typecheck && pnpm test:unit && pnpm build` 验证工作区契约；
3. Gateway/Web 恶意异常测试证明 HTTP、NDJSON、SSE、WebSocket 不泄漏内部内容；
4. 跨入口 fixture 冻结工具完成、失败、审批、取消、能力不可用和运行失败的事件顺序；
5. CI impact 测试覆盖 DB、migration、desktop、Web、docs、根依赖、未知路径和全矩阵事件。
