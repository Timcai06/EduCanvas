# ADR-0013：K12 消息渐进迁移与双轨退役边界

- 状态：`accepted`
- 日期：2026-07-27
- 负责人：项目负责人

## 背景

通用 Conversation 使用 `conversation_messages`，结构化 K12 Session 仍使用
`chat_messages`。直接合表会同时改变教学租约、取消、幂等、消息读取和历史恢复，难以
证明兼容性，也缺少安全回滚窗口。

平台需要先提供统一历史读取，再逐步把 K12 可见消息迁入平台消息事实，同时保留
`chat_messages` 中只有教学运行时需要的字段。迁移过程不能创建第三张消息事实表，也
不能让同一条消息在两个表中产生互相矛盾、无法对账的身份。

## 决策

1. `conversation_messages` 是平台长期消息事实，`chat_messages` 在迁移期继续作为 K12
   兼容消息与教学运行态事实；统一历史 Repository 只是只读投影，不是新事实源。
2. 统一读取通过受信的 `lesson_sessions.conversation_id` 关联 K12 消息，并先验证当前
   Actor 的 Notebook 访问权。不存在、跨用户和跨 Notebook 统一表现为不可见。
3. 历史按 `createdAt`、来源和消息 ID 确定性排序，使用有界 keyset cursor，不使用
   `offset`，分页不得重复或遗漏。
4. K12 `student` 角色投影为平台 `user`；`assistant` 保持不变。迁移不得伪造
   `system` 或 `tool` 角色，failed、cancelled、interrupted 等状态必须诚实保留。
5. 新 K12 可见消息可以在创建 `chat_messages` 的同一 PostgreSQL 事务中写入
   `conversation_messages`。副本 ID 必须由原 K12 消息 ID 确定性派生，重试只能得到
   同一身份；同 ID 不同内容或归属必须拒绝并回滚整个事务。
6. `legacy|observe` 阶段的新副本创建由 `EDUCANVAS_K12_CONVERSATION_DUAL_WRITE` 控制且默认
   关闭；`platform` 已选择平台可见权威，因此必须持续创建副本，不能由独立观察开关关闭。
   已经存在的平台 assistant 副本在任一阶段仍随原事务收敛到相同终态，避免部署切换产生永久
   processing 漂移。
7. lease、heartbeat、`cancelRequestedAt` 和教学内部运行态只属于 `chat_messages`，
   不复制到 `conversation_messages`。平台副本只保存浏览器和跨入口需要的消息事实。
8. 对账必须有界并至少区分 missing、mismatch 和 orphan；不得返回消息正文、Prompt、
   Provider 原文、堆栈或私人判分信息。对账结果供受信 operator/service principal 使用。
9. 回填、切读和旧表退役是三个独立闸门。任何阶段失败都应能关闭双写并回到上一条已验证
   读路径，不能通过删除旧表制造不可逆切换。

## 切换闸门

### 回填前

- 统一读取覆盖两张表、相同时间戳、所有终态和跨 Notebook 拒绝；
- 双写具备并发幂等、冲突回滚和开关跨部署漂移测试；
- 对账能诚实报告 missing、mismatch 与 orphan。

### 切读前

- 有界回填完成并记录批次、游标和校验摘要；
- 连续观察窗口内新增双写无未解释差异；
- Web、Gateway、TUI 与 K12 恢复路径均通过兼容测试；
- 回滚开关和旧读路径仍可用。

### 退役 `chat_messages` 前

- K12 lease、取消和恢复运行态已有明确的新归属，或证明仍需保留独立运行表；
- 所有生产消费者已停止读取其可见消息字段；
- 数据保留、审计、回滚窗口和删除迁移获得独立批准。

## 后果

- 当前允许双表共存，但双轨是有退出条件的迁移状态，不是永久领域模型；
- 页面和 API 可以先获得统一历史，而不强迫一次性迁移 K12 Runtime；
- 写放大、对账和回填增加短期成本，换取可观察、可回滚的迁移；
- 在上述闸门通过前，不删除、不重命名 `chat_messages`，也不宣称已经完成消息事实合并。

## 实施状态（2026-08-13）

统一读取投影、默认关闭的事务内双写和有界对账已实现。手工维护任务
默认 Worker registry 不暴露回填写入；受信 operator 直接调用 repository preview/apply，保持稳定游标和幂等补缺；
发现既有投影错配时整页零写入。真实 PostgreSQL 集成测试覆盖 dry-run、回填、续跑、重跑和
错配拒绝。

受控切读已经接入 Web K12 可见历史：单一 authority 配置支持 `legacy|observe|platform`，默认
legacy 并在进程构造时冻结。platform 只在 provenance sidecar 与单个 repeatable-read 快照的
全量 missing/mismatch/orphan 对账均通过后返回 `conversation_messages` 可见字段；不一致整页
fail closed，不混读或静默 fallback。公开 message ID、引用、分页键和教学运行态仍来自
`chat_messages`，显式改回 legacy 并重启即可回退。

旧表退役仍未开始。回填通过、切读通过与旧表退役继续是独立闸门；当前应用的 settle 与审计
仍引用 provenance sidecar，因此配置回退也不删除 sidecar、两张消息表、引用或教学运行态。
