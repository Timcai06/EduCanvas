## 一、先立两个硬约束（来源：CLAUDE.md 与 KM 计划）

| 约束                     | 原文出处                                                                                                                                                           |
| :----------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 不复制第二套检索基础设施 | `docs/plan/active/KM-知识记忆.md:19-21`、`:122-125`：「禁止……为教育场景复制检索基础设施」「不得创建第二个 Agent Loop、Context Compiler、RAG 基础设施或权威事实表」 |
| LangChain 不作为核心依赖 | `CLAUDE.md:45`；`docs/03-ai/01-智能体编排边界.md:114-116`                                                                                                          |
| 嵌入式向量必须记录身份   | `CLAUDE.md:44`：「Embedding 必须记录模型、版本、维度、指令和切块版本」                                                                                             |

**推论**：该技能的技术栈（Milvus + Ollama + Docker + LangChain 全家桶）**整体不可照搬**，与本仓库 [ADR-0015](../../09-decisions/0015-混合语义检索与向量身份边界.md) 的"不删 tsvector、不用外部托管向量库"决策直接冲突。本分析只提取**方法论思想**。

## 二、逐项对比：该技能 vs EduCanvas 现有底座

### 2.1 检索编排

| 维度     | 技能方案                        | EduCanvas 现状                                                                                                      | 对比结论                                           |
| :------- | :------------------------------ | :------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------- |
| 混合策略 | BM25 + 向量，weights=[0.3, 0.7] | `postgres_hybrid`（`rrf-v1`）FTS + 向量 RRF 融合                                                                    | **我们更强**：RRF 无权重调参，技能用的是加权和     |
| RRF 参数 | 无（技能未用 RRF）              | `knowledge-hybrid-retrieval.ts:41-45` k=60、召回池 limit×4、硬上限 200                                              | 我们有 ADR-0015 依据的完整参数                     |
| 降级语义 | 无                              | `:329-332` 向量失效时诚实返回 `postgres_fts` + `rrf-fallback-v1`，绝不空结果冒充                                    | **我们更强**：fail-closed + 诚实标记               |
| Rerank   | BgeRerank（虚构类）             | **未接入生产**：`docs/03-ai/04-检索增强与嵌入.md:24`「Reranker 尚未接入生产」；候选 Qwen3-Reranker 系列在评测冻结中 | **这是技能唯一领先的能力方向**，详见 §3.2          |
| 查询嵌入 | BGE instruction 前缀            | `apps/web/server/teaching/knowledge-retrieval-runtime.ts:105-127` embedQuery 失败返回 null 退回纯词法               | 概念一致（query/passage 不对称），我们有指令版本化 |

### 2.2 向量身份（技能完全没有的一环）

EduCanvas 的向量身份五要素（`packages/db/src/schema.ts:2176-2194`）：**模型、模型版本、指令（`passage:v1`）、切块版本、chunk 内容哈希**，唯一键=(chunkId, model, modelVersion, instruction)，同 chunk 多模型向量可共存；`model-gateway.ts:205` 维度 1536 写死为 Schema 级事实。

技能的做法是**裸向量**（BGE-zh 1024 维，无版本、无指令、无切块标识）——换模型/换分块即静默错配。

**结论：这是技能最薄弱的环节，也是我们最成熟的环节（ADR-0015 全文）。** 技能文档里"Matryoshka 1024 截 256 省 75%"的声称恰恰忽略了：截断即换向量空间，需要身份机制才能安全切换——我们已有现成机制。

### 2.3 分块

| 维度     | 技能方案                        | EduCanvas 现状                                                                                                                                                                                 |
| :------- | :------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 分块器   | 3 种策略 + 选择矩阵（见 04 篇） | **仓库内无分块器**：`apps/worker/src/tasks/ingest-knowledge-document.ts:19-41` 只接收外部已分好的 chunk（content≤20000、heading≤500、sha256 校验）；`docs/03-ai/04:85-91` 教材切块目标仍是规划 |
| 切块版本 | 无                              | `:54` parserVersion 由入队方冻结，作为切块版本；向量落库携带 `chunkingVersion`                                                                                                                 |
| 小2大    | 有（128/1024 tokens）           | 规划中（父子块）                                                                                                                                                                               |

**结论：这是技能最有借鉴价值的领域**——分块策略矩阵（按文档类型选策略）和小2大思想与我们"父子块"规划（`docs/03-ai/04:85-91`：保留年级/章节/知识点）方向一致，可作为规划参考，详见 §3.1。

### 2.4 作用域与安全（技能完全缺失的一环）

| 维度 | 技能方案                                           | EduCanvas 现状                                                                                                                             |
| :--- | :------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| 权限 | "RBAC 权限分级"一章引用的 `rbac.md` 文件**不存在** | `knowledge-retrieval-repository.ts:155-177` 权限判定在召回之前；`:322-346` source 绑定强校验 gradeBand/courseSlug 且必须 active            |
| 引用 | source_documents 原样返回                          | citation 白名单：`persistMessageCitations` 只允许引用本轮已持久化 candidate，`message_citations` 表不接受直达字段（`schema.ts:2474-2511`） |
| 隐私 | 无                                                 | ADR-0020 K12 隐私红线；ADR-0015 检索候选只存 query_hash 不存原文（`schema.ts:2421`）                                                       |

**结论：作用域与安全我们全面领先**，技能方案只停留在"提到 rbac.md 但文件不存在"的程度。K 线要做的就是"复用现有 fail-closed 语义扩展到 product 作用域"（KM 计划 62 行），而不是学技能。

### 2.5 评估

| 维度       | 技能方案                                               | EduCanvas 现状                               |
| :--------- | :----------------------------------------------------- | :------------------------------------------- |
| 指标       | 4 项 chunk 指标（召回/精确/完整性/噪声）+ ragas 4 指标 | `docs/03-ai/04:48-50` 有冻结评测集与候选模型 |
| 数据可信度 | 所有阈值（>90% 等）无出处（见 04 篇 §四）              | 数字需以我们自己的评测为准                   |

**结论**：指标方向一致（chunk 级召回/精确 + ragas 系），但技能的数字不可信。K03 评测可以参考其**指标维度**，阈值必须来自我们自己的冻结评测集。

## 三、可借鉴清单（3 条）与不适用清单（4 条）

### ✅ 可借鉴（方法论层面）

**1. 分块策略矩阵（高价值）** — 按文档类型选分块策略（通用/技术MD/论文/合同/对话/代码），与我们 K 线语料（`docs/` 的 markdown 技术文档）对应的是 MarkdownHeader 结构化分块。参考价值：**产品知识文档按标题层级分块，保留 heading 元数据**——我们 schema 已有 `heading` 列（`schema.ts:2111-2126` 的 search_vector 生成列就是 `heading || content`），摄取时嵌入 heading+content（`embed-knowledge-document.ts:85-87`），说明我们的底座天然支持按标题分块。具体分块器实现（仓库内目前没有）可以按此方向补，但归 Python 生态（`docs/05-engineering/02-后端工程.md:101`）。

**2. 小2大（Small-to-Big）检索（中价值）** — 检索小 chunk 精确定位、返回父 chunk 完整上下文。与我们 `docs/03-ai/04:85-91` 的父子块规划方向一致。注意：技能的实现（child 128 / parent 1024 tokens）是经验值且无出处，落地需自测参数。

**3. 评估指标维度（中价值）** — chunk 级召回率/精确率 + ragas 的 context_precision/context_recall 维度，K03 评测表可参考这些维度；阈值一律用我们冻结评测集的实测值。

### ❌ 不适用 / 不可照搬

**1. 全部代码** — LangChain 1.x 下 7/10 API 失效 + BgeRerank 虚构类 + 脚本编译失败。我们不用 LangChain（CLAUDE.md:45），无迁移负担。

**2. Milvus/Ollama/MinIO 技术栈** — 与 ADR-0015"不用外部托管向量库"、KM 计划"不复制第二套检索基础设施"直接冲突。我们的 pgvector + FTS 是既定事实源。

**3. "准确率数字"（72%→97% 表）** — 无出处、无评测方法，不可作为选型依据。我们以冻结评测集为准。

**4. 裸向量做法** — 无身份、无版本、无作用域的向量设计，与 ADR-0015 五要素身份机制背道而驰。

## 四、对 KM 计划 K 线的具体启示

| KM 任务             | 本研究的输入                                                                                                                   |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------- |
| K00 语料 allowlist  | 分块策略矩阵提醒：**不同语料形态要不同分块策略**。K00 定 allowlist 时应同时记录"每个来源的文档形态"，为 K02 分块策略提供输入   |
| K01 检索契约        | 技能无契约概念；我们的契约已在（作用域、fail-closed、citation 白名单），K01 是"扩展到 product 作用域"而非新建                  |
| K02 摄取 + 按需工具 | 分块器是真实缺口（仓库内没有），K02 需要补，参考 MarkdownHeader + 小2大方向；embedding 复用现有 gateway（1536 维、指令版本化） |
| K03 评测            | 参考技能的指标维度（chunk 召回/精确、ragas），阈值来自自有评测；Rerank 可作独立评测项（我们候选已冻结 Qwen3-Reranker 系列）    |

## 五、一句话总结

> 这个技能教的是**2024 年风格的独立 RAG 系统**，代码与数字都不可信；但它的**分块策略矩阵、小2大检索、评估指标维度**三个方法论方向，正好补在我们 K 线最薄的"分块"环节上。其余部分（检索编排、向量身份、作用域安全）我们的 ADR-0015 + KM 约束已经覆盖且更强——K 线要做的是把现有底座**复用到 product 作用域**，而不是向这个技能看齐。
