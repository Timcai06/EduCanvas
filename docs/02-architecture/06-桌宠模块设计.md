# 桌宠端（apps/desktop）模块设计

> 日期：2026-08-10 · 状态：已实现（PR #339，CI 全绿，待 Code Owner 审批）
> 依据：ADR-0024（远端桌宠运行形态与语音交互边界）与 spec `docs/superpowers/specs/2026-08-10-desktop-pet-design.md`
> 范围：P1（壳 + 占位角色 + 状态机演示交互）；P2 语音 / P3 身份 / P4 handoff / P5 双平台打包未实现

## 1. 总体架构与分层

```
┌─ 主进程（Node/Electron）─────────────────────────────────────────────┐
│  index.ts（入口/IPC 注册）                                            │
│    ├─ pet-window.ts   桌宠窗口控制器（拖动/位置记忆/钳制/托盘隐藏）     │
│    ├─ tray.ts         托盘生命周期（保留自旧小窗）                     │
│    ├─ assistant-proxy.ts  assistant:turn IPC → 本地 API（保留，P2 复用）│
│    └─ window.ts       旧文本窗（已不引用，待 P2 后删除）               │
└──────────┬────────────────────────────────────────────────────────────┘
           │ contextBridge
┌─ preload（index.ts）─────────────────────────────────────────────────┐
│  window.desktopPet（4 个方法）+ window.desktopAssistant（保留）        │
└──────────┬────────────────────────────────────────────────────────────┘
┌─ renderer（React + Canvas 2D）───────────────────────────────────────┐
│  App.tsx（交互编排） → pet-sprite.ts（帧渲染）→ pet-demo.ts（演示时序） │
└──────────────────────────────────────────────────────────────────────┘
           ↕ 共享纯函数层（src/shared/，无 Electron 依赖，可单测）
    pet-state.ts · pet-clamp.ts · pet-manifest.ts · pet-drag.ts
```

**分层原则**

| 层 | 依赖 | 可单测 | 职责 |
|---|---|---|---|
| `src/shared/` | 无（纯函数 + 类型） | ✅ 全部覆盖 | 状态机、钳制、校验、拖动计算——**所有业务逻辑** |
| `src/main/` | Electron | 手动/集成 | 窗口生命周期、IPC、系统集成 |
| `src/preload/` | Electron | 手动 | 唯一的 renderer↔main 通道（contextBridge，sandbox 下无 Node） |
| `src/renderer/` | React/DOM | 纯函数部分 | 交互、动画、渲染 |

> **为什么这么分层**：业务逻辑（状态机/钳制/校验）与 Electron 彻底解耦，54 个单测不启动 Electron 即可覆盖核心行为；Electron 特有代码薄而清晰，P2 替换渲染层不会碰 shared。

## 2. 角色包（assets/pet/）与生成脚本

### 2.1 scripts/generate-pet-sprites.mjs —— 占位角色生成器

**干什么**：零依赖生成占位像素角色的 sprite sheet + manifest，作为角色包契约的权威样本。

- 手写 PNG 编码器（Node `zlib.deflateSync` + CRC32 查表，RGBA color type 6，filter 0，IHDR/IDAT/IEND 三个 chunk）
- 绘制 11 帧 32×32 角色：idle 呼吸 2 帧、walk 4 帧、think 2 帧、speak 1 帧、success 1 帧（弯眼）、error 1 帧
- 输出 `assets/pet/sprite-sheet.png`（513B）+ `assets/pet/manifest.json`

**产出契约（manifest）**：

```jsonc
{
  "frameWidth": 32, "frameHeight": 32, "fps": 8,        // 帧尺寸与默认帧率
  "anchor": { "x": 16, "y": 32 },                       // 脚底锚点（后续用于地面/阴影定位）
  "states": {
    "idle":    { "frames": [0, 1],           "fps": 4,  "loop": true  },
    "walk":    { "frames": [2, 3, 4, 5],     "fps": 10, "loop": true  },
    "think":   { "frames": [6, 7],           "fps": 4,  "loop": true  },
    "speak":   { "frames": [8],              "fps": 8,  "loop": true  },
    "success": { "frames": [9],              "fps": 8,  "loop": false },
    "error":   { "frames": [10],             "fps": 8,  "loop": false }
  }
}
```

**替换角色**：只需替换 `assets/pet/` 下这两个文件（帧数/尺寸/状态名须满足契约），渲染层零改动——这是 P2/P5 换真实素材的入口。

### 2.2 为什么零依赖 PNG 编码而不是引入 pngjs

P1 素材是占位符，为它引入依赖不值；手写编码器约 120 行且被单测锁住（PNG 签名/尺寸/IDAT 存在性）。真实素材接入后此脚本退役，但**契约与校验逻辑保留**。

## 3. 共享纯函数层（src/shared/）

### 3.1 pet-state.ts —— 业务状态机

**干什么**：桌宠的全部**业务**状态转换，纯函数、无副作用。

```ts
export type PetState = 'idle' | 'listen' | 'think' | 'speak' | 'success' | 'error';
export type PetEvent = 'pet_click' | 'cancel' | 'listen_done' | 'think_done'
                     | 'speak_done' | 'demo_fail' | 'demo_reset';
export function transition(state: PetState, event: PetEvent): PetState;
```

转换表（6 状态 × 7 事件，未定义的事件**失败安全地保持原状态**）：

| 状态 | pet_click | cancel | *_done | demo_fail | demo_reset |
|---|---|---|---|---|---|
| idle | → listen | — | — | — | — |
| listen | → idle | → idle | → think | → error | — |
| think | → idle | → idle | → speak | → error | — |
| speak | → idle | → idle | → success | → error | — |
| success | — | — | — | — | → idle |
| error | — | — | — | — | → idle |

**设计要点**：
- **walk 不是状态**：踱步是渲染层动画变体（`walking` flag 只改变 idle 下渲染的帧序列），业务状态机冻结 6 状态——P2 接真语音时事件换成真实 Voice/Agent 事件，转换表不用动
- 交互中点击 = `cancel` 立即回 idle（P1 演示语义）
- 单测：17 个 case 全覆盖转换表 + 失败安全 + 终态不响应点击

### 3.2 pet-clamp.ts —— 多屏钳制与初始位置

**干什么**：保证桌宠窗口**永不丢到屏幕外**——跨屏拖动、显示器热插拔、分辨率变化时的钳制逻辑。

```ts
export const PET_SIZE = 128;
export interface DisplayInfo { x; y; width; height; workArea: {...} }
export function clampRect(rect: Rect, displays: DisplayInfo[]): Rect;
export function initialPetRect(displays: DisplayInfo[]): Rect;
```

- **clampRect**：钳到**重叠面积最大**的 display workArea 内；完全不重叠时（窗口飞在两个屏之间）钳到**中心距离最近**的屏
- **initialPetRect**：主屏 workArea 底部居中、底留 40px；**坐标取整**（Electron 43 的 setPosition 拒绝小数像素——踩坑记录，见 §8）
- 单测 8 个：不动/右越界/屏外/跨屏选重叠最多/全屏外选最近/顶越界/初始位置/奇数宽取整

### 3.3 pet-manifest.ts —— 角色包契约校验

**干什么**：renderer 加载角色包时校验 manifest，非法直接 throw（fail-fast）。

```ts
export interface PetManifest {
  frameWidth: number; frameHeight: number; fps: number;
  anchor: { x: number; y: number };
  states: Record<string, { frames: number[]; fps: number; loop: boolean }>;
}
export function parseManifest(raw: unknown): PetManifest;
```

校验项：帧尺寸/fps 正整数、anchor 数值、6 个必需状态都存在、每状态 frames 非空且索引为非负整数、fps 为正、loop 为布尔。单测 5 个（含报错指明缺哪个状态名）。

### 3.4 pet-drag.ts —— 拖动目标计算

**干什么**：拖动时窗口跟随指针但**位置不跳变**——目标窗口位置 = 指针屏幕坐标 − 抓取偏移。

```ts
export interface DragPoint { screenX; screenY; offsetX; offsetY }
export function dragTarget(p: DragPoint): { x: number; y: number };
```

单测 3 个（左上角抓取偏移 0、右下角抓取）。

## 4. 主进程（src/main/）

### 4.1 pet-window.ts —— 桌宠窗口控制器（P1 核心）

**干什么**：创建透明无框 128×128 桌宠窗口，并暴露动作对象供 index.ts 注册 IPC。

```ts
export interface PetWindowController {
  win: BrowserWindow;
  dragMove(p: DragPoint): void;   // 窗口移到 dragTarget 结果（钳制后生效）
  moveBy(dx: number, dy: number): Rect;  // 踱步相对移动，返回钳制后新 bounds
  getBounds(): Rect;
}
export function createPetWindow(onFirstHide: () => void): PetWindowController;
```

**窗口特性**：`transparent + frame:false + resizable:false + skipTaskbar:true + alwaysOnTop:true`（置顶浮窗）；`show:false` + `ready-to-show` 显示（防白屏闪烁）。

**职责明细**：
1. **拖动**：`dragMove` 计算目标 → 钳制 → `setPosition`（全部经 `setPositionPx` 取整）
2. **位置记忆**：隐藏时写 `userData/pet-window.json`（`{x, y}`），下次启动恢复；损坏文件忽略回默认位置
3. **多屏钳制**：`display-added/removed/metrics-changed` 事件时钳回可见区域（显示器热插拔不丢宠）
4. **托盘生命周期**：`close` = 隐藏到托盘（`isQuitRequested()` 置位时才真正放行），首次隐藏触发 toast 提示
5. **reduced motion**：不在主进程处理——electron 43 已移除 `nativeTheme.shouldUseReducedMotion`，改由 renderer `matchMedia` 原生读取（见 §8 踩坑）

**为什么不直接给 renderer 一个窗口句柄**：IPC 只暴露薄动作方法，renderer 无法越权（不能改窗口 flag、不能直接 quit）。

### 4.2 index.ts —— 入口与 IPC 注册

**干什么**：进程生命周期（单实例锁、window-all-closed no-op）+ 全部 IPC channel 注册。

| Channel | 方向 | 载荷 → 返回 | 消费方 |
|---|---|---|---|
| `pet:drag-move` | invoke | DragPoint → void | renderer 拖动 |
| `pet:move-by` | invoke | (dx, dy) → Rect | renderer 踱步 |
| `pet:get-bounds` | invoke | → Rect | renderer 踱步边界检测 |
| `pet:toast` | send | string | 首次隐藏提示 |
| `assistant:turn` | invoke | {text} + AbortSignal → TurnResult | 旧对话流（P2 复用） |

- `petController` 在 `whenReady` 后创建，IPC 注册期为空则安全 no-op
- `assistant:turn`/proxy 保留不删：P2 语音 turn 直接复用

### 4.3 保留模块

- **tray.ts**：托盘图标/菜单（显示/退出）、`isQuitRequested` 标志——桌宠与旧小窗共用，未改
- **assistant-proxy.ts**：`assistant:turn` IPC → fetch 本地 gateway API——P2 语音语义复用
- **window.ts**（旧 380×600 文本窗）：已无引用，**P2 后删除**（演进替换决策：不并排维护两套窗口）

## 5. Preload 桥（src/preload/index.ts）

**干什么**：sandbox 化 renderer 访问主进程的唯一通道（contextBridge，无 Node 能力）。

```ts
window.desktopPet = {
  onHidden(cb: () => void): () => void,       // 订阅 pet:toast（首次隐藏提示）
  dragMove(p: DragPoint): Promise<void>,       // 见 4.1
  moveBy(dx: number, dy: number): Promise<Rect>,
  getBounds(): Promise<Rect>,
};
// window.desktopAssistant 保留（P2 语音复用），类型声明随文件全局可见
```

**设计要点**：所有 `on*` 返回退订函数（cleanup 友好）；类型经 `declare global` 全 project 可见（renderer 直接用 `window.desktopPet`，无需额外 d.ts）。

## 6. 渲染层（src/renderer/src/）

### 6.1 pet-sprite.ts —— 帧渲染器

**干什么**：按 manifest 状态帧序列在 canvas 绘制当前帧，每状态按自身 fps 推进。

```ts
export function safeFrameIndex(frame: number, totalFrames: number): number;
export function nextFrameIndex(current, frameIndex, frames, loop): number;
export class PetSprite {
  constructor(canvas, manifest, sheetUrl);
  draw(state: string, timeMs: number): void;
}
```

- **nearest-neighbor + 整数倍缩放**（`Math.round(devicePixelRatio)`）：像素风不糊
- **帧推进语义**：`nextFrameIndex` 支持大步数跳进（后台标签页回来不欠帧）；loop 越界回卷 0，非 loop 钳最后一帧——单测锁死
- `safeFrameIndex` 兜底 manifest 与 sheet 失配
- **素材加载**：vite 资源导入（`import sheetUrl from '../../../assets/pet/sprite-sheet.png'`）而非 fetch——CSP `connect-src 'none'` 拦运行时请求（见 §8 踩坑）

### 6.2 pet-demo.ts —— 演示时序

**干什么**：P1 的假交互流——idle 点击后 listen(800ms) → think(1s) → speak(1.5s) → success(600ms) → idle。

```ts
export function runDemo(emit: (event: PetEvent) => void,
                        getState: () => PetState): () => void;
```

- 每步先核对当前状态仍是目标（用户 cancel 后跳过后续事件，不产生错误迁移）
- 返回取消函数；**P2 接真实语音事件流时整体替换此模块**，状态机/渲染层不动

### 6.3 App.tsx —— 交互编排（桌宠主组件）

**干什么**：把状态机、渲染、窗口 IPC、系统设置接成完整交互。职责明细：

| 职责 | 实现要点 |
|---|---|
| 状态持有 | `useState<PetState>`，`emit(event)` 经 `transition` 推进；`stateRef` 供 demo 时序读取最新状态 |
| 点击 | idle 点击 → `pet_click` + 启动 demo；交互中点击 → `cancel` 立即回 idle |
| 拖动 | pointer events + **>6px 判定**（防点击误判拖动）；`setPointerCapture` 保证拖出窗外不丢事件；拖动中打断踱步 |
| 踱步 | idle 15~30s 随机延迟后 ≤3 步 × 20px（≤60px/轮），`moveBy` 钳制后位置未变 = 碰边界停住；`walking` flag 只改渲染帧序列 |
| 踱步防重 | effect 依赖含 `walking` 且首行 `if (walking) return`——踱步期间不再调度新计时器（避免双循环对撞） |
| reduced motion | `matchMedia('(prefers-reduced-motion: reduce)')` + change 监听；开启时不调度踱步、立即停当前踱步 |
| 动画循环 | 单 rAF 循环驱动 `sprite.draw(renderState, t)`；walking && idle → 'walk' 帧序列 |

### 6.4 其余

- **styles.css**：`html/body` 透明、`#root` 128×128、canvas `cursor: grab/grabbing` + `touch-action: none`
- **env.d.ts**：`/// <reference types="vite/client" />`（*.png 资源导入类型）
- **main.tsx**：标准 React 19 createRoot（未改）

## 8. 踩坑记录（Electron 43 实测）

1. **拒绝小数像素坐标**：`setPosition(789.5, …)` 抛 `Error processing argument at index 0, conversion failure`。奇数宽 workArea 居中公式产生小数 → 所有 setPosition 统一 `Math.round`（`setPositionPx`），`initialPetRect` 内也取整
2. **nativeTheme.shouldUseReducedMotion 已移除**：electron 43 d.ts 无此 API → 改用 renderer `matchMedia('(prefers-reduced-motion: reduce)')`（Chromium 原生读 OS 设置，跨平台，免 IPC）
3. **BrowserWindow 显式传 `x/y: undefined` 也报参数转换失败**：有存档才条件展开 `...(saved ? { x, y } : {})`
4. **CSP 拦 fetch + 拦 data URI**：index.html `connect-src 'none'` 拦 `fetch(manifest)`；vite 默认把 <4KB 资源（513B PNG）内联成 data URI，又被 `img-src 'self'` 拦 → 角色包走 vite 资源导入 + `renderer.build.assetsInlineLimit: 0` 强制输出文件

## 9. 演进路线（P2–P5）

| 阶段 | 改动面 | 不动 |
|---|---|---|
| P2 语音 | pet-demo.ts 替换为真实 VAD/ASR/TTS 事件流；preload 增语音通道 | 状态机、shared、pet-window |
| P3 gateway 身份 | OAuth + deep link；assistant-proxy 升级 | 窗口、渲染 |
| P4 web handoff | renderer 增交接 UI/URL | 窗口、状态机 |
| P5 双平台打包 | electron-builder 双目标；真实素材换 assets/pet/ | 全部逻辑 |

**替换真实素材**：生成脚本退役，`assets/pet/` 两文件换成美术产出的 sheet + manifest（满足 §2.1 契约），渲染层零改动。
