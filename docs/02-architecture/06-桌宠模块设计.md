- 状态：`accepted`
- 最后验证时间：2026-08-13
- 当前实现基线：`apps/desktop`
- 关键决策：[ADR-0028](../09-decisions/0028-桌宠作为统一EduCanvas系统的第一方桌面外延.md)
- 产品需求：[桌宠第一方桌面外延项目需求](../01-product/04-桌宠第一方桌面外延需求.md)
- 执行计划：[DP 桌宠统一桌面外延](../plan/active/DP-桌宠统一桌面外延.md)
- 质量基线：[DP00 桌宠事实与回归基线](../06-quality/15-DP00桌宠事实与回归基线.md)

本文描述当前代码事实和已经接受的演进边界。P1-P3 的逐步实现过程保留在
`docs/superpowers/` 历史材料中，不再作为当前模块契约。

## 1. 系统定位

桌宠是统一 EduCanvas 系统的能力受限第一方桌面外延，不是独立 Agent，也不是 Web 的本地
复制品：

```text
Pet/Chat Renderer
  → 受限 contextBridge
  → Electron Main
  ├→ Gateway Client → gateway.v1 → 唯一 Agent Runtime
  ├→ Voice Proxy → Web Voice BFF → Model Gateway
  ├→ 系统浏览器 PKCE / deep link
  └→ 窗口、托盘、麦克风权限与操作系统保护存储
```

- 服务端拥有 User、Agent、Notebook、Conversation、Message、Turn、Operation、Memory、
  RAG、Tools、Citation、Artifact 和 CanvasResource 的业务事实；
- Electron main 拥有凭据、窗口、IPC、录音代理和跨窗口协调；
- renderer 只拥有输入草稿、瞬时视觉状态、播放状态和可重建 View Cache 投影；
- Web 继续承担 Sources、Studio、Canvas、Slides、思维导图和 Artifact 编辑等富 Renderer。

## 2. 当前目录职责

```text
apps/desktop/
├─ assets/
│  ├─ pet/                 角色语义状态素材
│  └─ icon.*               托盘与打包图标
├─ src/
│  ├─ main/                Electron 权限、窗口、身份和网络代理
│  ├─ preload/             contextBridge 最小 IPC API
│  ├─ renderer/src/        React 角色、聊天与语音交互
│  └─ shared/              main/renderer 共用的纯类型和纯函数
├─ tests/                  不启动真实 Electron 的确定性测试
├─ electron-builder.yml    当前 Windows portable 打包基线
└─ electron.vite.config.ts main/preload/renderer 构建入口
```

依赖方向固定为：

```text
renderer → preload 暴露的类型化动作
main → gateway-client / gateway-core / Electron
main + renderer → shared
shared ↛ Electron / React / Node I/O
```

renderer 不导入 main，desktop 不导入 `apps/web` 内部模块；语音经过公开 Web BFF HTTP 契约，
不是源码反向依赖。

## 3. Electron main

### 3.1 `index.ts`：组合根与 IPC 信任边界

`index.ts` 负责：

- 单实例、`educanvas://` 注册和 deep link 分发；
- 创建桌宠窗口、独立聊天窗口和托盘；
- 装配桌面身份、Gateway assistant proxy、voice proxy、View Cache、operation lease 和 abort registry；
- 只允许桌宠/聊天窗口的受信 `webContents` 调用特权 IPC；
- 校验 requestId、lease token、文本/音频大小和 operation owner；
- renderer 销毁时取消其请求并释放 lease；
- 只允许受信 renderer 主 frame 申请音频媒体权限。

打包应用入口固定为本地 renderer 文件。开发时仅允许 loopback Vite URL；桌宠窗口和聊天窗口
都拒绝新窗口及非受信顶层导航，远端页面不能继承 preload 权限。

### 3.2 `pet-window.ts`：桌宠窗口

当前桌宠窗口是固定内容尺寸的透明、无框、不可缩放、跳过任务栏、适度置顶窗口：

- 首次位于主显示器右下安全区域；
- 保存左上角位置，恢复时基于真实宠物可见区域判断是否仍可抓取；
- 用户正常拖动可以跨显示器，不被单一屏幕 work area 锁死；
- 显示器移除或 metrics 变化时，只在宠物不可抓取时恢复到可见区域；
- 普通关闭隐藏到托盘，明确退出时保存位置并终止；
- renderer `ready-to-show` 后使用透明预热显示，避免旧背景或错误尺寸闪烁。

桌宠默认不会自行踱步或在用户未操作时移动。视觉变化只能表达真实登录、Voice 或 Operation
状态，不能改变窗口位置。

### 3.3 `pet-mouse-tracker.ts`：透明区域穿透

Electron 透明窗口仍有矩形命中区。main 按鼠标屏幕坐标和窗口 bounds 计算：

- 对话框展开时，对话框和宠物可见区域接收输入；
- 对话框折叠时，宠物与展开按钮接收输入；
- 其他透明区域调用 `setIgnoreMouseEvents` 穿透到桌面或其他应用；
- 窗口隐藏时停止轮询，显示时恢复，避免托盘后台持续唤醒。

透明命中矩形必须与 `petVisibleRect`、布局 CSS 和显示器恢复逻辑保持同一坐标定义。

### 3.4 `chat-window.ts`：独立聊天窗口

独立聊天窗口是可调整大小的普通窗口，复用同一 renderer，通过 `view=chat` 选择密集聊天
投影。它与小窗共享 main 内的历史快照、视觉广播和 operation lease，不建立第二份身份或
Agent 会话。

当前两个窗口共享的是进程内 View Cache；DP03 将其改为按 Conversation 分区、可从服务端
canonical Message 重建的缓存。

### 3.5 身份与保护存储

`desktop-auth-service.ts`、`native-auth.ts` 和 `desktop-session-store.ts` 实现：

- 系统浏览器 PKCE S256；
- deep link 回跳只携带一次性 code/state；
- token exchange 有时限和登录/退出 generation，旧交换不能复活已退出凭据；
- bearer 由 Electron `safeStorage` 加密并原子写盘；
- renderer 只收到 signed-in/out/error 状态；
- `401`、撤销、过期或无法解密时清理本地 Session；
- 退出先清本地凭据，再以有界时间尝试远端撤销。

当前 Session 还包含固定 `notebookId/conversationId`。这是 DP01 要迁移的旧路由绑定，不是
ADR-0028 接受后的长期授权模型。

### 3.6 Assistant 与 Voice 代理

`assistant-proxy.ts` 使用桌面 bearer 和 `GatewayClient` 提交 Turn、消费 NDJSON 事件并协作式
取消远端 Operation。当前代理只拼接 `message.delta`，到 completed 后返回最终字符串；它没有
向 renderer 推送真实增量，也忽略 Citation、Artifact 和工具状态。这些缺口由 DP04-DP07
处理。

`voice-proxy.ts` 使用同一桌面 bearer 调用 Web Voice BFF：

- ASR 上传有界音频字节并只返回 canonical transcript 投影；
- TTS 请求有界文本，响应使用流式字节上限读取；
- 超时、用户取消、`401`、网络和响应错误归一化；
- Provider Key、模型配置和原始响应止于服务端。

当前语音流程先把 transcript 写进本地历史，再提交 Turn；DP09 将改为由服务端 canonical User
Message 回填，并把 TTS 明确绑定 Assistant messageId。

### 3.7 Operation 与 View Cache

`operation-lease.ts` 防止小窗和大窗同时发起前台操作；lease 由 main 按 sender/token 强制校验。
`ipc-abort-registry.ts` 按 owner 管理 ASR、Turn 和 TTS 取消，renderer 销毁时清理。

`chat-history-store.ts` 当前是进程内数组，给小窗和大窗分发 revision snapshot。它不是持久化
数据库，但仍自行生成消息 ID 和时间且应用重启后为空，只能视为过渡 View Cache。DP03 会把
服务端 Message 作为唯一事实并增加分页、Conversation 分区、乐观消息去重和缓存重建。

## 4. Preload API

`src/preload/index.ts` 只暴露受限领域动作：

| 命名空间           | 当前能力                                   |
| ------------------ | ------------------------------------------ |
| `desktopAuth`      | 查询状态、登录、退出、订阅状态             |
| `desktopAssistant` | 发起 Turn、取消、订阅低敏提示              |
| `desktopVoice`     | ASR、TTS、取消                             |
| `desktopChat`      | 读取/追加当前 View Cache、订阅 revision    |
| `desktopOperation` | 获取/释放跨窗口 lease                      |
| `desktopPet`       | 隐藏、折叠布局、打开聊天窗口、广播视觉状态 |

preload 不暴露 bearer、任意 fetch、Shell、文件系统、窗口对象或 Electron 原始 IPC。DP01-DP09
扩展时继续使用窄类型化动作，不能把 `GatewayClient` 或通用 IPC 直接交给 renderer。

## 5. Renderer

### 5.1 `App.tsx`：交互编排

当前 `App` 同时支持宠物小窗和独立聊天窗口：

- 管理输入草稿、聊天折叠、业务状态、视觉状态和历史 snapshot；
- 登录后获取 main operation lease，再发起文本或语音流程；
- 请求期间提供 Stop，并在 effect cleanup 中取消本窗口拥有的操作；
- 小窗/大窗订阅共享历史和视觉广播；
- 短暂视觉状态约三秒后回 idle；listening/speaking 随真实阶段持续；
- success 只映射登录成功或服务端明确的 `assessment_correct`，普通回答完成不庆祝。

本地 `state` 是控制当前窗口按钮的 UI 状态；跨窗口视觉广播只改变角色表现，不能替代 main
operation owner 或服务端 Operation 终态。

### 5.2 `pet-chat-panel.tsx`：聊天投影

- 历史和运行状态使用不同无障碍区域，listening/thinking 等文案不进入 `role=log`；
- Enter 发送、Shift+Enter 换行，输入有最大长度；
- 提供麦克风、朗读最新回复、Stop、折叠、放大和隐藏入口；
- 独立窗口依赖原生 resize，历史区域滚动。

当前只渲染纯文本消息。DP02-DP08 将增加 Conversation 选择、canonical 分页历史、真实增量、
Citation/Artifact 卡和用户点击式 handoff，但不复制 Web 的 Sources/Studio/Canvas 编辑器。

### 5.3 角色视觉

`pet-view.tsx` 将语义视觉映射到用户提供的 PNG：

- `idle`：待机；
- `greeting`：启动问候；
- `listening`：语音输入；
- `thinking`：Turn 处理；
- `speaking`：TTS 播放；
- `celebrating`：登录成功或答题成功；
- `login-failed`、`backend-offline`、`confused`：稳定错误投影。

现有素材和角色不会因 DP 迁移被删除或重画。未来 APNG、PNG 序列或 sprite sheet 必须通过
新的版本化 manifest 映射相同语义状态，不能把文件名写进业务状态机。

## 6. 当前数据流

### 6.1 文本

```text
Renderer 输入
→ 获取 main operation lease
→ 本地 View Cache 追加 User Message
→ assistant:turn IPC
→ GatewayClient.streamTurn
→ main 聚合 message.delta
→ completed 后返回最终字符串
→ main 追加 Assistant Message 并广播历史
```

DP03-DP05 将移除“本地正式追加”和“最终字符串才返回”两个过渡行为，改为 canonical Message
分页和真实事件投影。

### 6.2 语音

```text
用户点击麦克风
→ MediaRecorder + VAD
→ voice:transcribe
→ transcript 本地显示
→ 同一 assistant:turn
→ 最终文本
→ voice:synthesize
→ 本地音频播放
```

TTS 失败保留文字结果；取消会中止当前阶段和远端 Operation。DP09 将 transcript、Assistant
Message 和 TTS 绑定到服务端 canonical ID。

## 7. 本地持久化边界

当前允许落盘：

- 加密桌面 Session；
- 桌宠窗口位置；
- 打包应用资源。

当前聊天历史没有落盘。未来可以增加可删除 View Cache，但不能增加本地 Conversation、
Message、Artifact、Memory、RAG、Prompt 或学习事实数据库。

## 8. 测试与构建

DP00 基线：

- Desktop 36 个测试文件、167 个用例；
- Desktop TypeScript 和 electron-vite production build；
- Gateway Core 25 个、Gateway Client 14 个契约用例；
- CI 的 `desktop-build` lane 执行 test、typecheck、build，并检查 main/preload/renderer 产物。

当前测试主要是纯函数、源码边界和代理契约，不等于真实 Electron/Windows/macOS 验收。Windows
打包、多屏、缩放、休眠、协议、真实语音和性能由 DP11 验收；macOS 由 DP12 验收。

## 9. DP 演进边界

| 任务      | 模块变化                         | 不得改变                                 |
| --------- | -------------------------------- | ---------------------------------------- |
| DP01      | Session 身份与初始游标解耦       | PKCE、保护存储、撤销和 renderer 无 Token |
| DP02      | Conversation 目录、切换、新建    | 服务端权限重验与单 Agent                 |
| DP03      | canonical 历史与 View Cache      | 本地无业务数据库                         |
| DP04-DP05 | 稳定请求身份、resume、真实事件流 | Operation 单终态与跨窗口 owner           |
| DP06-DP07 | capability 与结构化结果卡        | 不复制 Web 富 Renderer                   |
| DP08      | 用户点击式精确 handoff           | 不自动弹浏览器、不重复 Tool              |
| DP09      | Voice 与 canonical Message 对齐  | 显式录音、TTS 不重做 Agent               |
| DP10      | 图片/PDF Asset 输入              | 不直传 Provider、不越权引用              |
| DP11-DP12 | Windows/macOS 打包验收           | 平台差异不进入业务契约                   |

现有桌宠是所有任务的回归基线。任何纵切都必须保持角色素材、拖动、透明穿透、折叠/放大、
登录、文本、语音、TTS 和托盘主流程，除非另有明确产品决策。
