## 三、ADR-0024 与 ADR-0028 差异审计

### 3.1 ADR-0028 已继承的有效约束

- Electron + React 和 2D 可替换角色资产；
- 桌宠独立于浏览器，保留透明窗口、拖动、托盘和多屏恢复；
- 系统浏览器 PKCE、一次性回跳、保护存储、会话撤销和 `401` 清理；
- 唯一 Agent Runtime，不建设第二 Agent、RAG、Memory、Tools 或消息账本；
- 明确点击录音，不做持续监听、唤醒词和后台静默录音；
- Provider Secret 不进入桌面端；
- 复杂 Canvas/Artifact Renderer 保留 Web，并通过受控 handoff 衔接；
- Windows 与 macOS 最终支持同一业务契约。

### 3.2 ADR-0028 明确替换的旧限制

| ADR-0024                        | ADR-0028 提案                                          | 决策原因                                     |
| ------------------------------- | ------------------------------------------------------ | -------------------------------------------- |
| 登录后固定绑定一个 Conversation | 身份与 Conversation 游标解耦，可目录读取、切换和新建   | 固定绑定无法形成真正跨端统一产品             |
| 桌宠不渲染完整聊天历史          | 桌宠分页投影完整 canonical 历史，但不复制 Web 富工作面 | 用户已要求可滚动查看历史；服务端仍是唯一权威 |
| 复杂结果完成后自动打开 Web      | 显示结果卡，由用户点击后打开                           | 避免突然弹浏览器，保留用户控制               |
| macOS 首要开发和验收            | Windows 当前先开发/验收，随后补 macOS 同流程           | 与当前开发设备、打包配置和现有证据一致       |
| idle 时允许偶尔移动             | 默认不自行移动，视觉只表达交互状态                     | 用户已明确要求不点击时保持不动               |
| 短气泡为主，不扩成聊天客户端    | 提供轻量完整聊天投影和独立窗口                         | 不复制后端和富 Renderer，仍保持轻量边界      |

### 3.3 接受结论

审计结论为 **接受 ADR-0028**：新决策完整包含旧决策仍有效的安全与架构边界，替换项均有
明确产品决定、迁移任务和验收条件，没有要求推倒重写当前 MVP。项目负责人于 2026-08-13
明确确认接受，并已按一次原子文档变更完成：

4. 将现有 canonical 文档中的 ADR-0024 链接切到 0028；
5. 旧 `docs/superpowers/` 计划作为历史执行材料保留，不重写其中当时的引用；
