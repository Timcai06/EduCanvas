# CA08B 消息账本受控切读证据

- 范围：K12 可见消息的 provenance、全量 parity、受控读源与显式回退
- 不包含：`chat_messages`、引用、lease、cancel、heartbeat 的退役或删除
- 接受边界：本文记录本地工程证据，不替代 reviewer 的最终 PASS

## 权威与回退

`EDUCANVAS_K12_CONVERSATION_AUTHORITY_STAGE` 是唯一可见读源配置，严格接受
`legacy|observe|platform`，默认 `legacy`。Web 组合根在进程启动时冻结它：

| stage      | 可见字段                             | 教学运行态      | 新副本                   |
| ---------- | ------------------------------------ | --------------- | ------------------------ |
| `legacy`   | `chat_messages`                      | `chat_messages` | 服从 dual-write 观察开关 |
| `observe`  | `chat_messages`                      | `chat_messages` | 服从 dual-write 观察开关 |
| `platform` | 经全量对账的 `conversation_messages` | `chat_messages` | 强制建立                 |

非法值只产生稳定配置错误，不回显配置原值。回退必须显式设置
`authority=legacy`、`dual-write=false` 并重启；不会删除或改写两侧历史。

## Provenance 与 readiness

Migration `0057_faulty_corsair.sql` 新增窄 sidecar
`k12_conversation_message_projections`，冻结 source chat ID、确定性 platform ID、
session 与 conversation。表刻意没有级联外键：删除任一消息不能抹掉缺失或 orphan 证据；
匿名主体生命周期在删除消息前显式删除其 sidecar。

新 begin、settle 与受信 operator backfill 都在原事务内插入或验证映射。历史 K12
platform ID 从最初实现起使用 SHA-256 派生 UUID v8；其他生产写入者省略 ID，使用数据库
UUID v4。因此目标 conversation 内所有 v8 行都是 fail-closed K12 candidate：无 sidecar、
source/platform 缺失、确定性 ID、session 或 conversation 作用域漂移均计入 orphan。
未来非 K12 写入者若显式使用 v8，只会安全地阻断切读，不能伪造 readiness。

只有从首游标到 EOF 的单个 repeatable-read 快照满足以下条件才可得到
`readCutoverEligible=true`：存在 K12 session，missing=0、mismatch=0、orphan=0。
单页、空 conversation 或 `orphanDetection=unavailable` 都不能获得资格。

## Platform 读取兼容

Platform stage 先按 trusted student + session + conversation owner 鉴权，再在同一
repeatable-read 快照完成全 conversation shadow comparison。任何差异整页抛稳定
`k12_message_projection_inconsistent`；不逐行混合、不自动 fallback、不返回正文或底层错误。

可见 status/content/parts/failure/timestamps 来自 platform；公开 message ID、turn、
clientMessageId、分页排序键及 citation 关联继续使用 legacy 身份；lease、heartbeat、取消与
恢复字段继续来自 legacy。页面历史与模型 recent-history 使用同一 adapter。

## 本地验证（Node 24.18.0）

- DB unit：13 files / 118 tests；
- Web focused unit：2 files / 8 tests；env gate：24/24；
- PostgreSQL cutover/backfill/parity：2 files / 41 tests；
- PostgreSQL anonymous lifecycle：1 file / 5 tests；
- fresh/N-1 migration：以最终候选门禁结果为准；
- DB/Web typecheck、Prettier 与 `git diff --check`：提交前通过。

首次 PostgreSQL 组合运行为 38/39：无外键 sidecar 未纳入既有 suite 的 truncate，产生跨
用例残留 orphan；补齐显式清理后同一矩阵 39/39，随后扩展 fault/citation/rollback 用例为
41/41。该修正只改变测试隔离，不降低 orphan 检测。

## 保留边界

- 不删除 `chat_messages`、`message_citations` 或任何教学运行态；
- 不注册可由普通 Worker payload 触发的 apply backfill；
- 不创建第二套 Agent loop、Message domain 或 Gateway authority；
- 真实生产规模、发布观察窗口与最终切换批准仍由 reviewer/运维负责。
