## 1. 证据边界

本记录不能把 fixture、虚拟时钟、合成音频或单元测试解释成真人麦克风证据。
本轮已经证明协议、配额、隔离和稳定失败语义；尚未证明真实课堂声学条件下的产品质量。

运行环境为 macOS 26.5.2（arm64）、Node.js 24.18.0。仓库要求 Node.js
`>=22 <23`，因此 Node 版本差异作为环境限制保留，不改写为代码通过条件。

## 3. 已有 Voice Lab 证据

`tooling/voice-lab/evidence/` 保存了 2026-08-04 至 2026-08-05 的受控实验摘要。
其中 V02-U 为 `BLOCKED_MODEL`、V02-W 为 `BLOCKED_MODEL_OR_PROVIDER`、V02-X 为
`REVIEW_REQUIRED`。这些结果可证明实验诚实记录和候选模型边界，不能证明 U20 的
真人麦克风、课堂噪声或十分钟连续产品会话已经通过。

## 4. 项目负责人最小真人验收

在把 U20 标为 PASS 前，负责人需要在目标浏览器完成一次连续记录：

1. 选择 `general` 或 `restricted` 模式，确认能力状态与产品文案一致；
2. 用真实麦克风完成普通话短句、包含课程术语的短句和一段可重复课堂噪声样本；
3. 连续运行 10 分钟，期间记录 partial/final、终态、断开、重连和取消结果；
4. 用受控并发会话验证配额拒绝不会影响已建立会话；
5. 若启用音频留存，验证撤回/到期后数据库状态、对象删除与 Outbox 回执；若仅用
   `restricted` 瞬时模式，明确记录未创建留存事实；
6. 检查浏览器、Gateway、Worker 日志，不得出现 Secret、PCM、原始 Provider 响应或学生数据。

记录至少包含：机器与系统、浏览器版本、模式、模型/Provider 配置别名、开始/结束时间、
输入场景、最终文本、错误码、CPU/内存峰值、并发数、删除回执和已知限制。音频本体不提交仓库。

## 5. 判定规则

- 自动化门禁通过且第 4 节真人记录完成：U20 可判 `PASS`；
- 自动化通过但真人记录缺失：保持 `HUMAN_EVIDENCE_REQUIRED`，不得归档 UV；
- 真人验收发现功能缺陷：另开单一职责修复，修复后重跑受影响证据；
- 若项目负责人决定竞赛阶段不要求此真人门禁，必须先显式修改 U20 的验收范围，
  将其列为非阻塞后续，而不能直接把现有 fixture 改称真实证据。
