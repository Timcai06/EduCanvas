## 二、事实源与身份矩阵

| 维度            | 权威事实                                      | 当前公共投影                                                                   | RM 必须保持的边界                                          |
| --------------- | --------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Source          | Asset 与不可变 Asset Version                  | `resourceKind=source`、`resourceId=assetId`、`versionId`、`sequence=null`      | 原件、派生表示和启停绑定不合并成新聚合根                   |
| Artifact        | Artifact 与不可变 Artifact Version            | `resourceKind=artifact`、`resourceId=artifactId`、`versionId`、数字 `sequence` | 生成、编辑、修订和恢复继续产生不可变版本                   |
| Context Binding | 当前主体与 Asset 的最大 binding sequence      | Source 列表的成员私有 `enabled`                                                | 只适用于 Source；Dock 可见或 Artifact 打开不等于进入上下文 |
| SurfacePosition | `(spaceId, subjectId, kind, id)` 私人空间记忆 | `zone/x/y/z/restState/updatedAt`                                               | 不作为资源存在、版本、权限或 context 的事实源              |
| Allowed actions | 服务端 CanvasResource 投影                    | Renderer 只能消费服务端动作交集                                                | 客户端不得按角色名或类型推断权限；执行时仍重新鉴权         |
| Provenance      | 实际物化的 Source 与版本引用                  | 有限 `sourceResourceIds/sourceReferences`                                      | 只导航和审计，不授予 Source 读取权限                       |

Source 当前状态映射为 `pending|processing → processing`、`ready → ready`、`failed → failed`、
`tombstoned → unavailable`。正常列表和详情排除 tombstone，因此公开读取通常是同形 404。

Artifact 当前按 archive、latest job 和不可变 version 组合状态：queued/running 为 processing，
failed/cancelled 为 failed，未知 job 或无 version 为 unavailable，有 version 且无阻断为 ready。
`latestVersion` 与实际 version 不一致时投影 fail closed。

## 三、Renderer 与动作事实

Source MIME 到 Renderer 的答案由 `packages/canvas-protocol/src/source-resource-projection.ts`
持有；Artifact kind 到 Renderer、信任层和 Runtime 的答案由相邻 Artifact 投影持有。Web
Registry manifest 必须覆盖资源投影的全部 `allowedActions`，否则打开门禁返回
`action_not_supported`，不能由资源库绕过。

| 资源                 | ready 基础动作                                   | owner/editor 额外动作        | 当前特殊边界                              |
| -------------------- | ------------------------------------------------ | ---------------------------- | ----------------------------------------- |
| Source               | `view, annotate`；PDF/图片/音视频另有 `download` | `rename, delete`             | Markdown/TXT/DOCX 投影当前不授予 download |
| 结构化 Artifact      | `view, annotate`                                 | 依 kind 增加 edit/regenerate | 无 version 时无动作                       |
| Markdown 文档        | `view, download`                                 | `edit, regenerate`           | canonical Markdown 仍是版本内容           |
| Web App              | `view, run, cancel, annotate`                    | `regenerate, download`       | 继续进入隔离 Runtime，不进入主页面信任域  |
| 处理中/归档 Artifact | 有 version 时最多 `view`                         | 无客户端推断                 | failed/unavailable 为空动作               |

已冻结一处现有漂移：DOCX Source 投影标记 `downloadable=false`，但原件阅读组件始终显示下载
入口。RM06 必须让服务端动作与实际受控下载能力一致，不能在资源库复制第三套判断。

## 四、当前消费者与调用链

### 4.1 Source 与 Artifact 列表

- `GET /api/v1/chat/assets` 返回 Source 元数据、成员私有 enabled、批量 CanvasResource 和
  `page.nextCursor`。
- `GET /api/v1/chat/artifacts` 返回 Artifact 摘要和 `page.nextCursor`，但不含 versionId、job、
  Renderer、allowedActions 或 provenance；逐条详情补全会形成 N+1。
- `GET /api/v1/canvas/resources/{kind}/{id}` 是打开前统一授权门禁；正文、媒体和 Artifact
  detail 仍由既有端点按需读取。
- `use-studio-open-actions`、Workspace Canvas 和 Live 预览都消费同一打开门禁，不应新增第二套
  资源客户端或 Renderer Registry。

### 4.2 Composer 与 Artifact 生成

当前存在两条产品编排：

1. `PlusMenu create_* → confirm → POST /api/v1/chat/artifacts → poll`；
2. `outputPreference → Agent Turn → Canvas Artifact Tool → artifact.proposed → existing job/version`。

第二条是 RM 目标主链。直接 Artifact API 仍保留给 Studio/Canvas 空白新建、手动保存、修订、
恢复和受控资源操作，但 Composer 不应借它创建第二个智能生成任务。

当前还有四个 pending session key，其中 `canvasSelected` 与 `outputPreference !== auto` 重复表达
输出意图。Landing 先排 pending prompt 的发送 microtask，再排输出偏好恢复，首轮可能以初始
`auto` 提交。Artifact proposed 又只清一侧状态，能形成短暂漂移。

### 4.3 Turn 与 Live 上下文

普通 Turn 在 `use-general-workspace-controller.ts` 内联构造 `asset_ref`。Live 先用
`freezeLiveVoiceContext` 冻结数组，随后仍回到同一 controller 发送。两处过滤规则并不相同：
Live 接受所有 ready kind，而 controller 只发送 image/document。已启用的 link/audio/video
因此可能显示为上下文却被请求静默遗漏。

浏览器只提交 `assetId + versionId`；服务端 materialization 再冻结 representation identity、
quality、producer 和 producerVersion 到 Turn context ledger。RM04 只统一浏览器选择与请求
builder，不把服务端 representation 事实搬到客户端。

## 五、分页、懒加载与 N+1 基线

### 5.1 已成立的正向事实

- Source 和 Artifact Web route 使用 cursor，默认 50、最大 100。
- Source page 一次联查 Asset/Version，按当前页 Asset IDs 批量取 processing job；Notebook
  role 只取一次，CanvasResource 循环是纯投影。
- Artifact metadata list 不读取正文或媒体。
- PDF、DOCX、媒体字节、Artifact detail 和 Web Runtime 只在打开后请求。

### 5.2 已确认缺口

1. `loadAssets` 与 `fetchNotebookArtifacts` 都丢弃 `nextCursor`，Studio 实际静默停在各自前 50。
2. Source 每页仍读取整个 Notebook 的 binding 集合；请求数恒定，但数据量随全库增长。
3. Gateway 的统一 CanvasResource list 固定各取 50，并对每个 Artifact 调
   `getArtifactDetail`，存在明确 `1 + N` fan-out。
4. Web 尚无统一 Source/Artifact 摘要列表；两域分页键分别是 Source createdAt 与 Artifact
   updatedAt，不能简单拼接两页后截断。
5. Surface list 无服务端 limit/cursor，客户端 schema 上限 256；超过后整份解析失败并被 hook
   静默退化为空 Dock。
6. Studio 的 OptionWheel 挂载所有条目并逐帧遍历，不适合 256/500 项资源库。

## 六、Dock、Studio 与 Source 阅读现状

- `DeskRestRail` 只展示非 open SurfacePosition 的前六项，无剩余计数；Source 图标按索引奇偶
  交替，标题为序号，不含真实 Renderer、生命周期、版本、context 或动作。
- 多个陈旧 open position 会同时被 Rail 隐藏，但恢复逻辑只打开第一条 open/pinned。加载和保存
  错误当前均被静默吞掉。
- Studio 一级只有“来源/AI 产物”，无搜索、筛选、排序或分页入口。Artifact `latestVersion=0`
  一律显示“生成中”，无法区分 failed/cancelled。
- Source 阅读已保留 PDF/DOCX 原件与 structured/degraded 切换，图片、Markdown、TXT、音视频
  继续走现有安全 Renderer。
- representation `unavailable` 当前会无提示回原件；processing Source 打开后不轮询资源状态，
  可能永久停在 loading 直到关闭重开。
- Preview 阶段的 forbidden/not_found/offline/unavailable 会被 Renderer 压成通用 failed，已有
  state 联合中的 not_found/offline 没有真实产生路径。
- Live 打开 Artifact 时先取 CanvasResource 再取 detail，却用较早的 resource 覆盖 detail 自带
  的较新投影；两请求间若产生新版本，content 与 resource version 可能不一致。
