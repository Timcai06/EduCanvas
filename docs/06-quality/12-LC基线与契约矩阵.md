## 二、LC00 事实冻结

### 2.1 Live 语音链路事实

#### 2.1.1 message.delta 流式文本增长

**文件与行号：**

- `apps/web/features/chat/turn-state.ts:431-442`

**当前事实：**

- `message.delta` 事件已直接追加到同一条 Assistant 消息
- 普通聊天具备真实流式文本事实源
- 文本通过 `message.text + event.delta` 增量增长

**Gap vs ADR-0025：** 无差距，已实现。

#### 2.1.2 Live 是否存在第二份聊天事实源

**文件与行号：**

- `apps/web/features/voice/voice-composer.tsx` (VoiceComposerRuntime)
- `apps/web/features/voice/playback/use-live-speech-playback.ts`

**当前事实：**

- Live 面板直接消费当前 Assistant 消息的投影（只读 selector）
- 语音层只保存瞬时游标、字幕和播放状态
- 退出后不产生第二份聊天记录

**Gap vs ADR-0025：** 无差距，已实现。

#### 2.1.3 TTS 消费模式：增长文本 vs 整段消费

**文件与行号：**

- `apps/web/features/voice/playback/use-live-speech-playback.ts:279-346`
- `apps/web/features/voice/playback/live-speech-segments.ts:28-70`

**当前事实：**

- TTS 会读取增长中的 `assistantText`
- 维护已消费字符 `consumedCharacters`
- 顺序入 Web Audio 队列
- 首段阈值 10–32 字，后续段 18–72 字
- 未闭合尾句等 Turn 完成才释放

**Gap vs ADR-0025：** 无差距，已实现增长文本消费。

#### 2.1.4 短语是否每段重新建立 HTTP 请求

**文件与行号：**

- `apps/web/features/voice/playback/use-live-speech-playback.ts:401-469`
- `apps/web/app/api/v1/voice/live/speech/route.ts:19-88`

**当前事实：**

- 每个短语仍单独 POST `/api/v1/voice/live/speech`
- 响应 PCM 是流式的
- 短语之间重复建连

**Gap vs ADR-0025：** 无差距。ADR-0025:23-28 要求的是增长文本按语义段增量 TTS、同一 Web Audio 时间轴和插话取消，没有规定长连接/会话级 TTS transport。当前逐短语 HTTP 符合 ADR-0025 的增量分段语义。LC L04 独立选择连续 Session 作为性能优化。

#### 2.1.5 显示、语音提交、播放游标

**文件与行号：**

- `apps/web/features/chat/turn-state.ts:431-442`（`message.text`）
- `apps/web/features/voice/playback/use-live-speech-playback.ts:84-110`（`queueRef`）
- `apps/web/features/voice/playback/pcm-player.ts`（`Pcm16Player`）

**当前事实：**

| 游标类型     | 当前字段             | 实际语义                                                                   | 是否显式存在 |
| ------------ | -------------------- | -------------------------------------------------------------------------- | ------------ |
| 显示游标     | `message.text`       | Turn reducer 中 Assistant 消息的完整文本，是唯一显示事实源                 | ✅ 显式      |
| 语音提交游标 | `consumedCharacters` | 已从增长文本释放给 TTS 队列的原始字符偏移，更接近 speech-committed cursor  | ✅ 显式      |
| 待处理短语   | `queue.queue`        | 已提交但尚未开始 TTS 合成的短语缓冲区                                      | ✅ 显式      |
| 播放时间窗口 | `Pcm16Player`        | Web Audio 时间窗口（startAt/durationSeconds），无文本级 audioPlayed cursor | ⚠️ 仅时间    |
| 失效游标     | `runId`              | 用于失效旧 Session 事件                                                    | ✅ 显式      |

**Gap vs ADR-0025：** **存在差距**。需要引入显式的文本级 `audioPlayedCursor`（当前只有 Web Audio 时间窗口，没有文本偏移）。`consumedCharacters` 是 speech-committed cursor 的近似，但不是显式状态机字段。

#### 2.1.6 插话与取消

**文件与行号：**

- `apps/web/features/voice/playback/use-live-speech-playback.ts:138-165`（`interrupt`）
- `apps/web/features/voice/voice-composer.tsx:252-266`（`handleLiveFinal`）
- `apps/web/features/voice/voice-composer.tsx:305-313`（`cancelPendingSpeech`）

**当前事实：**

- `interruptSpeech`（`speech.interrupt`）只中止 TTS/PCM 播放和清空未播队列
- Agent Turn 取消只在 ASR final 且 `busy` 时由 `onStop` 触发（`voice-composer.tsx:259-262`）
- 部分语音输入时（`live.inputLevel >= 0.08` 且 `partialText.trim().length >= 2`），`cancelPendingSpeech` 只取消待处理的 TTS 短语
- 已显示文字保留

**Gap vs ADR-0025：** **存在差距**。插话未原子取消 Agent operation。当前是 TTS/PCM 先取消，Agent Turn 要等 ASR final 且 busy 时才取消。这是 L06 待实现的竞争问题。

## 三、LC01 契约矩阵

### 3.1 Live 游标契约

| 游标类型     | 当前字段               | 语义                                   | ADR-0025 目标              | 迁移策略                             |
| ------------ | ---------------------- | -------------------------------------- | -------------------------- | ------------------------------------ |
| 显示游标     | `message.text`         | Turn reducer 中 Assistant 消息完整文本 | 显式状态机字段             | 已是唯一显示事实源，无需迁移         |
| 语音提交游标 | `consumedCharacters`   | 已释放给 TTS 队列的字符偏移            | 显式状态机字段             | L02 引入显式 `speechCommittedCursor` |
| 待处理短语   | `queue.queue`          | 已提交但未合成的短语缓冲               | 保留                       | 无需迁移                             |
| 播放游标     | `Pcm16Player` 时间窗口 | Web Audio 时间，无文本偏移             | 文本级 `audioPlayedCursor` | L02 新增文本级游标                   |
| 失效游标     | `runId`                | 失效旧 Session 事件                    | 已存在                     | 无变化                               |

L02 已将上述迁移落地为 `live-speech-cursors.ts` 的纯状态机，并增加
`sessionBaselineCursor` 表达入室前已存在但本次不重播的前缀。三个核心游标仍满足
`0 ≤ audioPlayedCursor ≤ speechCommittedCursor ≤ displayCursor`；baseline 只决定本次
分段扫描起点，不伪造已经提交或播放的进度。语义段保存原文 start/end offset，只有同一
`assistantId + runId` 的 PCM 完成 marker 可以推进 `audioPlayedCursor`。

### 3.3 Artifact Kind/Version 契约

**版本轴字段级定义：**

| 轴字段                             | 存储或投影位置                                      | 当前事实                                                                          | 演进规则                                                                      |
| ---------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `artifact.kind`                    | `artifacts.kind`                                    | `mind_map`、`note`、`slides` 等                                                   | Artifact 身份创建后不可变；新 kind 需在 Tool、Worker 与服务端 projection 注册 |
| `contentVersion` / `schemaVersion` | `artifact_versions.content` JSONB 内                | 类型化内容通常使用 `contentVersion: 1`；`dom_exploration` 使用 `schemaVersion: 1` | 由每个 kind 的严格 schema 所有；服务端 projection 需在投影前验证              |
| `rendererId` / `rendererVersion`   | `CanvasResource.renderer`，由服务端按已知 kind 投影 | 如 `artifact.mind-map@1`                                                          | 服务端映射与浏览器 Registry 必须成对注册；版本变化不得静默覆盖旧 Renderer     |

**未知版本的当前行为：**

| 场景                       | 当前行为                                                | 所有权边界                | 预期行为              |
| -------------------------- | ------------------------------------------------------- | ------------------------- | --------------------- |
| 未知 `artifact.kind`       | 服务端 projection 抛出 `renderer_not_found`             | Artifact projection       | fail closed ✅        |
| 未知内容版本               | 服务端无统一检查；具体 Renderer 的 `safeParse` 可能拒绝 | 各 Renderer               | projection 层显式拒绝 |
| 未注册浏览器 `rendererId`  | Registry 返回 `unavailable / rendererId_not_registered` | Browser Renderer Registry | fail closed ✅        |
| 不匹配的 `rendererVersion` | Registry 返回 `unavailable / rendererVersion_mismatch`  | Browser Renderer Registry | fail closed ✅        |
| 已知 kind 但缺少版本记录   | 服务端 projection 抛出 `resource_invalid`               | Artifact projection       | fail closed ✅        |

**三个代表性纵切冻结：** dotted name 是产品契约名，不代替字段值。

| 产品契约               | `artifact.kind`     | 内容版本字段        | `rendererId@rendererVersion`   | 兼容策略                                                                               |
| ---------------------- | ------------------- | ------------------- | ------------------------------ | -------------------------------------------------------------------------------------- |
| `document.markdown.v1` | `document_markdown` | `contentVersion: 1` | `artifact.document-markdown@1` | 新增 kind；旧 `note`、`NoteRenderer` 与编辑能力继续保留                                |
| `mind_map.v2`          | `mind_map`          | `contentVersion: 2` | `artifact.mind-map@2`          | 保留 `artifact.mind-map@1` 与 v1 schema，历史 Artifact 继续通过 v1 Renderer 回放       |
| `web_app.v1`           | `web_app`           | `schemaVersion: 1`  | `artifact.web-app@1`           | 新增 kind；旧 `dom_exploration` 与 `PersistentWebRuntime` 长期保留，不设置自动删除条件 |

## 七、后续风险

### 7.1 最高风险 Top 3

1. **插话竞争取消不原子**：TTS/PCM 先取消，Agent Turn 要等 ASR final 且 busy 时才取消。L06 需要实现原子取消，但当前是两阶段非原子操作，可能导致旧回答继续生成。

2. **outputPreference 迁移兼容性**：旧客户端只发送 `'canvas'`，新服务端需要保留宽语义 alias。迁移期间需要同时支持旧值和新值，避免破坏现有功能。

3. **mind_map.v1 → v2 迁移风险**：v1 Renderer 只是递归缩进树，v2 需要边布局、视口、折叠等完整交互。历史 v1 Artifact 必须继续渲染，不能静默失效。迁移需要显式版本注册和 fixture 回放。

### 7.2 其他风险

- **dom_exploration → web_app.v1 升级**：当前 Tier 2 Runtime 基础有限，升级需要完整源码 manifest、构建诊断和发布包契约，同时保持旧 `dom_exploration` Artifact 可运行。
- **未锁依赖和超限输出**：当前只有部分检查，需要在 C06 中全面实现 fail closed。
- **性能预算未测量**：所有延迟指标都是 unmeasured，需要在 L08/C08 中通过 fake Provider 和 fixture 测量。
