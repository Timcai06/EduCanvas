## 1. Evidence Boundary

三类证据严格分开，**"当前已实现约束"与"D01 冻结的目标契约"不是同一种证据**：

| 证据类别                | 来源                                                                                                                                         | 本任务如何使用                                                                         | 边界                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **Schema 源码证据**     | `packages/db/src/schema.ts` + `schema/*.ts`（67 表）                                                                                         | 只用于填写 Current enforcement 中的数据库约束（FK/CHECK/UNIQUE/索引）                  | 反映源码定义，不代表目标契约                                        |
| **Migration 证据**      | `packages/db/drizzle/0000–0050` + `_journal.json` + `MIGRATIONS.md`                                                                          | 只用于确认约束来源与触发器（0007 不可变、0049 同意守卫）                               | 迁移链完整不代表生产已应用                                          |
| **代码证据**            | `packages/db/src/*repository*.ts`、`apps/*` 生产调用点、`tooling/`                                                                           | 用于 Writer/Readers/Idempotency/Concurrency/Recovery/Versioning 的 Current enforcement | 无生产调用点 = 无写入者证据，不推断为"有写入者"                     |
| **live 本地数据库证据** | `educanvas-db` 容器（PostgreSQL 16.14）只读 catalog 查询（D00 已实测：表 67 / FK 124 / CHECK 231 / 索引 236 / 迁移 51）                      | 交叉验证 Current enforcement 的约束存在性                                              | 本地开发库；**生产数据库未验证**，生产漂移状态未知（属 D07 范围）   |
| **架构决策证据**        | ADR（0004/0010/0011/0013/0015/0016/0022 等，全部 `accepted`）、R 线台账（R00.7/R05.1 已 PASS）、UV 线 V11/V14 台账、O 线台账（O00-O02 PASS） | 用于冻结 Authority/Retention/Deletion 目标契约的依据                                   | ADR 是契约依据；"ADR 已决定" ≠ "已实现"，实现状态单独以代码证据为准 |

**本任务的所有 Retention/Deletion/Authority 填写项 = D01 冻结的目标契约**；
Current enforcement 列只写实测事实。两者不一致的地方由 Enforcement gap 列显式声明。

### 2.2 Role（事实角色）

| 术语               | 含义                                                       |
| ------------------ | ---------------------------------------------------------- |
| `root_fact`        | 领域根事实，拥有独立生命周期，不依附其他事实存在           |
| `child_fact`       | 从属事实，生命周期绑定父事实                               |
| `fact_stream`      | 追加式变更事实流，当前值 = 同键 sequence 最大行            |
| `execution_ledger` | 执行/事件账本，只追加，供审计与重建                        |
| `projection`       | 可由源事实重算的投影，非独立事实源                         |
| `derivation`       | 由内容事实派生的表示/向量，可重建                          |
| `audit`            | 审计事实，只追加，不可变                                   |
| `queue_ledger`     | 业务任务账本（区别于 Graphile 队列表），记录任务终态与失败 |

### 2.3 Authority

`Authority` 一律填唯一权威表名（如 `chat_messages`），或 `<表1> + <表2>（受控双轨）`。
禁止使用"权威在服务层"这类无表归属的表述——服务层永远只是 Writer。

### 2.4 Mutation（变更模型）

| 术语                | 含义                                                            |
| ------------------- | --------------------------------------------------------------- |
| `immutable_version` | 行创建后不可修改/删除（版本不可变），新内容 = 新行              |
| `append_only`       | 只允许 INSERT，禁止 UPDATE/DELETE（数据库触发器或代码约定强制） |
| `mutable_state`     | 允许状态迁移 UPDATE（生命周期字段），终态后不可改               |
| `soft_delete`       | 状态位软删（archived/revoked/tombstoned），物理行保留           |
| `terminal_state`    | 一次写入终态，之后仅允许状态推进（pending→终态）                |

### 2.5 Retention（保留期）

| 术语             | 含义                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| `bounded:<期限>` | 有明确且可追溯期限（DB CHECK 或 accepted ADR），如 `bounded:7d`、`bounded:12mo`                                    |
| `bounded:expiry` | 行的有效期由 `expiresAt`/`revokedAt` 等字段界定；到期后的物理保留期若无证据则不得擅自量化                          |
| `bounded:parent` | 行随父事实或源版本生命周期保留；父事实删除/退役时按 Deletion 契约处理                                              |
| `indefinite`     | 长期保留；必须同时给出：为什么长期保存、删除触发条件、PII 风险、责任 Domain、归档/匿名化/法律保留要求（见第 7 节） |

### 2.6 Deletion（删除策略）

| 术语              | 含义                                                                |
| ----------------- | ------------------------------------------------------------------- |
| `cascade`         | 随父行数据库级联删除                                                |
| `restrict`        | 数据库阻止父行删除，须显式按顺序清理                                |
| `soft_delete`     | 状态位软删，物理删除另行触发                                        |
| `anonymize`       | 匿名化替代删除（个人可识别字段置空/替换）                           |
| `archive`         | 归档到冷存储后从在线库移除                                          |
| `audit_retention` | 审计/法律保留：不删除，只追加（含 legal hold 要求时）               |
| `derived_rebuild` | 派生物整表可重建/删除，不影响源事实                                 |
| `queue_cleanup`   | 任务账本终态后按已批准的清理策略处理；没有证据时不得在 D01 发明 TTL |

### 2.7 Privacy（隐私分类）

| 术语                  | 含义                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| `pii_none`            | 不含个人数据，且不能通过稳定内部标识关联到个人                                |
| `pii_pseudonymous`    | 不直接含姓名等明文标识，但稳定内部 ID/hash 可经其他表关联到个人，仍受隐私控制 |
| `pii_identifiable`    | 含个人标识（user_id/student_id/主体引用）                                     |
| `pii_minor`           | 含未成年人学习数据（K12 学生主体、学习事实）                                  |
| `pii_sensitive_audio` | 原始音频（未成年人敏感个人信息，ADR-0022）                                    |
| `pii_credential`      | 凭据材料（密码派生/会话 token 哈希/密文）                                     |

### 2.8 其他

- **Owner**：Domain owner = 第 2.1 节的 Domain 名；个人责任人在"Downstream task"中指定。
- **Enforcement gap**：目标契约与 Current enforcement 的差异；不得写"暂无/以后再看"，
  必须给责任 Domain 与后续任务。
- **Downstream task**：只填写计划中确实覆盖该工作的任务编号；否则填写 `待立项（责任域）`，禁止把工作塞入标题相近但范围不符的 D/O 任务。

## 5. D00 Evidence-gap Decisions

对 D00 §8.2 的 10 项证据缺口逐项冻结（当前事实 / 冻结契约 / 责任 Domain / 后续任务 / 退出条件）。

### 5.1 delegated_grants 无生产读写者

- **当前事实**：表结构完备（FK/CHECK/索引），全仓（排除测试）无 repository 写路径、无生产读取者；本地 live 表 0 行。ADR-0001 保留未来教师/监护人受限委托方向；ADR-0022 明确“委托语义不能冒充同意”。
- **Codex 最终裁定**：保留为未来受限委托的休眠 Authority，不退役、不在 D02 接线。当前必须 fail-closed；没有独立批准的委托功能、repository、授权消费方和安全测试前，禁止新增生产读写者。该表永远不得作为音频同意事实。
- **生命周期**：授权有效性由 `expiresAt` / `revokedAt` 界定；行随委托人、受托人或 space 的 FK cascade 删除。当前零行，不发明额外 TTL。
- **责任 Domain**：workspace（事实）+ gateway（未来授权消费边界）。
- **后续任务**：待立项（workspace/gateway），不属于 D02–D05。
- **退出条件**：独立功能任务获得批准并提供端到端授权、撤销、过期和越权拒绝证据；在此之前保持零生产接线。

- **后续任务**：UV V16/V17；不把产品接线塞入 D07。

### 5.5 security_audit_events 无查询服务

### 5.6 大面积 Retention 未定义

- **责任 Domain**：各表 Owner（第 2.1 节）。
- **后续任务**：按矩阵逐域立项；D02–D05 只承接其计划明示范围。
- **退出条件**：每张表有可执行清理/归档路径（含"审计保留需独立批准"的批准流程）。

### 5.7 删除路径覆盖不足

- **后续任务**：D02（本任务 FK 删除行为）；其他闭包逐域待立项；O03/O04 仅按 O 计划范围收口物理对象删除。
- **退出条件**：删除闭包覆盖全部可删除表；Outbox 覆盖全部对象类型。

## 7. Retention and Deletion Contract

八类策略的契约定义与归属表清单（每表的完整行见第 4 节矩阵；此处给策略级契约与
`indefinite` 表的长期保存理由）。

### 7.1 cascade（随父行级联删除）

- **契约**：子行生命周期完全绑定父行；父行删除闭包必须按子→父顺序显式执行，cascade 只是数据库兜底（03-外键索引审计.md 判定 1）。
- **适用**：全部 child_fact/execution_ledger/projection 的随父删除路径（conversation_messages、asset_versions、artifact_versions、model_runs、tool_calls、chat_messages、learning 子表等）。
- **责任**：数据库行删除闭包由各表 Owner；只有外部物理对象删除意图交给 O 线 Outbox。

### 7.2 restrict（证据不被顺手删除）

- **契约**：父行删除被数据库阻止，必须先处理子行（显式顺序）；适用证据类关系（learning_events→lesson_sessions、lesson_sessions→conversations、operation_sources→asset_versions、audio consent/retention 全部外键）。
- **责任**：study/asset/voice 域；删除闭包顺序由 anonymous-data-lifecycle.ts 固化。

### 7.3 soft_delete（软删 + 状态位）

- **契约**：状态位（archived/revoked/tombstoned）软删；物理删除由后续流程触发；archive 形状 CHECK 保证状态与时间戳一致。
- **适用**：spaces、conversations、artifacts、assets（tombstone）、knowledge_sources、gateway 通道/节点绑定、web_sessions（revoke）。
- **责任**：各表 Owner；物理行删除必须由明确批准的域流程触发。

### 7.4 anonymize（匿名化）

- **契约**：个人可识别字段在获批保留期后匿名化而非删除（主体身份引用置空/替换）；当前**仅 learner_profiles 随主体删除走 cascade**，其余表无匿名化路径——属 enforcement gap（责任：identity 域，须独立设计）。
- **适用（目标）**：platform_users、web_user_profiles、匿名主体衍生数据。

### 7.5 archive（归档）

- **契约**：达到已批准的保留期/退役状态后迁移冷存储，在线库移除；当前无通用归档实现。D01 不冻结无来源的年限。
- **适用（目标）**：knowledge 退役资料、未来经合规批准的审计/对话历史超期段；具体期限与归档介质必须逐域立项。

### 7.6 audit_retention（只追加法律/审计保留）

- **契约**：只追加、禁删；法律保留（legal hold）需独立批准流程；删除触发=法律保留期裁决。
- **适用**：learning_events、turn_safety_decisions、security_audit_events、audio_consents、audio_retentions、gateway_operation_events（随 operation 生命周期内）。
- **长期保存理由（按要求逐项）**：
  - `learning_events`：掌握度回放与教育合规审计的事实源；删除触发=主体删除裁决（restrict + 显式顺序）；PII=未成年人学习事实（pii_minor）；责任=study；法律保留需独立批准，归档当前未实现。
  - `security_audit_events`：安全事件可追溯；删除触发=法律保留期裁决；PII=可识别主体（pii_identifiable）；责任=audit；归档/导出服务须独立立项。
  - `turn_safety_decisions`：安全决策审计投影；随会话闭包删除，法律保留需独立批准。
  - `audio_consents` / `audio_retentions`：合规同意与留存审计元数据（触发器禁删）；撤回/到期只触发音频对象 Outbox 删除意图，审计行本身继续保留；consent 有效期最多 12mo、音频对象最长 7d，均不等于行保留期；PII=未成年人关联数据；责任=voice。
- **责任 Domain**：各表 Owner；法律保留流程须由合规任务独立批准，不属于 D07。

### 7.7 derived_rebuild（派生重建/删除）

- **契约**：派生物可整表重建或随源删除，不影响任何引用/判分/历史候选（ADR-0015 决策 6）。
- **适用**：knowledge_chunk_embeddings、asset_representations、asset_video_keyframes、mastery_states（投影，可由事件重算）。
- **责任**：knowledge/asset/study 域。

### 7.8 queue_cleanup（任务账本终态清理）

- **契约**：只有已有 accepted ADR、法规决定或明确产品 SLO 的表，才能冻结数值 TTL；否则终态行按父事实生命周期保留，清理期限保持“未批准”，不得由 D01 推测默认值。
- **当前结论**：除 Graphile Worker 自有队列表外，本次没有证据支持为业务账本统一冻结 90 天。`tool_approval_intents` 的 prepared 有效期、session/handoff 的 expiresAt 是有效性边界，不自动等于物理行清理期限。
- **责任**：各业务账本 Owner 独立提出数据量、审计需求、清理窗口和回滚证明。O 线只负责外部物理对象删除 Outbox 的可靠性，不承担所有业务表 TTL。
- **退出条件**：逐域策略获批并有清理/恢复/审计测试；在此之前不实施统一清理。
