## 3. Repair / Backfill

- **是否发生**：是，仅限 A 的 1 个孤儿 asset。
- **方式**：Migration `0051_d02_core_referential_integrity.sql` 仅允许以下已审计身份进入 repair：

```sql
DELETE FROM "assets"
WHERE "id" = 'f488d009-7753-46e7-9367-c83d5036e265'::uuid
  AND "space_id" = 'eac85d6a-7e4c-44ce-a8d7-4abd9f06d081'::uuid
  AND NOT EXISTS (
    SELECT 1 FROM "spaces" s WHERE s."id" = "assets"."space_id"
  );
```

- **确定性**：ID + orphan space ID + 父行不存在三重匹配，只处理已核实的数据；其他环境中的未知孤儿不会被泛化 DELETE。
- **对象闭包**：删除前将匹配 asset 的 version、representation、keyframe 对象键写入 `object_deletion_outbox`，再通过既有 FK cascade 删除数据库派生行。
- **影响行数**：live 开发库 = 1 行 asset + 1 行 asset_version；已核实 representation/keyframe/processing_job 均为 0。
- **fail-closed 语义**：迁移开头统计额外 asset、lesson session、budget orphan；任一非零即以 SQLSTATE `23503` 在任何修改前中止。若 agent_message_parts 仍引用目标 asset，后续有界 DELETE 同样失败。
- **未发生**：B/C 无孤儿，无 repair/backfill。

## 6. C：lesson_sessions.student_id 口径证明

### 6.1 四类证据

| 证据类别            | 内容                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Schema 源码         | `lesson_sessions.student_id`（text NOT NULL，D02 前无 FK）；`learner_profiles.student_id`（text PK，已有 FK → platform_users.id cascade）；`platform_users.id`（text PK）                                                                                                                                                                                            |
| Migration           | 0011 迁移把每个历史 `lesson_session` 提升为 `spaces` 行（id = lesson_session.id），student_id 语义即主体；D02 前无 student_id FK                                                                                                                                                                                                                                     |
| Repository/生产路径 | 唯一生产写入入口 `learning-session-active-lifecycle.ts::insertActiveLearningSession` 在插入 session **之前**调用 `ensurePersonalIdentity`（upsert platform_users，anon→anonymous_compat、其余→registered）；教学网关入口 `apps/web/server/gateway/teaching-turn.ts` 同样先 `ensureAnonymousCompatibility/ensureRegistered`。**不存在绕过 platform_users 的写入路径** |
| live 统计           | 4 sessions / 1 distinct student：0 缺失于 platform_users、0 缺失于 learner_profiles；kind=registered                                                                                                                                                                                                                                                                 |

### 6.2 结论

- 口径与 `learner_profiles` 一致（student_id ≡ platform_users.id）；**零孤儿**；**不存在合法外部 ID** → 按任务 C 判定建立 FK，不 BLOCK。
- `grade_band / course_slug / knowledge_node_id` 仍为外部目录标识（D01 §6.3 裁定保持），本次不动。

### 6.3 ON DELETE 为什么是 restrict 而非 cascade

- `learning_events` 的教学事实 FK（`learning_events_session_student_fk`）为 **restrict**（D01 §4.10：audit_retention 策略，删除顺序必须显式）；若 lesson_sessions.student_id 用 cascade，删除 platform_users 会在级联路径上被 learning_events 拒绝，产生"级联承诺但实际失败"的误导。
- D01 §4.1 冻结 `platform_users` 删除 = `restrict（子表 FK 混合 cascade/restrict/set null，须显式删除闭包）`；`audio_consents` 对 platform_users 已是 restrict ×2。
- 匿名主体清理（`anonymous-data-lifecycle.ts`）不删除 platform_users 行，restrict 不影响现有匿名闭包（闭包显式按序删除 lesson_sessions）。
- `learner_profiles` 维持 cascade（D01 冻结：画像随主体删除），不受本 FK 影响。

## 7. Migration：0051_d02_core_referential_integrity.sql

### 7.1 有界修复与约束建立

- **preflight**：在数据修改前统计未知 asset orphan、lesson session orphan 与 budget orphan；任一非零即以 `23503` 中止。
- **bounded repair**：只允许 §2.1 已审计的 asset ID + space ID 组合；不存在全表泛化 DELETE。
- **Outbox**：repair 前登记匹配 version、representation、keyframe 的对象删除意图，`ON CONFLICT` 保持幂等。
- **FK**：assets→spaces restrict、lesson_sessions→platform_users restrict、budget→operations cascade；均先 `NOT VALID` 后 `VALIDATE CONSTRAINT`。
- **索引**：`assets_space_fk_idx` 支撑父表删除检查。
- **锁风险**：有界 DELETE 仅锁命中行；约束建立和普通索引仍需数据库锁，生产规模与维护窗口由 D07 复核。
- **fresh install**：空库 preflight/repair 无操作，约束与索引正常建立。
- **N-1 upgrade**：合法数据升级通过；已审计孤儿先写 Outbox 再删除；未知三类孤儿在修改数据前 fail-closed。
- **rollback**：可删除三条 FK 与索引；Outbox 意图保持可审计。已删除业务行不能自动恢复，因此 repair 必须维持身份有界。
- **不可变性**：已进入 main 的历史 Migration（0000–0050）零修改；0051 使用 `drizzle-kit generate --custom` 创建并由 Drizzle snapshot 冻结目标 schema。

## 10. 对 UV / KM / PET 的影响

- **UV（画布语音）**：语音资产复用 `assets.space_id` 强 FK——新语音上传路径的 spaceId 必须来自真实 space（现生产路径已满足）；`audio_retentions` 引用 asset_versions 不受影响；lesson_sessions restrict 不影响语音同意链。
- **KM（知识记忆）**：`assets.space_id` FK 不影响 knowledge_* 表（无引用）；记忆类新事实若挂接 Asset 需遵守 space FK。
- **PET（桌宠）**：不触碰 turn-ledger/tool-ledger/message-ledger；budget 账本 FK 为只读侧（无读取产品）无影响。
- **共同边界**：新增子表若引用 spaces/agent_operations/platform_users，默认应直接建 FK（参照本台账）；主体删除流程立项时必须先处理 lesson_sessions restrict 闭包（§6.3）。
