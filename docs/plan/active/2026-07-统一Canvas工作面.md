# 统一 Canvas 工作面

- 状态：`active`
- 负责人：项目负责人
- 最后验证时间：2026-07-25
- 对应路线图阶段：[统一 Canvas 工作面](../../10-planning/roadmap.md#当前核心阶段统一-canvas-工作面)
- 架构边界：[统一 Canvas 工作面](../../02-architecture/04-统一Canvas工作面.md)
- 重大决策：[ADR-0024](../../09-decisions/0024-统一Canvas工作面与运行时分层.md)

## 目标

在不复制 Notebook、Agent Loop 或数据事实的前提下，让同一 Notebook 的 Sources 与 Artifacts 进入统一 Canvas 阅读和共创，并为隔离交互应用、代码与机器学习 Runtime 建立可渐进实现的协议、安全和恢复边界。

## 范围

- 统一资源描述、Renderer Registry 和明确的 Runtime capability；
- Studio 输入/输出信息架构与同 Notebook 归属；
- PDF、图片、网页、文本、音频和视频来源预览；
- 结构化与媒体 Artifact 的版本、Provenance、失败和恢复；
- 持久 Tier 2 Web 沙箱及审计依赖包；
- `ExperimentRuntimePort`、受控代码环境和最小可复现实验纵切；
- Web 主体验、TUI/渠道降级与跨入口状态一致性；
- 权限、配额、审计、无障碍和真实运行证据。

## 非目标

- 不重写第二代 Agent Runtime、Gateway、Tool Kernel 或 Notebook 归属；
- 不一次实现任意语言、任意依赖、任意 GPU 或任意联网执行；
- 不把所有内容压成一个 Artifact Schema 或单一 Renderer；
- 不允许模型代码进入 Web 主页面；
- 不让 Canvas、沙箱或实验结果直接改变判分、掌握度和课程状态；
- 不把正式 IdP、全部渠道或完整生产 SLO 捆绑成首个 Canvas 纵切的完成条件。

## 前置事实与依赖

- 第二代 Hybrid Ports 架构已[结档](../completed/2026-07-第二代架构升级.md)；
- Notebook、Source、Artifact、Operation 和 Worker 的当前事实见[系统架构现状](../../02-architecture/01-系统架构现状.md)；
- Artifact 与持久任务遵守 [ADR-0019](../../09-decisions/0019-modular-monolith-artifacts-and-durable-jobs.md)；
- 能力授权与学习证据遵守 [ADR-0018](../../09-decisions/0018-capability-trust-and-learning-evidence.md)；
- 当前 HTML 沙箱仅为消息内轻量预览，不应被当成持久应用 Runtime。

## 验收条件

1. Source 与 Artifact 使用同一有界资源描述进入 Canvas，服务端校验 Notebook 归属，未知类型诚实失败；
2. Renderer Registry 可独立增加类型，不需要修改巨型中心组件或复制数据访问；
3. Studio 在同一 Notebook 下清晰区分输入和输出，切换 Notebook 后 Sources、Artifacts、运行状态不串读；
4. 至少完成 PDF/图片两类来源预览，具备引用定位、加载、空、失败和无权限状态；
5. 至少完成一种真实媒体生成 Provider 纵切，结果有不可变版本、Provenance、成本和失败恢复；
6. Tier 2 持久应用不能访问主页面 DOM、Cookie、Credential 或任意网络，依赖来自审计固定版本包；
7. `ExperimentRuntimePort` 完成一个无网络、有限时、可取消的 CPU 代码/数据实验，输出可追溯 Artifact；
8. Web、TUI 和渠道看到一致的资源与 Operation 终态；非 Web 入口提供摘要或安全交接；
9. 交互事件只有经可信领域服务验证后才能影响学习事实；
10. 全量 lint、typecheck、单测、集成、build、E2E、安全复核和真实 Runtime smoke 有可复现证据。

## 实施步骤

### P0：协议与兼容基线

- [ ] 盘点现有 Source、Artifact、Canvas、HTML sandbox 和 Worker 契约；
- [x] 在无 UI/Provider 依赖的 Core package 定义有界 `CanvasResource`、Renderer manifest、Runtime capability 和标准错误；
- [ ] 建立 Renderer Registry 与组合边界，保留现有 Artifact URL/API 和 Renderer 行为；
- [ ] 增加依赖守卫、未知类型、跨 Notebook 和版本不兼容测试；
- [ ] 记录当前 Web 真实页面的亮色、暗色、移动端、空、加载、失败与长内容人工验收矩阵；CI 不维护操作系统相关像素快照。

### P1：Studio 与来源工作面

- [x] Studio 改为同级输入/输出目录，不再把 Sources 放入历史记录；
- [x] Source 与 Artifact 从相同 Canvas 入口打开，但保持独立事实源；
- [~] PDF 与图片已进入安全预览；页面/引用定位和可访问替代文本待补；
- [ ] 补齐网页、文本、音频转写和视频时间轴的协议与 unavailable 状态；
- [ ] 验证切换 Notebook、跨用户拒绝和版本恢复。

### P2：结构化与媒体产物

- [x] General Agent 可通过受控 `artifact.create` Tool 原子创建思维导图、Slides、闪卡或笔记任务，并以真实事件接回 Canvas；
- [x] Agent 产物以 `operation_id` 恢复到对应助手消息末尾，可反复打开；Studio 保留 Notebook 级远期检索；
- [ ] 收敛思维导图、Slides、闪卡、笔记和音频的统一生成状态与错误；
- [ ] 修复生成长度、重试、取消和 Worker 终态，使失败不再被任务成功掩盖；
- [ ] 接入一种真实生图或语音 Provider，并保存模型、Prompt 摘要、输入引用、成本和输出校验和；
- [ ] 为所有媒体提供文本等价物、下载/删除边界和渠道降级。

### P3：持久隔离应用

- [ ] 将消息内 HTML 预览升级为独立、版本化的探索型 Artifact；
- [ ] 定义 Web Runtime Adapter、版本化消息桥、资源配额、取消和错误协议；
- [ ] 建立 React、GSAP、Motion、Three.js 审计依赖包与固定版本清单；
- [ ] 验证 CSP、无同源、禁网络、禁嵌套、禁表单、输出限额和 reduced-motion；
- [ ] 明确 Tier 2 事件不能进入可信学习事实。

### P4：代码与机器学习实验

- [ ] 定义 `ExperimentRuntimePort`、Run Record、输入挂载和输出 Artifact 契约；
- [ ] 实现无网络、CPU 限额、可取消、可超时的最小 Adapter；
- [ ] 在 Canvas 提供代码、日志、表格/图表与运行状态，不暴露宿主机权限；
- [ ] 保存代码、依赖、数据集、随机种子、资源和结果 Provenance；
- [ ] 完成一个可复现的小型数据或机器学习实验；GPU 和自定义镜像继续禁用。

### P5：跨入口与发布证据

- [ ] TUI 可列出、创建、打开或交接支持的 Canvas 资源；
- [ ] 渠道无法渲染时返回摘要、媒体或一次性交接链接；
- [ ] 执行取消、超时、失败、结果未知和恢复在所有入口一致；
- [ ] 完成滥用、安全、成本、低端设备、无障碍与真实 Provider/Runtime dogfood；
- [ ] 回写 canonical 文档，记录证据并归档本计划。

## 原子交付规则

- 一个 PR 只交付一个可回滚纵切：协议/Port、Adapter、组合/UI、证据按依赖拆分；
- 单文件只承担一个命名职责；接近 400 行开始复核，除机械或生成文件外不得超过 600 行；
- 新增 Renderer、Provider 或 Runtime 必须同时提交上限、错误、权限和失败测试；
- 不在功能 PR 中顺手重排全仓目录或批量重写无关 UI；
- 每个纵切先保持旧消费者可用，再迁移组合根，最后删除兼容层。

## 风险与回退

- **范围膨胀**：按 P0-P5 独立验收；后续阶段不能阻塞已稳定的前序纵切；
- **协议过早抽象**：只为已有或当前阶段的两个以上真实消费者抽象，不预造通用媒体 DSL；
- **沙箱逃逸或供应链风险**：依赖默认关闭并固定版本；安全证据不足时回退为只读结构化 Renderer；
- **Compute 成本与滥用**：首个 Adapter 无网络、CPU only、硬配额；超预算直接拒绝；
- **UI 与主线冲突**：共享协议和数据加载边界由主线维护，视觉工作只消费稳定 Props/状态；
- **迁移回归**：保留旧 Renderer 与 URL 兼容到真实 E2E 证明新路径等价后再移除。
