## 一、目标

这是一条可独立开发、独立测试、独立合并的轻量优化线。它只改善现有 Canvas 外壳的
响应式布局、焦点管理、状态展示和视觉回归，不修改资源协议、数据读取、Renderer
registry、Runtime、语音、数据库或 Gateway。

本 PR 可以与主线同时开发。两边都合并后由 Codex 做一次联合审计；主线不依赖本计划
才能编译，本计划也不依赖主线新增的任何接口。

## 五、顺序

朋友一人按 `F00 → F01 → F02 → F03 → F04 → F05` 串行完成；整条协作线可以从
第一天开始与主线并行。F00-F05 不依赖任何主线任务或未合并接口。

### F00：冻结外壳行为与文件所有权

- 依赖：无
- 文件边界：本计划

```text
只读检查 CanvasHost、现有测试和调用方，记录当前 public props、键盘行为、全屏状态、
滚动容器和已知视觉状态。确认 git status 中协作线文件没有他人未提交修改。
只更新本计划验证表，不改源码。
```

完成标准：

- public props、调用方、测试命令和当前缺口都有文件/行号证据；
- 与主线的文件交集为零；
- 若专属文件已有他人修改，任务标记 blocked，不继续 F01。

### F01：CanvasHost 焦点与键盘行为

- 依赖：F00
- 文件边界：`canvas-host.tsx`、`canvas-host-utils.ts`、`canvas-host.test.ts`

```text
在不改变 public props 的前提下，补齐 Canvas 展开/全屏/关闭的可访问语义。
关闭或退出全屏后焦点回到触发按钮；Escape 只执行当前可用的最小退出动作；
标题、关闭和全屏控件有稳定 accessible name。不得修改消费者或新增依赖。
```

完成标准：

- 键盘可到达关闭与全屏按钮；
- 进入/退出全屏、关闭后的焦点恢复有行为测试；
- Escape 不重复触发、不穿透执行两个动作；
- `pnpm --filter @educanvas/web test -- canvas-host` 与 typecheck 通过。

### F02：响应式布局、滚动与安全区域

- 依赖：F01
- 文件边界：`canvas-host.tsx`、`canvas-host-utils.ts`、`canvas-host.test.ts`

```text
只优化 CanvasHost 的外壳布局：窄屏不横向溢出，长标题不会挤掉操作按钮，
内容滚动只有一个明确所有者，全屏覆盖安全区域并尊重现有层级。
使用已有 design token 和 Tailwind class，不加全局 CSS，不改变 Renderer 内容。
```

完成标准：

- 320px、768px 和桌面宽度的结构断言或真实页面证据；
- 200 字标题、超长正文下按钮仍可操作且无双重滚动；
- 无硬编码品牌色、无新增 z-index 体系；
- Web test/typecheck 通过。

### F03：统一外壳状态提示组件

- 依赖：F02
- 文件边界：`canvas-shell-status.tsx`、`canvas-shell-status-contract.ts` 及其测试

```text
新增纯展示组件，统一 loading、empty、failed、unavailable、denied 五种 Canvas 外壳状态。
组件只接收安全文案、可选重试回调和状态种类，不读取资源、不发请求、不判断权限。
失败信息不能展示堆栈、对象键或 Provider 原始错误。此任务不接入任何消费者。
```

完成标准：

- 五种状态分别有 role/status 或 alert、标题和可读说明；
- 只有传入重试回调时才显示重试按钮，键盘可触发一次；
- 超长中文和英文文案不破坏结构；
- 组件测试和 Web typecheck 通过。

### F04：Canvas shell 真实页面视觉与无障碍回归

- 依赖：F03
- 文件边界：`tests/e2e/canvas-shell-visual.spec.ts`、`docs/06-quality/04-视觉回归.md`

```text
新增独立 Canvas shell E2E，只使用仓库现有可控 fixture。覆盖亮色/暗色、桌面/移动端、
正常/长标题/长内容/失败状态、键盘焦点和 reduced-motion。
不得依赖主线新接口，不修改产品代码，不把 OS 字体像素差异设为脆弱的全局门禁。
```

完成标准：

- spec 可单独运行，不依赖执行顺序；
- 截图、trace 和 fixture 不含真实学生信息或 Secret；
- 文档记录浏览器、viewport、日期、命令和 passed/failed；
- 焦点顺序与无横向溢出有 DOM 断言，不只依赖截图肉眼判断。

### F05：协作线收口与交付

- 依赖：F04
- 文件边界：本计划、视觉回归文档；不得再改产品源码

```text
运行协作线全部测试、Web typecheck、lint 和 git diff --check。
逐项填写验证表，确认 diff 只包含专属文件；提交一个独立 PR。
不要等待或合并主线代码，不要自行修改主线解决冲突。
```

完成标准：

- `git diff --name-only` 全部位于专属清单；
- Web 相关 test/typecheck/lint 和目标 E2E 通过；
- PR 描述列出 F00-F05 证据、风险和回退；
- Codex 审核结论为 PASS 后方可合并。

## 六、Codex 审核标准

每个任务只能得到 `PASS`、`REVISE` 或 `BLOCK`：

- 是否严格限制在七个专属文件和本计划；
- 是否保持 `CanvasHost` public props 与现有调用方兼容；
- 是否没有复制 registry、数据读取或权限判断；
- 是否用行为断言验证焦点/键盘/溢出，而不是只更新 snapshot；
- 是否覆盖亮暗色、移动端、长内容与 reduced-motion；
- 是否没有新增全局样式、依赖、密钥或真实学生数据；
- 是否实际运行任务规定命令。

## 七、最终联合审计

朋友 PR 合并后不立刻宣布整个阶段完成。待主线 PR 也合并，由 Codex：

1. 比较两个 PR 的文件清单，要求开发期交集为零；
2. 运行 CanvasHost、registry、资源打开和目标 E2E 的组合回归；
3. 确认主线没有复制 `canvas-shell-status`，朋友线没有复制主线协议；
4. 检查 UI 是否仍按服务端 `CanvasResource` 和 `allowedActions` 诚实展示；
5. 只有联合审计通过，才在主线 U21 中完成最终归档。
