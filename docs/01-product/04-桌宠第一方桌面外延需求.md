- 状态：`accepted`
- 负责人：@Timcai06
- 日期：2026-08-13
- 关键决策：[ADR-0028](../09-decisions/0028-桌宠作为统一EduCanvas系统的第一方桌面外延.md)
- 实施计划：[DP 桌宠统一桌面外延](../plan/active/DP-桌宠统一桌面外延.md)

> 本文定义已接受的目标产品需求，不把计划中的能力描述成已经可用。Conversation 切换、
> canonical 完整历史和富结果投影仍是待实施目标，当前能力以第四节基线表为准。

## 1. 产品定义

EduCanvas 桌宠是统一 EduCanvas 系统的第一方桌面入口。它让用户无需一直打开浏览器，
即可通过桌面角色进行文本或语音交流、查看对话历史和轻量结果，并在需要复杂内容时打开
Web 中同一个 Notebook、Conversation、Message 和 Artifact。

桌宠不是独立 Agent，也不是 Web 的缩小复制品：

- Agent、Notebook、Conversation、Message、Turn、Operation、Memory、RAG、Tools、Asset、
  Citation、Artifact 和 CanvasResource 均以服务端为权威；
- 桌宠负责桌面窗口、角色表现、录音、播放、轻量消息和结果卡；
- Web 继续承担 Sources、Studio、Canvas、Slides、思维导图和 Artifact 编辑等高密度工作面。

## 2. 目标用户与场景

### 2.1 首要用户

- 已拥有 EduCanvas 账号、需要随时提问或继续学习任务的学生；
- 以 Windows 桌面环境作为首轮开发和验收对象，随后补齐 macOS 同等主流程。

### 2.2 核心场景

1. 用户在桌面快速提问，不必先找到浏览器标签页；
2. 用户通过显式麦克风按钮说话，听到同一条 Assistant Message 的 TTS；
3. 用户在 Web 与桌宠之间继续同一 Conversation；
4. 用户查看完整历史，并从 Citation 或 Artifact 卡片进入 Web 精确内容；
5. 网络中断、窗口关闭或应用重启后恢复同一 Operation 或 canonical 历史，不重复回答和工具副作用。

## 3. 产品原则

1. **同一事实**：不同客户端只能投影同一份服务端事实，不能各自生成回答或消息账本。
2. **轻量而完整**：核心对话链路完整，富内容 Renderer 可以简化，但资源身份不能丢失。
3. **用户控制**：录音必须显式触发；复杂结果由用户点击后打开 Web，不自动弹出浏览器。
4. **可恢复**：重启、断线、取消和安全重试不得产生第二个逻辑 Turn。
5. **最小权限**：桌面端不持有 Provider Key，不默认申请屏幕、摄像头、Shell 或文件系统权限。
6. **诚实状态**：未支持的 Part、Provider 失败和 handoff 失败必须明确提示，不伪装成功。

## 5. 功能需求

### FR-01 桌面窗口与角色

- 桌宠独立于浏览器显示，默认不阻塞角色和对话框以外的桌面交互；
- 用户可以从角色可见区域拖动，按下后角色与鼠标保持稳定相对位置；
- 对话框展开、折叠时不改变角色可拖动能力；
- 桌宠允许在所有已连接显示器组成的桌面空间内移动；显示器移除、缩放或分辨率改变后，
  至少保留可抓取角色区域；
- 关闭窗口默认隐藏到托盘，托盘提供显示和退出；
- 再次显示不得出现可感知的白底、灰框、旧位置或尺寸闪烁；
- 对话框可折叠，独立聊天窗口可缩放、滚动并保持与小窗一致的 Conversation；
- 透明区域受控穿透，不能形成大面积隐形输入遮挡。

### FR-02 角色语义状态

- 持续态：idle、listening、thinking/streaming、speaking；
- 短暂态：greeting、success、auth-failed、backend-failed、confused，默认约三秒后回 idle；
- success 只用于登录成功或明确可验证的用户答题成功，不用于普通对话完成；
- listening 只在实际录音期间持续，speaking 只在实际 TTS 播放期间持续；
- Agent 文本不得夹带括号形式的桌宠动作、表情或舞台说明；视觉行为由客户端状态机控制；
- 角色包支持 APNG、PNG 序列或 sprite sheet，以版本化 manifest 映射语义状态；
- 替换资产不改变 Turn、Voice 或 Operation 业务逻辑。

### FR-03 登录与身份

- 未登录用户发起对话时，通过系统浏览器完成登录授权；
- 登录成功后桌面凭据可撤销、可过期，并只保存在操作系统保护存储；
- renderer、preload、URL、日志和错误响应不得暴露 Token；
- `401` 或撤销后立即清理本地凭据并提供重新登录入口；
- 登录 Session 绑定用户身份，不永久绑定单一 Notebook/Conversation；
- 授权时返回的 Notebook/Conversation 仅作为首次打开游标。

### FR-04 Notebook 与 Conversation

- 桌宠可以列出当前用户有权访问的 Notebook/Conversation；
- 用户可以切换 Conversation，并能明确看到当前会话名称；
- 用户可以新建 Conversation；新会话必须由服务端创建并校验归属；
- 桌宠可以继续 Web 已有 Conversation，桌宠创建的 Conversation 也能在 Web 打开；
- 切换时同步更新历史、当前 Operation、输入草稿和 handoff 目标，不能串会话；
- 无 Membership、跨用户、已删除或已撤销的会话返回稳定拒绝状态。

### FR-05 Canonical 历史

- 桌宠按页加载当前 Conversation 的完整服务端历史；
- 消息至少保留 canonical messageId、role、时间、status、parts、citations 和资源引用；
- 首屏优先加载最近消息，向上滚动加载更早页面，保持稳定滚动锚点；
- 小窗和独立聊天窗口共享同一份 View Cache 和 revision；
- 应用启动、重新登录、切换会话和显式刷新时可从服务端重建；
- optimistic 消息必须由稳定 `clientMessageId` 与服务端消息对应，不能形成重复消息；
- listening、thinking、speaking 和错误提示放在独立状态区，不进入对话历史。

### FR-06 文本 Turn 与流式输出

- Enter 发送，Shift+Enter 换行；空白输入禁止发送；单条文本上限 4,000 字符；
- renderer 在用户形成新意图时创建稳定 `clientMessageId`，主进程不得擅自替换；
- 服务端接受后显示 Stop，并实时投影真实 `message.delta`；
- 禁止用定时器制造假流式输出；
- completed 后以服务端 canonical Message 校正本地投影；
- failed、cancelled、timeout、interrupted 和 unauthenticated 使用稳定错误语义；
- 只有用户明确重新发送才创建新 `clientMessageId`；断线续传复用原 ID 和 Operation。

### FR-07 语音输入与输出

- 录音只能由麦克风按钮或明确用户动作开始；再次点击或 Stop 可以取消；
- UI 按 listening → transcribing → thinking/streaming → speaking → idle 投影；
- ASR transcript 经用户身份和资源权限校验后进入同一 canonical Turn 和 User Message；
- ASR 空文本进入 confused 短暂状态并可重试；
- TTS 播放同一 Assistant Message 的文字，不创建新 Turn；
- 用户可以停止播放或重新播放最近 Assistant Message；重新播放不重新生成回答；
- TTS 失败时保留文字、Citation 和结果卡；
- 麦克风拒绝、网络失败、ASR/Agent/TTS失败都有稳定提示与恢复入口。

### FR-08 Operation 与跨窗口协调

- 小窗和独立聊天窗口同一时间只允许一个可控前台 Operation；
- operation owner、operationId、clientMessageId、sequence 和终态由 main 统一协调；
- 非 owner 窗口可以观察进度，但不能错误取消或覆盖 owner 状态；
- 关闭窗口、隐藏托盘或 renderer 销毁时，按产品动作决定继续、取消或可恢复挂起；
- 断线后从最后 sequence 继续消费同一 Operation；
- 迟到事件不能覆盖已经确认的服务端唯一终态；
- 已完成写工具的安全重试不能重复副作用。

### FR-09 结构化结果投影

- 文本和短 Markdown 直接显示；
- Citation 显示编号、来源标题和“查看来源”入口；
- 图片显示有界缩略图、标题和打开入口；
- Artifact 显示类型、标题、状态、版本和“在 EduCanvas 中打开”；
- 工具进度显示稳定摘要，不暴露内部 Prompt、Provider、原始参数或堆栈；
- 未识别 Part 显示“此内容需要在 Web 查看”，同时保留可 handoff 的资源身份；
- 不支持的 Part 不能被静默删除，也不能压成无法追溯的纯文本成功。

### FR-10 Web handoff

- 复杂结果卡提供由用户点击的“在 EduCanvas 中打开”按钮，不自动打开浏览器；
- 目标可以精确到 Notebook、Conversation、Message、Artifact Version 或 CanvasResource；
- 桌面先向服务端申请短期一次性凭证，再通过系统浏览器打开受控 HTTPS 地址；
- Web 重新验证当前用户与资源权限；
- 打开失败保留“再次打开”，不得重新执行原 Turn 或 Tool；
- 重复打开同一结果只能打开同一资源，不产生第二份 Artifact。

### FR-11 图片和 PDF 输入

- 本能力位于核心统一链路完成后的后续阶段；
- 文件选择只由明确用户动作触发，首批至少支持图片与 PDF；
- 文件进入统一 Asset 上传、版本、安全校验、派生表示和权限流程；
- Turn 只携带服务端受权的 `assetId + versionId` MessagePart；
- Electron 不把本地文件直接发送给模型 Provider；
- 上传、解析或能力不可用时诚实失败，不把文件名文本当作已理解内容。

### FR-12 设置、无障碍与降级

- 支持静音、音量、动画强度和 reduced motion；
- 键盘可访问输入、发送、停止、语音、朗读、折叠、放大和 handoff；
- 运行状态使用独立 live region，不把状态文案混入对话历史；
- 200% 缩放和常见 Windows 缩放下保持可拖动、无内容截断；
- 无网络时保留历史浏览、停止本地播放和恢复入口，不伪造离线回答。

## 6. 信息架构

### 6.1 桌宠小窗

- 当前 Conversation 标识；
- 最近消息与运行状态；
- 文本 Composer、麦克风、朗读和 Stop；
- 折叠、放大和隐藏入口；
- Citation/Artifact 简化卡片。

### 6.2 独立聊天窗口

- 当前 Notebook/Conversation 选择与新建入口；
- 分页完整历史；
- 与小窗共享的 Composer、运行状态和结果卡；
- 用户可调整窗口大小；
- 不复制 Sources、Studio、Canvas 或 Artifact 编辑器。

### 6.3 Web

- 完整 Sources、Citation 定位、Artifact/Version、Canvas、Slides、思维导图和编辑流程；
- 从 handoff 恢复同一上下文与资源，不重新执行 Prompt。

## 7. 核心用户流程

### 7.1 继续 Web 会话

```text
登录桌宠
→ 服务端返回 Notebook/Conversation 目录和初始游标
→ 加载当前 Conversation 最近一页 canonical Message
→ 用户发送文本或语音
→ 同一 Turn/Operation 产生消息和结果
→ Web 打开同一 Conversation 时读取相同消息
```

### 7.2 复杂结果

```text
用户在桌宠要求生成思维导图
→ 同一 Agent Runtime 调用现有 Artifact/Canvas Tool
→ 服务端持久化唯一 Artifact Version
→ 桌宠显示摘要和结果卡
→ 用户点击“在 EduCanvas 中打开”
→ 一次性 handoff 打开 Web 精确资源
→ 不重新执行 Tool
```

### 7.3 断线恢复

```text
Turn accepted 并记录 operationId/clientMessageId/sequence
→ 网络中断
→ UI 显示 interrupted，不伪造失败终态
→ 恢复网络后按 cursor 继续同一 Operation
→ canonical completed/failed/cancelled 结束
```

## 8. 非功能需求

### 8.1 安全与隐私

- Electron 保持 main/preload/renderer 信任分层、contextIsolation 和最小 IPC；
- 特权 IPC 只接受受信应用窗口主 frame，并对 payload、大小和 operation owner 做校验；
- 应用入口固定为本地受信资源；生产禁止任意远端 renderer URL 和顶层导航；
- Token、Provider Secret、原始音频响应、Prompt 和内部错误不写日志或跨不可信边界；
- 未另行获得音频留存同意时，桌面录音不写长期存储。

### 8.2 性能

- 桌宠隐藏到托盘时停止不必要的鼠标轮询和动画计时器；
- 历史必须分页，不能一次加载无限消息；
- 图片、JSON、音频和上传均使用明确字节上限和流式有界读取；
- 增量输出只更新当前消息，避免每个 delta 重建全部历史 DOM；
- 具体启动、首屏历史和流式渲染预算在 `DP11` Windows 实机基线后冻结。

### 8.3 可靠性

- Operation 单终态、消息幂等和资源权限由服务端重验；
- 窗口关闭、托盘隐藏、显示器变化和系统休眠后均有确定恢复行为；
- Provider 或 Web handoff 不可用不影响已完成文字结果的读取；
- 本地 View Cache 损坏可安全删除并从服务端重建。

### 8.4 平台

- Windows 11 x64 是首轮开发、打包和人工验收平台；
- macOS 在 Windows 主流程通过后补齐 deep link、麦克风权限、透明窗口、托盘、打包与签名证据；
- 平台差异只存在 main/platform adapter，不进入 Agent、Turn、Voice 或 Message 契约。

## 9. 成功指标与验收

### 9.1 核心一致性

1. 同一用户在 Web/桌宠读取相同 Notebook、Conversation 和 canonical Message ID；
2. 跨端发送、刷新和重启不存在重复 User/Assistant Message；
3. 删除本地 View Cache 后历史可完整分页恢复；
4. Citation 和 Artifact 的资源身份在桌宠简化投影后仍可追溯；
5. 复杂结果 handoff 重复打开不产生第二个 Operation 或 Artifact Version。

### 9.2 操作可靠性

1. 文本真实增量、Stop、取消、超时、断线恢复和最终终态均有自动化契约测试；
2. ASR transcript 只产生一个 User Message，TTS 重试产生零个新 Turn；
3. 小窗/大窗并发操作不会导致双 Turn、错误取消或状态互相覆盖；
4. 显示器变化后角色可抓取，折叠对话框后仍可拖动；
5. 未授权 Conversation、Message、Asset 和 Artifact 请求全部拒绝。

### 9.3 发布证据

- Windows：打包应用完成登录、会话切换、文本、中文语音、流式回答、历史恢复、取消、
  Citation/Artifact 卡和 handoff 人工验收；
- macOS：在 Windows 主流程通过后完成相同业务验收，并补 deep link、麦克风和窗口差异证据；
- CI：fake Provider、固定 Conversation/Artifact fixture、跨客户端一致性、权限和幂等测试；
- 真人麦克风、真实 Provider、网络中断和多屏证据单独记录，不以单元测试代替。

## 10. 范围分层

### 第一阶段：统一对话核心

- 身份与 Conversation 解耦；
- 目录、切换和新建；
- canonical 历史分页；
- 稳定 clientMessageId、真实流式输出、取消和 Operation 恢复。

### 第二阶段：统一结果闭环

- capability manifest；
- Citation、工具进度、图片和 Artifact 简化投影；
- 用户点击式精确 Web handoff；
- 语音与 canonical Message 对齐。

### 第三阶段：扩展与发布

- 图片/PDF Asset 输入；
- Windows 打包与实机验收；
- macOS 同流程适配与验收；
- 文档、能力状态与发布证据收口。

## 11. 非目标

- 桌宠内完整 Sources、Studio、Canvas、Slides 或 Artifact 编辑；
- 第二 Agent Runtime、本地离线 Agent、本地业务数据库或桌宠专属 Prompt；
- 持续监听、唤醒词、声纹、全双工语音或后台录音；
- 默认屏幕理解、任意文件读取、Shell 或设备控制；
- 为桌宠复制一套 Provider 路由、Memory、RAG 或 Tool Registry；
- 在本项目中完成儿童账户与商业生产合规全部建设。

## 12. 开放项

- macOS 的签名、公证和分发身份需在 `DP12` 前准备；
- 启动时间、历史首屏和增量渲染的数值预算需先取得 Windows 实机基线；
- 图片/PDF输入是否进入第一个可发布版本，由统一对话核心和 handoff 验收结果决定。
