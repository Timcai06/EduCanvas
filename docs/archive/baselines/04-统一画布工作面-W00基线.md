### 3.4 Studio 与主槽位的关系

- Studio 是**覆盖层**（`{studioOpen ? <StudioOverlay/> : null}`，498-521），与中央槽位**叠加渲染**而非互斥；
- 但 Studio 打开来源/产物时会先 `setStudioOpen(false)` 再进主槽位；
- 这是两套互斥语义：主槽位级联三元 + Studio 覆盖层布尔，**无统一状态权威**。

## 七、状态转换表（当前隐式状态机）

| 当前状态                    | 触发                                | 目标状态             | 是否手工清理              | 可达性  |
| --------------------------- | ----------------------------------- | -------------------- | ------------------------- | ------- |
| 任意                        | 打开 Source（Studio）               | sourceResource = {…} | 需手工清 artifact/preview | ✅      |
| 任意                        | 打开 Artifact（消息/Studio/状态卡） | openDetail = {…}     | 部分入口清 source/preview | ✅      |
| 任意                        | HTML Preview                        | previewHtml = src    | 需手工清 source           | ✅      |
| 任意                        | Studio 覆盖                         | studioOpen = true    | 叠加渲染                  | ✅      |
| sourceResource              | 关闭                                | null                 | 直接 set null             | ✅      |
| openDetail                  | 关闭                                | null                 | closeCanvas               | ✅      |
| sourceResource + openDetail | 打开另一资源                        | 由级联三元决定胜者   | 不一致时后者覆盖          | ⚠️ 冲突 |

### 标注

- **不可达状态**：无显式建模，级联三元保证同时只有一个"胜者"，但 `sourceResource` 与 `previewHtml` 同时非 null 的状态**可达且无权威裁决**（靠手工清理避免）；
- **冲突状态**：落地态 `isLanding && artifactFlow.openDetail` 与 `isLanding && sourceResource` 理论上可同时为真，靠 529/550 两个独立 `{...}` 三元各渲染一个——但 source 打开会清 artifact（503-508），实际互斥靠调用方自觉；
- **需手工清理状态**：第 5.3 节 5 处 `setSourceResource(null)` 组合是典型手工清理点，W01 应收敛为判别联合 transition。
